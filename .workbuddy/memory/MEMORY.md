把「一个人带 AI 干长周期精工活」做成别人能照做的**工具 + 规程 + 模板**。**推 GitHub 是副产品，别为对外好看改内部设计。**

`字幕精校通用库`（本库，真身，已公开）／`是大臣系列`（实例，只读 + 写它 `03_工作区/`）／`日常杂活`（实例 + 历史账本，只读）。**别人的库文档一个字不改。**

## 两库怎么通消息（11-08 建）

- **用户说「对账」= 读 `docs/协作协议.md` 第零节**：读 `<剧库>/06_治理/` 的 `卡点.tsv` + `待报通用库.md` → 判新条目 → 更新第 5 节状态与顶部「已读到」戳 → 第 8 节记流水。判据是**时间戳**，不是记忆。
- 剧库报事实与建议，本库判并把结论写在第 5 节；**谁都不转述内容**，只通知「对账」。
- 协议**固定文件名**，干活方不存副本；改名或搬家等于把两边指针全断掉。
- **协议长度跟病根数走，不跟 GQ 条数走**（11-08 定，上限 200→135）：那天 18 条 GQ 只有 2 个病根，按条写 100 行、按病根 25 行。判词正文进 `docs/archive/答复_*`，前台只留登记表。**干活方开始绕开协议（"107 行/场，开工只比版本戳"）就是协议太长，是协议的错，不是它偷懒。**

## 不看不就会干错

- **四样**：工序定义 / 四件工具 / 骨架 / 4 份字幕技能，缺一样不算沉淀完。**`tools/` 现 30 件、能独立跑 25**（`blind_sample`/`isolate_review`/`prefilter_semantic`/`validate_semantic`/`gen_progress` 要剧库目录），对外报 25。`NEEDS_PROJECT` 名单只在有 `scaffold.py` 时核（骨架库只 4 件，照核必假报）。
- **跨库编号：一个问题一个号**（11-09 定）：`GQ-n` 只给剧库报本库的问题（新条目从 `GQ-19` 起）；**同一个问题两边沿用同一个号**——本库台账记它也用 `GQ-n`，不另起本库号（`#42` 就是反例，挂了三个号）；裸 `#n` 只给本库自己发现的；`#1`~`#12` 封存不改。
- **台账按「卡在谁身上」分节**（11-09 定）：等我动手 / 等协作方 / 等外部 / 等你拍板。**别按内容分**（换库就失效）、别按进度分（同一条来回跳）。
- **协议 135 行满格**：下次加东西先搬走一批——§8 只留最近 2 轮、§4 做完当天归档。这跟「§5 按病根不按条」是同一条闸。
- **名字按 `docs/命名准则.md`**；**集号真假看有没有剧名陪着**（`S01E01` 单独出现是假号）；**历史已定型**，只往前修，不做整库重写。
- **指路必须同时设闸**——只写「注意」不加检查，整条路径能被绕开。
- **能数出来的数不写死**：工具件数由 `doc_lint` 的 `check_counts` 核（真身＝`tools/*.py` 实际数，写错报 ERROR）；`selftest` 项数不写进文档，只写「看运行输出」。写死一个数就要几处同步，11-08 漂成过四个值。
- **假报一次，闸就没人看了**：宁可漏报边界，也别给假 WARN（「台账未提交」判「连续两次都脏才报」就是这么来的）。**同一个病根会复发**：修法要照**语境**判（`DOCS.name != 'docs'`），别只修单个检查。
- **改完文档跑一次 `eol_guard --fix`**：Edit 把整份 `判定记录`（172 行）写成过 CRLF，`write_text` 也会；新建文件按字节写。
- **4 份字幕技能在全局是软链，不是副本**：`C:/Users/Annoy/.workbuddy/skills/subtitle-*` 的 `Path.resolve()` 落回本库 `skills/subtitle-*`（11-08 实测）。所以**改全局＝改库工作区、直接进 `git status`**；也没有"改这份不影响那份"这回事。
- **验技能触发必须在场景里**（11-08 实测）：空目录里发「这条该不该改」，模型只会反问「哪一条」——技能 description 的前提（字幕精校）不存在，测的是通用问答，必然不触发。要测就把会话开在**剧库**、句子里带「这一集 / 这条字幕」；判据看**第一步有没有读 `SKILL.md`**，绕过技能直读 `docs/` 干对了也算没过。
- **改闸的退出码，先把它的调用方全跑一遍**（11-08 撞过）：`eol_guard` 把「检查 0 个」改成退 2，而 `pre-commit` 是逐文件跑的，于是**每个新增文件都被判红、提交直接拦死**。返回值是给调用方看的，改它等于改所有调用方的行为——钩子、自检、别人的脚本都算调用方。
- **改口径要全文 grep 同一个词，别只改显眼处**（11-08 `agent-craft` 把「申报四要素」改成三要素，`:28`/`:143` 都改了，漏掉 `:128` 的「申报里的分钟数」，同一份文件前后打架——**半改比不改更糟**）。改完不留 `.bak`：本库不靠本地备份，旧版用 `git show HEAD:<path>` 取。
- **`MF8` 已落地**（`--f8`，默认关）；**判据要事前可判**——报告写的「100%」多是事后视角。
- **全局技能装了两个**（11-09）：`writing-for-agents`、`diagnosing-bugs`，上游原版只改 description 指向本库、正文不动；`domain-modeling` 装了又删。全局一改四库同时生效。原库在 `电脑管家/.workbuddy/_research/mattpocock-skills/`。
