# 命名准则

> **最后更新：2026-11-08** · **一句话：一个维度一套词，不跨维借用。**
> 上限 60 行（`doc_lint` 会拦）。它是规则型——只放骨架，实例在各文档。
> 改任何名字之前先查这张表；表里没有的维度，先加维度再加词。

## 一、五个维度

| 维度 | 问什么 | 专用词 | 不许用 |
|---|---|---|---|
| 做什么 | 哪道工序 | **X 稿** | 层、档 |
| 改哪儿 | 对象粒度 | **层** | 档、级 |
| 做多深 | 强度 / 范围 | **档** | 层、类 |
| 判成什么 | 结论分类 | **类** | 档、级 |
| 凭什么判 | 规则 / 条目 | **前缀编号** | 中文别名 |

## 二、四级命名

| 级 | 管什么 | 规则 | 现状 |
|---|---|---|---|
| **一 · 工序** | 做什么 | 动词 + 稿，全库四个（验收是 11-07 补的，不带「稿」） | 清稿 / 对稿 / 审稿 / 验收 |
| **二 · 组** | 工序内部怎么分 | 对象=层、强度=档、结论=类 | 文件层·文本层；全量·关键点；T1–T3·T? |
| **三 · 编号** | 规则与条目 | 工序缩写打头，前缀唯一 | 见第三节 |
| **四 · 字段** | 机器读的列名 | 英文小写下划线，基础七个 + 对稿一个 | `no old new rule evidence source stage`（7），对稿另加 `verdict`（合计 8） |

**字段分两层，别混为一谈**：**逻辑名**（上表八个，清单、文档、跨工序对账用）与**表头列名**（工具实际输出，可以中文，如 `中文条号`／`中文文本`）。两者对不上就是两张皮——加列或改列时，文档与工具必须一起改。

## 三、前缀登记（新前缀先在这里登记，不许直接用）

| 前缀 | 归属 | 范围 |
|---|---|---|
| `MF` | 清稿 · 文件层规则 | MF1–MF8 |
| `MT` | 清稿 · 文本层规则 | MT1–MT6 |
| `DR` | 对稿 · 机器规则 | DR0 参照侧空 / DR1 数字不一致 / DR2 整条未译 / DR3 比例过低 / DR4 拉丁残留 / DR5 术语不符 |
| `T` | 对稿 · 结论类 | T1 漏译 / T2 误译 / T3 表述差异 / T? 无法判定 |
| `C` `N` `F` | 审稿 · 条目 | `docs/工序-审稿-判据表.tsv` 是真身，引用写全「审稿 C1.4」 |
| `R` | **旧库查表标签，不是本库编号** | R07a / R07b / R04 / R10，由工具输出。折算：`R07a`→清稿 **MT1**、`R04`→对稿 **DR1**、`R10`→对稿 **DR2**、`R07b`→审稿 **C2.2 / C2.5**（详细对照在旧库手册里，那份不进新库，所以折算写在这里） |

**引用规矩**：编号单独出现时必须带归属（「对稿 T1」「清稿 MT3」「审稿 F7」）。只写 `T1` 或 `F7` 等于没说是谁的。

## 四、一条判据：有判据文档的是工序

**工序 = 有 `docs/工序-<名>.md`，结论二值（改/不改、过/不过）**：清稿 · 对稿 · 审稿 · 验收。其余都是**步骤**：**备料 5 件**（造底本 · 体检 · 对齐 · 攒词表 · 定样式基准）输出的是数据不是判断——体检报数值、对齐报配对率、攒词表机器只挑候选而判的是译名；**调度执行 2 件**（定档定读多深、落地纯写回）都不判内容对错。

**旧判据「带『稿』的是工序」已废（2026-11-07）**：它只认得出前三道，而验收不带「稿」却确实是工序——按名字分，碰到反例就得回来改；按「有没有判据文档」分，加新东西时看一眼就知道该不该配判据。

## 五、改过的冲突（三行一条，别再犯）

- 2026-11-06 `T1–T6` → `MT1–MT6`：与对稿结论 T1 撞号，一张清单里写 T1 两义。
- 2026-11-06 `F1–F8` → `MF1–MF8`：与审稿形态 F7（话轮标记）撞号。
- 2026-11-06 `layer=form/align/sentence` → `stage=mech/triage/read`：`layer` 与「层」撞义，值改为与工序一一对应。
- 2026-11-06 `source_model` → `rule` + `source`：一个字段装了规则名和模型名两种东西。
- 2026-11-06 步骤 `落地与复算` → `落地`：四字带连词是九个步骤名里唯一的多动作组合，且复算是写回的内建动作。**名字要短，描述可以长**——需要时说「落地（写回 + 复算）」。
- 2026-11-07 「第一部剧 / 第二部剧」→ **写剧名或库名**：项目史（法医先、大臣后）与本库验证顺序（大臣先、法医后验）共用一批序数词，两处口径互相打架。跨库写库名（`日常杂活` / `是大臣系列`），表先后用日期，不用序数。**同一 IP 下的剧集分类用「正传 / 续一 / 续二」**，不用「重启 / 续集 / 正剧 / NB」——判据要求共用基准词表再按剧过滤，**剧型名错了判据会跟着错**。

## 六、不适用范围

- **工具名**（`triage_diff.py` 等）：文件名给机器读，与工序名是两套，不对齐。
- **中英分工**：带编号的目录给人翻（`01_源字幕`），不编号的给命令敲（`docs/` `tools/`）；工序、步骤、判据用中文，文件名、字段、参数用英文。**判法：这名字会不会出现在命令行里。** 这是刻意的，不是乱。
- **措辞类**（假红/假阳性、跳过/锚点失配）：一句话在文档里统一即可，不进本表——进表就把准则撑成词典。
