# 做法（本库怎么干活）

> 这一页管「怎么干」，不管「干什么」。工序怎么判看 `docs/工序-*.md`，定了什么看 `docs/判定记录.md`。
> **每条只写原则 + 落地形态**，理由一律不抄——去判定记录找那一条，两份理由迟早对不上。
> 上限 60 行（`doc_lint` 会拦）。加新原则先删旧的。

## 一、八条常驻原则

| # | 原则 | 踩过的坑 | 落地形态 |
|---|---|---|---|
| 1 | **一份内容只有一个真身**，别处只留指针 | 接棒必读原第 47 行写「理由在判定记录与台账」，两处 grep 零命中——指针指了个空地址 | **摘要只作定位，判断前读真身**——说某个技能做什么、或建议跳过某步之前先读那份 `SKILL.md`，指针表的摘要不是判据；靠自觉（`doc_lint` 只查文件在不在，查不了章节） |
| 2 | **上限写进脚本才算上限** | 落点表写着接棒必读 100 行，`doc_lint` 里根本没这项检查，它长到 71 行没人喊 | `doc_lint` 的 `LIMITS` + 提交钩子 |
| 3 | **同类错第 3 次必须变脚本** | 换行符、文档超限、残留行，都是先说「注意」，第二次还犯 | `selftest` 用例 / `doc_lint` 检查 / `.githooks` 三选一 |
| 4 | **能降级的工具有人用**，判不了就明说判不了 | 对稿器缺参照时若把 T1 记成 0 条，读的人会当成「一条没漏」 | 工具里显式打印「判不了什么」 |
| 5 | **机器只挑候选，人定案** | 对稿第一版用「省略号=截断」，538 条挑出 83 条，全是正常分句 | 判据写进 `docs/工序-*.md`，改判据要过 9 集 |
| 6 | **制度靠自觉＝没有制度** | `eol_guard` 在本库恒绿（`gitattributes` 已归一），真防线是别的东西 | 每条规矩问一句：坏了会不会报错？不会就不是防线 |
| 7 | **派活单必须点名加载哪个技能**，不靠 AI 自己想起来 | 四句话实测，当时那批技能里只有 1 个走注册表加载，其余自己去翻文件——翻到的只是被读那份，公共纪律一条没进来 | 派活单第 0 步写「加载 `subtitle-xxx`」+ 开工声明行；`description` 改动只是提高概率，不是保证 |
| 8 | **能前置的全前置；不可重跑的那道单独放最后**（2026-11-08 加） | 多集剧库全库没有一处写「多集怎么排」，接手方默认「继续做下一集」，连续三次汇报都念「下一步 E02」，三次被当场纠正 | `docs/流程总图.md` 第 0 节的四段排法（预扫 → 按季落盘 → 单集审稿 → 全剧比对）+ `examples/新剧接入.md` 11.5 节 |

**起名另有规矩**：先查惯例、再谈自造；自造要「易读 + 对仗」。真身在本库 `docs/命名准则.md`（四级命名 + 前缀登记）。

## 二、硬隔离的三级阶梯

坑不落盘会再踩，但**落到哪一级要看代价**，不是一律上重装备。**能让人根本犯不了的，先那么干**——让这个错在结构上写不出来，比任何一级都强（例：`进度台账.md` 禁手改、由 `gen_progress` 生成）：

| 级 | 形态 | 什么时候用 | 本库例子 |
|---|---|---|---|
| 0 | 判定记录一行 | 第一次踩。结论 + 理由 + 重开条件，三行以内 | 对稿器删掉「省略号=截断」 |
| 1 | 脚本断言 | 第二次踩，或能写成断言（可机判） | `selftest` 全过、`doc_lint` 各项上限 |
| 2 | 钩子拦截 | 第三次踩，或错了没人看得见（静默失效） | `pre-commit` 跑体检 + 换行符守卫 |
| ✗ | 卡片 / 清单 / 提醒 | **永不**。要靠人读才算生效的东西，等于没有 | 隔壁库的 inbox 在那边也没被严格遵守 |

**判据一句话**：这个错犯了，有没有东西会自动喊？没有，就往下走一级，直到有。**收工前过一遍**：这一轮踩的坑够不够往上走一级——不主动问，它就永远停在 0 级。**0 级不是「靠人读」**：它落的是结论和重开条件（下一棒读它才知道边界），不是指望人当场想起，跟 ✗ 那档的卡片 / 清单不是一回事。

## 三、跟隔壁库（`日常杂活`）还差什么

按「工作流程机制」对，不按字幕业务对。

| 机制 | 隔壁 | 本库 | 结论 |
|---|---|---|---|
| 经验卡 `procedures/` | 15 张卡 + `INDEX`/`_inbox`/模板 等 5 个管理文件 | 无 | **不搬**，见判定记录；能写成断言的进脚本，写不成的进判定记录 |
| MOC 导航页 | 有 | 无 | **不搬**：靠 `接棒必读`（一页目录）+ `文档落点表`（内容放哪）两层已经够，加第三层只是把同一件事写两遍。**这条不看文件数**——`docs/` 已 32 份，结论不变（2026-11-07 改：原理由写「不到 10 个文件」，前提早过期） |
| 开工索引 / `CONTEXT.md` | 有 | `docs/待办台账.md` 的「现在到哪」段 | 已覆盖 |
| 统筹手册 / 标准工序规范 | 有 | `docs/工序-*.md` | 已覆盖（清稿 / 对稿 / 验收三道必经，审稿可选） |
| 派活单模板 | 有 | `docs/派活单模板.md` | **部分覆盖**：审稿那条链有模板（模板第 0 步就是「加载两个技能」）；其余工序仍是对话里现写，不可复现 |
| skill 编写规范 + 验收清单 | 有 | 全局技能 `writing-for-agents` | **已覆盖**。写技能前加载它读判据；**本库只留一条 override**：判据进 `docs/工序-*.md`，技能只留目录 + 指路，不放命令、不放脚本名、不放判据。上游决策第五、六节不再作为引用来源（那份不随库发布，指向它就是空地址） |
| 回归集 / 盲测隔离 | 有专门手册 | 只有代码回归 `selftest` | **半缺**：判据改动该跑的盲判回归，本库没有流程 |
| 工具副本登记表 | 有 | 有 | 已对齐 |
| 成本台账 | 有 | 无 | **缺**，批量跑（9 集、整季）之前要立 |
| 成品 diff / 账本重算 | 有 | 不适用 | 本库不出成品，数据产物归各剧库 |

**上面「缺」的四项不进台账**：它们属于「等活来了再立」，现在立就是空转——但要有这一页记着，否则下一个人以为是想漏了。

## 四、一条事实只在真身处写全（2026-11-08 加）

**参数 / 判据 / 工时 / 数字，只在一个文件里写全，别处只许引 `文件:行号`，不许重写结论。**
已有参数的真身：画布 = `docs/工序-清稿-规则清单.md` 的 `MF2`；全量档工时 = `docs/工序-审稿.md:49`（约 2.8 小时/集）。**新参数在立的时候就把真身定下来，写在这条下面。**
为什么：副本越多，读者越按「先读到哪份」执行，而**重写必然丢适用条件**——审稿 `F7` 就是这么丢的（判据原文带前提，转到别处只剩「中文要补标记」，一部老剧要改 79 条）。
**能数出来的数不写死**（`#38`）：工具件数、自检项数这类脚本一跑就有的，文档只写「跑一次看输出」或指到 `tools/`。写死一个数就要几处同步，`#38` 就是这么漂成四个数的——现在 `doc_lint` 的 `check_counts` 会核工具件数，对不上报 ERROR。
**判复发**：再出现「同一事实两个数、两个说法」，算这条复发，不算新缺口——先去把两个数并成一处。
