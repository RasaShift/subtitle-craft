# 中间产物格式

> **为什么有这份**：这些格式原来只活在代码里——`align.tsv` 有几列、`result.json` 有哪些字段，
> 除了读代码没有别的地方能查到。后果有三个：别人拿到文件不知道怎么读；换实现只能先读代码；
> 从别的库搬工具时说不清「该改哪几个参数」。本文件把两类格式抄成明文，一处一份。
>
> 抄写规则：**从代码里读，不设计新格式**。列名照抄代码里的常量，示例值一律虚构。

## 一、本库工具之间的（7 个）

### 1. `X.align.tsv` 配对表

产：`tools/align_bilingual.py`（两条轨）或 `tools/bilingual_pairs.py`（一份双语字幕）　吃：`tools/triage_diff.py`

| # | 列 | 说明 |
|---|---|---|
| 1 | 中文条号 | 中文轨的条号 |
| 2 | 中文开始 | `HH:MM:SS,mmm` |
| 3 | 中文结束 | 同上 |
| 4 | 中文文本 | |
| 5 | 英文条号 | 未挂上为空 |
| 6 | 英文开始 | |
| 7 | 英文结束 | |
| 8 | 英文文本 | |
| 9 | 置信度 | 0–1 |
| 10 | 标记 | 无候选 / 被占用 / 低置信 / 标识 / 注释 等 |
| 11 | 来源 | `文件名@YYYY-MM-DDTHH:MM`，建表那一刻的字幕与时刻。**只有 `bilingual_pairs` 产的表有这一列**；`align_bilingual` 产的和旧表没有，`triage_diff` 见到只提示、不拒 |

**编码 UTF-8、LF 换行、制表符分隔**。读时 `csv.DictReader(quoting=csv.QUOTE_NONE)`——
台词以引号开头时，默认的引号处理会啃掉引号甚至吞掉后面几列（实测过一次，误判成「四条文不符」）。

**唯一例外：两张扫描清单（`mech.tsv` / `需人判.tsv`）带 BOM**，`text_scan.write_tsv` 用 `utf-8-sig` 写（为的是 Excel 直开不乱码）。读它们必须 `encoding='utf-8-sig'`——按普通 utf-8 读，首列名会变成 `'\ufeffno'`，`row['no']` 直接 KeyError。其余表都是无 BOM 的 utf-8。

### 2. `X.mech.tsv` 机改清单

产：`tools/text_scan.py`　吃：`tools/land_verify.py apply`

五列：`no` / `old` / `new` / `rule` / `note`。**前三列直接喂落地**，后两列给人看（规则代号、说明）。

### 3. `X.需人判.tsv`

产：`tools/text_scan.py --report`　吃：人

四列：`no` / `rule` / `note` / `text`。工具能认出毛病但改法不唯一，挡在这里等人加行。

### 4. `X.triage.tsv` 对稿分诊表

产：`tools/triage_diff.py`　吃：人判 → 结论进改动表

| # | 列 | 说明 |
|---|---|---|
| 1 | 中文条号 | |
| 2 | 中文开始 | |
| 3 | 中文文本 | |
| 4 | 参照文本 | 英文轨原文 |
| 5 | 建议代号 | `T1` 漏译 / `T2` 误译 / `T3` 表述差异 / `T?` 无法判定 |
| 6 | 规则 | 命中哪条规则，如 `DR1` |
| 7 | 理由 | |
| 8 | 证据 | 具体对不上的词或数字 |
| 9 | 需人判 | 是 / 空 |
| 10 | `stage` | 这条是在哪一步产生的 |

### 5. 改动表（落地用，也叫 `all.tsv`）

产：人（对稿定案 + 审稿清单并成一张）；**findings 那一路可用 `tools/findings2tsv.py` 直接转**　吃：`tools/land_verify.py apply`

三列必需：`no` / `old` / `new`。可选追加 `rule` / `note` / `evidence` / `old_time` / `new_time` / `stage`。
**可选列按表头认名**（`no`/`old`/`new` 或 条号/旧文本/新文本 都认）；**没有表头时只认前三列**——第四列起在旧表里可能是 `rule`，按下标猜会把它当时间码。

**`old_time` / `new_time`（2026-11-10 加，`GQ-22`）**：字幕要动时间码时写这两列，各自 `开始-结束`（如 `0:11:41.12-0:11:42.12`），**两侧写全**。它们与文本一样走双锚点：`old_time` 必须与改前一致，否则按失配处理、不改不猜；`verify` 同时比文本与时间码，所以「改了时间码却漏在表外」会红。只支持 ASS——SRT 的时间码在 `-->` 行里，改它等于改块结构。

**`stage`（2026-11-10 加，`GQ-28`）**：`mech` / `triage` / `read` / `fmt`，跟对稿清单里那一列同一套值。**`fmt` = 格式层动作**（话轮标记这类），`accept` 靠它把「审稿改动」和「格式层动作」的密度分开算——混在一起时那个数没有判读价值（某集因同集加话轮标记报 18.59 条／百条，看着像审稿失控，其实 78 条是格式）。**注意别跟 `accept.py` 的 `--stage` 参数混**：那个指的是「定档.md」，同名不同义。

**`evidence` 是 2026-11-08 补的第 4 个可选列**：改动表原先没有这一格，所以人工合并时 evidence 必然整段丢，验收第 6、7 项（evidence 空 / 查无出处）只能人读。`findings2tsv.py` 会把 findings 里的 `evidence` 原样搬过来。
**`old` 必须与字幕里那一行的文本逐字一致**——落地按「条号 + 旧文本」双锚点写回，文本对不上直接拒。

### 6. 补行表（`ins.tsv`）

产：人　吃：`tools/land_verify.py apply --inserts`

六列：`start` / `end` / `cn` / `en` / `after_no` / `style`。
位置由 `start` 时间算；`after_no` 填了就核对，对不上退出码 2。
只支持 ASS。`start` 是时间的唯一来源，`after_no` 只管位置——老库反过来按 `after_ln` 定位，出过「后一条的时间早于前一条」的跳行。（原来这句指向 `docs/流程总图.md` 第 5 节，2026-11-07 改成自包含：这份要随模板进新库，指针一断就成了死链。）

### 7. `词表.tsv`

产：人填（候选由 `tools/term_candidates.py` 出）　吃：`text_scan` / `triage_diff --term`

四列：`原文` / `规定译法` / `已见错写法` / `备注`。
一种写法只许有一个规定译法；两种都合法时写进备注，不硬压平。

## 二、剧库里那套（5 个，老库工具吃或吐）

> 本库不生产这些，但搬工具时要按它们改参数。格式由剧库的实际运行决定，不是本库发明的。

| 文件 | 产 | 吃 | 格式 |
|---|---|---|---|
| `worksheet.tsv` | 剧库的建表脚本 | 盲测抽样、隔离复核 | 四列：`行号` / `时间码` / `中文` / `英文`。**行号是 ASS 文件里的物理行号**，跟 findings 一致 |
| `review.tsv` | 执行方交回 | 分档分流 | **表头驱动**（第一行是列名），必含 `ln` / `tc` / `cn` / `en` / `fix` / `why`。实测带 BOM，一律按 `utf-8-sig` 读 |
| `candidates.tsv` | 隔离复核打包时生成 | 分档分流 | 与 `review.tsv` 同构，条号集合必须一致——多一条少一条先跑复核再过 |
| `result.json` | 执行方交回 | 隔离复核、语义校验 | `{"issues": [{ln, problem_type, severity, confidence, evidence, suggest}], "groups": [{"items": [...]}]}` |
| `judged.tsv` | 人判完留档 | 分档分流（剔已判过的） | 第一列是 `ln` |

**三个坑**（都是实测撞出来的，迁工具时要一起带过去）：

1. `review.tsv` 的编码是 `utf-8-sig`，按 `utf-8` 读会让第一列列名带 BOM，`ln` 匹配不上
2. `result.json` 的 `issues[].ln` 必须落在 worksheet 的行号范围内，否则是拿错片了
3. 候选表与复核表的条号集合不一致时，先跑复核，别直接分流

## 三、两套的关系

```
剧库：worksheet.tsv → 盲测/复核 → result.json / review.tsv → 分档分流
本库：align.tsv → triage.tsv ─┐
      mech.tsv ───────────────┼→ 改动表 → 落地 → 验收
      需人判.tsv → 人加行 ────┘
```

**不通用是有意的**：剧库那条链是「模型跑一遍、人复核一遍」，本库这条链是「机器挑候选、人判一遍」。
两套之间只有 `词表.tsv` 和「条号」这个概念是共用的。

**共用约定**（两套都遵守）：条号一律指 ASS 里的物理行号；TSV 一律制表符分隔；文本里的换行压成空格。

## 四、字幕文本里的排版约定：话轮标记

> **这一节是话轮标记的真身**，判据（审稿 `F7`）、手册、派活单都只引用，不各写一份。
> **标「待验」**：只在一部剧七集（加 171 条）上跑过。第二部剧照它走过一遍才定死。

一个人说话和两个人说话挤在同一条字幕里，观众分不清谁接谁的话。标记就是那个分隔符，长这样：`-甲\h\h-乙`。

**五条，改之前先看为什么：**

1. **双语条不拆行**，话轮在同一行内分开。中英已经占了两行（中文 + `\N` + 英文），再按话轮拆就是四行——字号不变，字幕块高度翻倍，4:3 画面下部会压到人，而且行高一变，样式器的字号边距全要重算。**只有单语交付（无英文轨）时才拆行。**
2. **中文用半角 `-`、紧贴台词**（`-甲`）。不用破折号 `——`：台词里本来就用 `——` 表示语气中断，同一个符号两种意思，观众分不清；也不加空格，一个空格半个字宽，长句会提前贴边。
3. **英文用 `- `（连字符 + 一个空格）**，沿用底本自带的写法。**中英样式不一样是规定的，不是错**——中文标记是我们加的，英文标记是原文自带的，来源不同各按各的习惯。
4. **分隔用 `\h\h`（ASS 硬空格）**，不用连续半角空格。渲染器保不保留连续空格没有保证，而这类错在别人机器上才看得见、自己屏幕上永远正常。
5. **老集不追**：已经落盘的成品保持原样（某剧七集用两个半角空格），公约只管新做的。见到老集别当漏改去「修」。

**数法**（`F7` 的口径）：中文行首 `-` 的个数，与英文侧 `- ` 的个数对齐；`\h` 不参与计数。**要数个数、不靠念。**

## 五、以后加新格式时

2. 再写代码 —— 反过来的话，格式又会只活在代码里
3. 加格式时顺手在 `tools/selftest.py` 补一条断言（列数、必需列名）
