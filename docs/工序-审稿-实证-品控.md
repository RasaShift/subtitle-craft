## 18 候选数 ≠ 人工要判的数

- **不跑预筛，41% 的人工花在成品已经改好的行上。** 这就是预筛存在的全部理由。
- **「跳过 N 条」不是结论**：必须人工扫一遍跳过明细（`<key>_已改过.tsv`）。同一行两处问题时，旧 finding 只覆盖一处、整行被跳过，第二处会**静默消失**。实测 S02E01 第一版剔 8 条，其中 **5 条是真问题**（同行两问题 2 条 + `en_typo` 型旧 finding 根本没碰中文 3 条）。
- **自动判「同行两问题」不采用**：按改动区段判会把措辞变体也算成两处，误报比抓到的真问题多。用 `--force-new` 手动捞。
- **判「成品改好没有」读 `03_成品/`，不是 `定稿基线/`**——后者是审稿输入，内容不同。

## 19 第三方复核

- **复核结论只作参考列，不做出发点**：实测与用户定档重叠 17 条，明确结论 9 条里**只对上 1 条**，3 条方向相反。
- **隔离目录绝不放候选清单**，放了就锚定，测试作废。
- **`--judged` 是防「判宽」的监视闸**：不改档漏报率 >30% 判本片复核失效。闸只管判宽，召回靠盲测兜，两个数都要看。
- **抽检人判「要改」时看理由落在哪**：落在 C1/C2/C3 才算 AI 漏判；只说「读着别扭」不算。一批里 C1/C2/C3 类漏判 ≥2 条才回去调提示词。

## 20 落盘与 merge

- **`verify` 绿 ≠ 改动到位**：它只校验 patch 内的条目，**被 merge 丢弃的条目它不知道存在**。三个数字一起看：findings 条数 → merge 保留数 → apply 应用数。
- **merge 丢弃数必须逐条看原因**——丢弃表基本等于执行方的抄写错误清单，同时就是打回证据。只看「0 被拒」就放行是错的：被丢弃的压根没进 patch，`apply` 无从拒绝，永远显示 0。
- **越界硬校验**：findings 行号落进 `recap_boundary.json` 的回顾区间 → 中止。
- **撞旧条就地改**：目标行已有旧 finding 的，补 `cn_new` 并改 `type`，不新开条。
- **待议 = 停手**：待议条目一律跳过并报「待议 N 条未落，等确认」。

## 22 盲测：它是成本开关，不是质量认证

- **100 行抽到 1 条，按比例外推全片还有 5–6 条**；可真实漏率 1%／百行时，抽 100 行有 **37% 的概率一条都抽不到**。**0 和 1 的差别常常落在抽样噪声里。**
- 拿它决定「要不要再花一次钱」可以；拿它证明「这集干净」不行。**密度当年就是被当成质量证明才出的事。**
- **抽样底本必须是「改后」的**（2026-11-04 续二 E01 踩）：续二 E01 第一次抽的 L264–L273 段正好压住已改的 0:15:04.82，整批重抽。拿首轮分片直接抽会照到已经改好的行——被测方「报出」它们，白算重叠，还稀释真漏判断。
- **0 漏只是「没找到证据」，不是「已证明干净」**：E03 片 1 盲测 0 漏，整片复扫又补出 **7 条**。

## 23 真漏处置表（阈值与理由）

| 真漏数 | 处置 | 依据 |
|---|---|---|
| 首轮密度 < 1.5（判崩） | **直接全片复扫，不看盲测结果** | E03 首轮密度 0.94，盲测真漏 0，整片复扫补 7 条——**首轮判崩时抽样里本来就没东西可漏，盲测的 0 是假象** |
| 0 | 收工 | — |
| 1 | **同类定向扫**（写错因形态清单，只找同类） | 1 条外推全片还有 5–6 条，装看不见不行；但一次全片复扫抓 5 条不成比例。**漏通常成簇**——E07 的 20 条里 14 条同属三类，告诉 Agent「只找这一类」命中率更高 |
| ≥2 | **带候选全片复扫** | — |
| 漏得分散、彼此矛盾 | **重判**，不补扫 | 判读方向性错误，补扫救不回来 |

- **重判 ≠ 复扫**：重判不给原候选、整片从头判，代价最高（会把已经判对的一起推翻）；复扫带原候选、只找没被覆盖的。**有漏但方向没错 → 复扫；方向性错误 → 重判。**
- **补扫之后不再抽样复验**（2026-11-02 砍掉）：补扫本身就是把全片过了一遍，再抽 40 行是重复劳动，还会把最坏情况从 4 个 Agent 拖到 5 个。
- **口径附注**：8 集实测真漏 **0/0/0/2/4/2/5/0**，5 次触发补扫、占 62%。**这个比例反映的是首轮判得不够全，不是门槛定高了。** 想降它得提高首轮覆盖（两遍分开派就是为这个），调松门槛只会把漏留在成品里。

## 24 合并去重

- **一集通常出三份候选**（首轮 / 盲测补 / 复扫补），落盘前必须并成一份，否则同一行会被改两次，或两处改法互相打架。
- **按时间码去重**——续一 / 续二 没有稳定行号，别拿行号做键。
- 同一时间码出现两次 → 保留首轮那条，把新增理由并进「一句话理由」栏，**不新增行**。
- **E07 实录**：17（首轮）+ 5（盲测）+ 15（复扫）= **37 条，零重复**；合并后片1 6.07、片2 4.82、整集 5.60。
- **判读方给的建议改法大多是半句**（E07 37 条里 **12 条**），合并时要把每条补成能整行替换的完整中文段。落盘方逐条拼回整行，那次多花 12 分钟。

## 25 预演与写盘

- **改后串不能是改前串的超集**（如 `他还没回来 → 他还没回来呢`）→ 撞 `assert old not in zh2`，**整批不写盘**。换措辞：`他压根还没回来`。
- **改前串不能与另一条规则的改后串首尾相接**，否则撞残留断言、整批不写盘。两行对调时把改后串写成互不为对方改前串的措辞。
- **`--allow-empty-new` 管的是「改后串为空」，不是「改前串为空」**（2026-11-02 修正，旧版这句写反了）：
  - 改**前**串为空 → 写盘脚本直接退出，**这个参数救不了，只能手改**。手改后声明里「改后中文」要写成含样式标签的整串，`verify` 的 V2 才过。**全库 NB+R 20 集这种行只有 2 处**：E05 `0:15:50.78` 已手改补好；E06 `0:01:10.09` 是歌名，本来就不该有中文，不动。
  - 改**后**串为空 → 必须加 `--allow-empty-new`。
- **规则写盘前自检三条**：一条规则只能有一个 `→`、改后串不含改前串、不含 ASCII 逗号（会把 `--rules` 切碎）。
- **声明文件名带系统日期，不是开工日期**。
- **分批 apply 时，多批声明要合并成一份、用第一批的基线统一验一次**。各批单独验会互相报 V6「声明外被改」，属正常现象不是错。

## 26 污染与泄漏（做盲测时最容易破的）

- **题面目录里每一个文件都 grep 一遍当集的特征串**——人名、专有名词、当集独有的长句、以及当集已落盘的改前／改后文本。命中任何一条，题面作废、重做。
- **2026-11-02 踩过**：把某集的三条真实答案写进判据当例子，又把判据发给被测方，被测方当场指出「泄漏的不算盲判召回」，**那次回归只算半次**。判据文件是双用途的——既是执行标准也是教材，教材举例就会漏答案。

## 27 一条元原则

**会报错的检查才值得信。** 新增或改动任何检查后，先故意造一个错看它认不认；认不出的检查等于没有。
