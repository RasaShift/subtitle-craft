## 用到的工具

| 干什么 | 本库命令 |
|---|---|
| 扫候选，分成「机改」「需人判」两张清单 | `python tools/text_scan.py <字幕> --term <词表.tsv> --tsv <机改.tsv> --report <需人判.tsv>` |
| 清单落进字幕、当场复算 | `python tools/land_verify.py apply` / `verify` |
| 文件层（编码 / 画布 / 样式表） | `python tools/style_normalize.py apply` / `verify` |

**两张清单的列定义在 `docs/中间产物格式.md`**（`mech.tsv` 5 列 / `需人判.tsv` 4 列）。列不对，下游读不了。

**本库没有的两件，别去找**：
- 老库有个分诊脚本会**自动扫判定表、把判过的行归「已判过」**；`text_scan.py` 不做这件事，重跑会把判过的行再列一遍。所以「还剩多少」得自己算差集（见第二节）。
- 剧专用的查表规则表（整张真实人名，是术语表本身）**不搬**。判据看 `docs/工序-清稿-规则清单.md`（MT 各条的判法与边界）。

## 一、开工先说一句（触发声明）

**凡按本技能干活，回复第一行必须写声明**——哪怕只是照派活单做事、没觉得自己「在用一个技能」。派活单里出现 `subtitle-clean` 就等同于被触发。

走注册表正常加载时：

```
已加载 skill：subtitle-clean（注册表）
```

只被 `@skill:` 附着、或按路径人工读了一遍而**没进注册表**时：

```
已按路径读取 SKILL.md：subtitle-clean（未进注册表）
```

**两种写法的区别就是信号本身**——它区分「技能自动触发」和「人读了一遍」。旧写法两种情况写同一句，标记等于失效。**派活单点名本技能时先调 `Skill` 工具，再谈读哪些文件**；只把判据路径写进派活单，执行方会直接当普通文件读，这个信号就丢了。

用户只是提到字幕、没要求判读 → 不触发，直接回答他的问题。

## 二、干什么（输入 / 输出 / 落位）

| | 路径 |
|---|---|
| 输入 | 查表扫描出的必看表（`text_scan.py --report` 的产物，4 列） |
| 输出 ① | findings JSON（**只追加**，字段格式按 `docs/findings写法.md`，本技能不定义文件结构） |
| 输出 ② | 逐行判定表 `…/交接/<任务名>查表/判定_<季>.tsv`，**待判行一行不漏** |
| 简报 | 同任务目录下，三问见 `docs/判断纪律.md` 第 4 节 |

**输出 ② 的位置是约定，不是建议**：本库没有工具替你归并，下一批要靠人按位置找它、算「还剩多少」。写到别处 = 下一批把判过的行重新列一遍，且差集只能人工一个个比。

## 三、先确认这一批的边界

开工前确认三件事：

1. 哪一季、哪几集
2. 待判多少行 —— 与必看表的**实际行数**核对
3. 本批特有禁区

**数字不一致时**：以必看表为准，但**必须先停下来报给统筹方**，等确认再动手。

必看表是脚本按当前规则生成的，派活单是人提前写的。**重跑过 scan 之后派活单常常过期**（撞过一次：派活单写 35 行、实际 41 行，差的 6 行是规则修订后新增的）。不要自己猜该判多少行，也不要拿别的季的派活单凑数。

## 四、动手前读什么

1. **判据（必读，只有一处）**：`docs/工序-清稿-规则清单.md`——工具标签的口径**只在那里定义**；旧号折算与片头行例外见 `docs/工序-审稿-判据.md` 第二节。
   引用判据一律写本库编号（必看表里看到的是工具旧号，别当成另一条规则）：

   | 工具旧号 | 本库编号 |
   |---|---|
   | `R07a` 旧译残留 | 清稿 **MT1** 译名错写 |
   | `R04` 数字不一致 | 对稿 **DR1** |
   | `R10` 空段 | 对稿 **DR2** 整条未译 |
   | `R07b` 人名未直译 | 审稿 **C2.2 / C2.5** |

2. **当批派活单（必读）**：任务边界、预置陷阱、交付路径、禁区、自查脚本都在里面。
3. **流程与收尾**：以派活单为准；派活单没写到的，查 `docs/流程总图.md` 与 `docs/工序-清稿.md`。

## 五、冲突优先级

`当批派活单 > ../SKILL.md > 该工序的判据来源`（判据来源 = `docs/工序-*.md`）。冲突必须在简报里写一行上报。

**「不许改」不等于「不许读」**；派活单列了「只读这些路径」才是禁止读。

## 六、硬约束

- findings **只能往 `findings` 数组里追加**。不许改已有条目、不许删、不许重建文件。
- 每条 `cn` 必须与源字幕**逐字一致**（含空格）。抄错会被落地器的四重定位拒掉。
- `evidence` 必填，必须引用原文片段。
- `season` 是两位字符串 `"01"`，`episode` 是 `"01x01"` 这种字符串——**不是数字**。写错会被静默丢弃。
- **不要跑 `apply` / `verify`**。那是统筹方的活，你交清单和简报就结束。
- **不改别人的库**（`日常杂活` / `是大臣系列`）里的任何文档。有发现写进简报的「顺带发现」一节。
- 判「不改」的也要留记录，别只交「改」的。

## 七、落盘与自查

交之前跑这三条，都过再交：

1. **行数对得上**：判定表行数 = 必看表行数。不相等就是漏判，别交。
2. **`cn` 抄得准**：每条「改」的 `cn` 回原字幕里搜一次（`grep -F`），逐字能对上。
3. **表格读得出**：判定表与机改清单能被 `csv` 模块按 `\t` 读出，列数与 `docs/中间产物格式.md` 一致。

两个常踩的坑：

- **词表列数不对会静默少匹配**（不报错，看着像「这一批没有译名问题」）。
- **两张清单带 BOM**（`write_tsv` 用 `utf-8-sig` 写）。按普通 `utf-8` 读，首列名是 `'\ufeffno'`，`row['no']` 直接 KeyError——读的时候必须 `encoding='utf-8-sig'`。

字幕本身不必先转编码：`land_verify.load` 认 UTF-8 / UTF-8-BOM / UTF-16，写回时用原编码，不会凭空多一个 BOM。但**自己写脚本读字幕时必须显式指定编码**，按默认 utf-8 读 UTF-16 会得到一堆乱码。

## 八、撞到现象先搜经验卡

改了没生效 ／ 替换没匹配上 ／ 数字离谱 ／ 脚本报红 → 先花十秒搜一次，别从零试错。**检索命令的唯一定义处是 `buddy-workflow` 技能第 2 步**（这里不抄，防两处漂移）。踩了新坑当场补进 `docs/工序-清稿-实证.md`。

## 九、交回什么

**三件，缺一件都不算交回**（格式与简报三问见 `docs/判断纪律.md` 第 4 节）：

1. **findings**：只追加，`cn` 逐字一致。字段（`layer` / `type` / `severity` / `tc` / `cn` / `cn_new` / `en_after`，补行走 `inserts`）按 `docs/findings写法.md` 写——本技能只判该不该改；写错会被并表静默丢弃（不报错）。
2. **判定表**：待判行一行不漏，判「不改」也要写。
3. **简报**：第一节**必须是大白话**——这批改了啥 / 有没有拿不准的 / 用户要不要做什么；后面写判了几条、采纳几条、哪几条拿不准、跑了什么自检。
