# 工序 · 对稿 · 机判与人判

> **最后更新：2026-11-08** · **这是哪一份**：`docs/工序-对稿.md` 第 5 节的详细版。拆出来的理由：这一节是「一条规则一行」的清单，会随规则增加一直长；主干讲的是判什么、怎么判，两样寿命不同。
> **管什么**：哪一条能交给机器挑嫌疑、哪一条必须人定案；无参照时判得了什么。
> **管不着**：判据本身（主干第 3、4 节）、输出字段（主干第 6 节）、错位区间怎么算（本文第 3 节）。

## 1. 分工表

| 项 | 谁判 | 说明 |
|---|---|---|
| 配对（谁跟谁比） | 机器 | 按时间轴做单调保序匹配，不看文本相似度 |
| 中英比例过低 | 机器 | 中文字数 ÷ 参照词数 < 0.6 且参照 ≥6 词 → 疑似漏句。阈值必须取保守值：0.8 会把「你要发表讲话」6 字对 8 词这种正常句也报出来（实测假红）。**这一档天生低精度**：两部剧实测两条分布几乎重合（中位都 1.50、P01 都 0.78），而真漏（0.44）和「中文简洁」（0.50–0.57）落在同一段——**没有哪个阈值能切分开，调阈值只会拿真漏换假红**。只当嫌疑，必须人看 |
| 数字对不上 | 机器 | **只查一个方向**：参照有、中文没有。反方向全是写法差异（「5月」对 `May`、「2万1千793」对 `21,793`）。**比之前必须先归一化**：中文按亿/万分节、「7点45」并成 745；参照认点号千分位（`23.000`）、时间点号（`10.00`）、量级词（`32 million`）。不做这层，9 集一次误报 15 条 |
| 整条没译 | 机器 | 中文轨这条一个汉字都没有，却配上了参照 |
| 术语与译名一致 | 机器 | 要有词表；没给词表就判不了，工具会明说 |
| 句子截断、语法不成立 | **人** | 机器挑不了。实测用「省略号/连词结尾」当截断，538 条里挑出 83 条**全是正常分句**，假红 100%，规则已删 |
| 分句 / 中文更简洁 / 缩写保留 | **人** | 这三类机器只能报出来给人扫，改规则就会连真错一起放过。9 集实测 3 条，占候选 43% |
| T1 有没有缺 | **人** | 语义问题，机器判不了「这句的意思在不在」 |
| T2 意思对不对 | **人** | 机器只能按上面几条挑嫌疑，不能定案 |
| T3 vs T2 的分界 | **人** | 「说法不同」和「意思不对」只差一层理解 |
| 错位区间在哪 | **人** | 要整段读一眼才判得出「这一段对不上」；机器划不出来，划了也只会多一层要维护的规则。见第 3 节 |

## 2. 有参照 / 无参照各判得了什么

| 模式 | 能判 | 判不了 |
|---|---|---|
| 无参照（只有中文轨 + 配对） | T2 的一半（中英自洽、截断、语法、数字专名）、T3 | T1 全部；「跟参照比」的那一半 T2 |
| 有参照 | 全部 | —— |

无参照时必须**明说判不了什么**，不许默默把 T1 记成 0 条——那会被读成「一条没漏」。

## 3. 错位区间：人划，机器只消费

**是什么**：某一段里中文和参照整体错开了——上一句的中文配上下一句的英文。这段的每条对子都「看着不对」，但错在配对，不在译文。逐条比只会把每一条都报成误译。

**谁划**：人。**机器不划**，理由同第 1 节的阈值问题——「这一段对不上」得整段读一眼才判得出，靠置信度阈值划，又是一条调不出好阈值的规则。

**怎么给**：一张三列 TSV（带不带表头都行）：

```
起条号	止条号	理由
318	331	西语现场对白，中英整体错开一句
```

**怎么用**：
- 对稿：`python tools/triage_diff.py <配对表> --offset 区间.tsv`，区间内的对子**不判、不出候选**，统计行报「跳过错位区间 N 条」。
- 审稿：区间表原样带过去，那几行**整段读**，不逐条比。

**三条纪律**：
1. 跳过 ≠ 没问题。报出「跳过 N 条」就是为了让这件事留在账上，别被读成「这段干净」。
2. 区间只划到「配对错开」为止。译文本身有问题，另立条目，别拿区间把它一起盖掉。
3. 区间表是要传给下一道的料，落在工作区，别只存在对话里。
