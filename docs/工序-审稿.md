# 工序 · 审稿

> **这是哪一步**：「通用工序定义」的第三份，也是**主线**——只有这道能判「观众会不会理解错」。
> **管什么**：先定档（这道题要读多深），再按档读。三道里**唯一不能机判**的一道。
> **不绑什么**：不出现剧名、季号、集号规则。

## 1. 这道工序解决什么

另两道都解决不了的那类错：**字都对、话也通、意思偏了半格**。

| 错 | 谁抓得到 |
|---|---|
| 译名不统一、标签残留、贴字 | 清稿 |
| 整句没译、数字对不上 | 对稿（要参照 / 或配对） |
| 否定拧反、时体错、漏半句、反讽读反 | **只有审稿** |

老库的反例：S03 只做了查表（= 本库的清稿 + 译名），63 处改动全是译名和拼写，**一条错译都没查出来**。做完对轨的 E04 再逐句读，还能补 43 处，其中一半是「英文对得上、中文意思不对」。

## 2. 输入

| 输入 | 必需 | 干什么 |
|---|---|---|
| 中文轨（或中英双语轨） | 是 | 被读的对象，一条不动 |
| 英文原文 | **否** | 有它才能判「否定／时体／数字／漏句」；没有就只能判「中文自己读不通」 |
| 词表 | **否** | 有它才判得了「术语与规定译法不符」，没有只能判「同一概念前后两种译法」 |
| 错位区间清单 | **否** | 人划的整段错开区间（怎么划见 `docs/工序-对稿-机判人判.md` 第 3 节）。那几行的中英对照本身是错的，读它必然误判——**整段读，不逐条比**，跳过 ≠ 这段没问题 |

**先认剧型再往下读**：正传 / 续一 / 续二 是三条步骤不同的链，走错一条整集白读（续篇要共用基准词表再按剧过滤，判据也跟着不同）。剧型名只有这三个词，见 `docs/命名准则.md` 第五节；每条链的具体步骤在 `docs/工序-审稿-手册.md`（正传七步、开工分片都在那一份里）。

## 3. 定档：这一集读多深（读之前先判这一件）

**判据是输入质量，不是流程走到哪。** 三条信号，按序用：

| 信号 | 怎么用 |
|---|---|
| **来源先验** | 机翻 / 无校对 → **直接全量**，不抽样，也别指望它好 |
| **抽 40 条** | 前/中/后各 13–14（只抽开头会高估：前段投入多、后段赶工）。**出现 1 条硬伤 → 转全量** |
| **对稿候选数** | **只单方向**：多 → 判全量；少 **不作证据**（对稿只有四条粗规则，候选少不等于翻译好） |

两条硬提醒：

- 40 条里 1 条硬伤 = 2.5%，放到一集 500 条就是 12 处错译，观众一定撞得上。**抽样在这里的作用是「发现」，不是「证明没问题」**。
- 抽到 0 条**不许写成「质量好」**，只能写「未发现硬伤」。

## 4. 两档：全量审 与 关键点核

| 档 | 什么条件下用 | 做什么 | 估时（一集 500 条） |
|---|---|---|---|
| **全量** | 来源差 / 抽样出硬伤 / 对稿候选多 | 按第 5–8 节逐条读 | 约 2.8 小时 |
| **关键点** | 来源好或不明 **且** 抽 40 条 0 硬伤 | 只核四条：`1.1` 否定、`1.5` 数字金额年代、`3.1` 既成事实、`3.3` 人物关系 | 约 20–40 分钟 |

**关键点档为什么是这四条**：它们错了会让观众**理解错剧情**，不是「读着别扭」。其余条目（措辞、语气、反讽弱化）漏了只是不够好，本来也在第 6 节「不报」里。

**关键点档会漏掉什么，要说清**：中文通顺但意思偏半格的那类——它恰恰是 C 组的典型命中项。所以这一档不是「审过了」，是「只排了最贵的雷」。

**定档结论落 `定档.md`**（剧库 `02_工作区/`，三行）：来源判断 / 抽样结果（抽了哪些段、几条硬伤）/ 档位。不留痕的话，下一棒要重判，发布后也查不到这版过了哪一档。

## 5. 判断路径（只问一句）

```
一行
  └─ 观众看到这一行，会不会理解错？
        ├─ 会 ──→ 应改（落盘）
        └─ 不会 → 不改（不落盘，含「读着别扭 / 翻译腔 / 不够精确 / 声音不贴」）
```

**「可改可不改」这一档已取消**（2026-10-31），整档并入不改：落到成品观众看不出来，而且它吃掉过一批人工判量的四成。

两条硬规矩：① 不许拿「读得通」当省事理由——它只证明「句子没塌」那一条没命中；② 不许把判据写成「与原文等义」，粒度说不清就必然各判各的。

## 6. 判据（条目在另一份）

十四条命中项、十二类不报、七种形态、关键点档要核的那四条，全在 `docs/工序-审稿-判据.md`。这里只留一句：**十四条全不命中 → 不改，命中任一 → 应改**。

## 7. 怎么读（全量档用；顺序不许反）

1. **先整句回读，再查清单**：读完英文 → 读中文 → 问「说的是同一件事吗」。不是就报，不必翻清单；同时先看上下文前后各 2 行，很多「错」在上下文里自洽。
2. **合上英文，中文单独念一遍**：念着卡、要回读的地方全记下。抓的是不需要英文就能发现的错。
3. **逐词核三样**（与上一条并列）：时态与语气（`almost / would have / used to / still / already`）、关键名词是不是同一个东西、限定词与范围（`only / never / most / every / all`）。老库实测：首轮漏的 20 条里 14 条属这三类，**中文全都念得通**。
4. **别打开英文逐词比措辞**——那样必然产出一堆「不够精确」，全部不报。

**必查顺序**（这几类以前整批漏过）：否定词 → 时体 → 主客 → 数字／年代／金额 → 专名与术语 → 「既成事实」→ 整句信息完整性 → 中文自身通不通 → 话轮标记。

## 8. 哪些机器判、哪些必须人判

| 项 | 谁 | 说明 |
|---|---|---|
| 切片、查前情回顾段、预筛已改过的行、密度统计 | 机器 | 只省人工，不产生判断 |
| **十四条命中项、该不该报（C 与 N 的边界）** | **人** | 全是语义判断，机器一条都不该定案 |

**这是四道工序里唯一机判项为 0 的一道**——别指望用规则替代它，能做的是把判断拆小、给出清单、上抽样。

## 9. 输出

| 字段 | 内容 |
|---|---|
| `no` / `old` / `new` | 前两列逐字照抄，抄错就锚点失配 |
| `rule` | 依据条目，`C1.4` 这类编号；说不出编号就是没判据 |
| `evidence` | 英文原句片段或上下文行号，必须能当场复算 |
| `source` / `stage` | `source` = 谁判的（模型名或 `human`）；`stage=read`，与清稿 `mech`、对稿 `triage` 分开 |

## 10. 三问与完成标志

| 三问 | 答案 |
|---|---|
| **触发条件** | 定档之后；人划的错位区间要带进来**整段读**（不是逐条比，也不是跳过不读） |
| **完成标志** | ① 档位声明过（`定档.md` 有档位与依据）② 该档要求的范围真读过（全量=每条都过；关键点=四条都核）③ 落地：实改 = 声明、跳过 0 ④ 净落盘密度落在 1.8–7.0 条／百行，超出要解释 |
| **不跑会怎样** | 错译、欠译、反讽读反全留在成品里，**没有任何别的工序会替你发现** |

**校准锚点（实测，别当目标值）**：候选密度 14.3 条／百行；整季净落盘 2.3–7.0；十集 1.78–6.20。数字是拿来找异常的，不是拿来凑的。

**抽样复验（判完自己回头查的那一步，不抽就等于只有一轮）**：判「不改」的候选**每批抽 1/3**，查有没有把真问题判成不改；已落盘的「应改」**每 5 集抽 1 集**全量回看，查误改率（应 **< 5%**）。抽出来的若不是个案，说明 C 组边界要重调，**别逐条返工**。

## 11. 禁区

1. **判据只能由不干活的人定**，改的人不验、验的人不改。
2. **不许为了压低条数放宽 C 组**——压的方法只有一个：把真错也说成「读得通」。
3. **不许把「可改可不改」捡回来**，它已经被取消一次。
4. **不许跳过定档直接读**：跳过的后果是「不知道这一集该读到什么程度」，也就无法声明完成。
5. **抽样给的是片段**：段首那行前半句常在上一行，判「缺主语／否定反了」先回看一条。
