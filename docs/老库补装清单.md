# 老库补装清单

> **什么时候用**：库**已经存在**（不是 `scaffold.py` 建的），想把通用件装进去。
> `scaffold.py` 只能从零长；老库比骨架早，后来加的每一样它都拿不到。这份清单补的就是这条路。
> **判断法**：先看它缺什么「**机器能喊的**」，缺「人记得的」不用急——人记得的东西写一次就在，机器该拦的没有闸，写了也等于没有。

## 一、先分清两类缺

| 类 | 例子 | 优先级 |
|---|---|---|
| 人记得就行 | 接棒必读 / 判定记录 / 进度台账 / 卡点表 | 它自己会长出来，别急着灌 |
| **要机器喊的** | 文档体检 / 提交守卫 / 忽略规则 | **先装这四件** |

一个库「缺得多」往往不是缺文档，是**缺自动化的那一层**：人写的东西都齐，机器该拦的全空。

## 二、四件，按顺序装

| # | 装什么 | 放哪 | 要改什么 | 不装的后果 |
|---|---|---|---|---|
| 1 | `tools/doc_lint.py` | `<库>/04_工具/`（任意子目录都行） | 跑时加 `--docs <你的文档目录>` | 文档没有体检，超限靠人眼发现 |
| 2 | `examples/新库骨架/.githooks/pre-commit` | 库根 `.githooks/` | 提交前跑一次 `git config core.hooksPath .githooks` | 提交前什么都不跑，体检形同虚设 |
| 3 | `.gitignore` 两条规则 | 库根 | 「忽略 memory 下全部」+「放行 MEMORY.md」两行 | 日志含剧名台词却进版本库，将来开源就是红线 |
| 4 | `MEMORY.md` 模板 | `<库>/.workbuddy/memory/` | 换掉 `{{库名}}` 占位，按三节填 | 记忆层没有上限也没有分工，会越长越像文档 |

第 3 条的两行别写反顺序：先 `*` 全忽略，再 `!` 放行单个文件。反着写不生效。

## 三、不必装的（按规模判，别一股脑灌）

| 通用件 | 为什么不装 |
|---|---|
| 文档落点表 | 治理文档不到 15 份时，维护一张表的成本高于收益。超了再装 |
| 待办台账 + 详情 | 进度台账若已在兼这个职能，两套会打架，先并成一套 |
| 骨架其余文档 | 骨架是给新库从零长的；老库的结构已经长成，硬灌会覆盖掉它自己的写法 |
| `做法.md` 全份 | 只抄第二节「三级阶梯」，其余是通用库自己的账 |

## 四、装完怎么验：三条命令，都要看到数

```bash
# ① 体检能真的查到你自己的文档——不该满屏「找不到」
python 04_工具/doc_lint.py --docs 06_治理

# ② 日常用 -q，只留 ERROR，WARN 不刷屏
python 04_工具/doc_lint.py --docs 06_治理 -q

# ③ 记忆层：MEMORY 在库里、日志不在
git ls-files .workbuddy/memory/
```

第 ③ 条期望**只有 `MEMORY.md` 一行**。多出 `YYYY-MM-DD.md` 就是 `.gitignore` 没写对。

## 五、`--docs` 为什么不是 `--root`

`ROOT = Path(__file__).resolve().parents[1]`，由**脚本位置**决定。脚本放进 `<库>/04_工具/`，`ROOT` 自动就是 `<库>`——所以 `--root` 从来不需要。

真正会错的是下一级：`DOCS = ROOT / 'docs'`。老库把文档放 `06_治理/`、不叫 `docs/`，于是每一项都报「找不到 `docs/X`（跳过）」，**全绿，但一个字没查**。

`--root` 解决不了这个，只能 `--docs`。不传就还是 `<库>/docs`，对现有用法零影响。

## 六、实测记录（2026-11-08）

模拟一个老库结构：脚本放 04_工具 下，文档放 06_治理 下，造一份 70 行的接棒必读。

| 验什么 | 结果 |
|---|---|
| `--docs 06_治理` 真指向 | 报「接棒必读共 70 行，超上限 60」——查到了 |
| 报错里的路径前缀 | 跟着变成「06_治理/待办台账.md」，不会误导成 `docs/` |
| `--docs` 指向不存在的目录 | `[ERROR] --docs 指的目录不存在：<绝对路径>`，退出码 2 |
| `-q` | 只留 ERROR，一行 |
| 不传 `--docs` | 与改动前完全一致，本库 `doc_lint` 照样通过 |
