# 验收

> **这份技能只当目录**：什么时候用、按什么顺序干、去哪查判据。判据条文与具体命令一律不在这里。
> 文中 `docs/…` 都指**当前项目库**的 docs。项目里没有这几份文件，就说明它不是字幕库——先问，别硬套。

## 什么时候用

执行方交回 findings 或判定表之后，要判「这批能不能落」时。**验收是正式一步，不当落地的尾巴**——它有自己的判据和结论，不是落地跑完顺手看一眼。

## 我吃什么、吐什么

- 吃：成品 + 改动清单 + `定档.md`
- 吐：放行 / 打回 + 各项数值 + 责任归属（成品错 / 清单错 / 工具错 / 底线错）

## 按什么顺序

1. **先跑复算**，拿到数：声明多少、在位多少、多改多少、跳过多少。
2. **逐条判红**。三种可能：真错（要改）、时序问题（清单拿改前的文件生成，重跑就没了）、工具误报（判据写歪了）。**分不清就别放行。**
3. **报红四分**：成品错 / 清单错 / 工具错 / 底线错。这四类的修法完全不同，混在一起会改错地方。
4. **有 ✗ 就是打回**，不许「差不多放行」。
5. **给结论**：放行或打回 + 每个数 + 是谁的问题。

## 我得自己记住的三条

1. **有 ✗ 就退出码 1，不许交付**。这条不是建议，是硬约束。
2. **报红四分**——分不清是谁的错就急着改，通常改错地方，把好的改坏。
3. **跳过不报错是安全设计，但大量跳过要停下查**。多半是清单拿改前文件生成的，锚点全失配了。
