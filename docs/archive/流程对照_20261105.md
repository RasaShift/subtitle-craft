# 流程对照：原流程 vs 当前（2026-11-05）

> 一次性报告，归档用。会话里给的是摘要，这里存全表与依据（文件:行号）。
> **原流程** = `日常杂活/05_参考资料/2_给AI看/标准工序规范_20261025.md`（三层 + 格式线 + 八步 + 22 项验收 + 7.1 句群 + 7.7 缺源降级）。
> **当前** = 本库三道工序 + 12 件工具 + 四份常驻文档。

## 六、要拍板的四件事（附推荐）

1. **补行放哪**：扩 `land_verify`，还是新立一件「结构改动」工具？
   推荐**新立**。补行要重编号、重排时间码、校验结构，与「只换字符串」是两种活；扩进去会破坏它现在最硬的那条保证（行数不变）。
2. **错位怎么处理**：沿用老库 `groups.json` 声明，还是让分诊只标「疑似错位」交人整段重写？
   推荐**沿用声明**。老库已在多集验过；靠人手改容易只改半句，V21 那条检查就是为这个加的。
3. **验收搬多少**：照搬 `check_all` 22 项，还是自定 6–8 项？
   推荐**自定**。22 项里 K / C 两组绑剧（术语表同步、NB 结构），通用层用不上；留「条数 / 行数 / 结构 / 声明到位 / 多改 0 / BOM / 引用已声明」这一组即可。
4. **外部模型抽查**：保留成固定环节，还是改成「判据改动时」触发？
   推荐**改成条件触发**。每 5 集固定抽一次的成本高，且实测与定档重叠 17 条、9 条只对上 1 条（`buddy-workflow` 成本节）。
