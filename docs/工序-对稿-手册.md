## 本手册用到的脚本 vs 本库

> 手册里的步骤是从第一个剧库带过来的，那时用下面这些脚本。本库有的已在 `tools/`，没有的逐个交代下落：剧专用的**不搬**（名字带集号或剧型，搬进来就违反红线）；通用的**写清对应哪个本库工具**，确实没有的直说「本库没有」，**别留裸引用**。**照手册跑之前先看这张表。**

| 手册里写的 | 本库 |
|---|---|
| `align_triage.py`（把差异折成必看 / 纯措辞） | ⚠️ 大体由 `tools/triage_diff.py` 做：`python tools/triage_diff.py <配对表.tsv> [--term <词表.tsv>] [--offset <错位区间.tsv>] [--tsv <输出.tsv>]`。**但它不扫判定表**——重跑会把判过的行再列一遍，「还剩多少」得人工算差集 |

| `_ctx_209.py`（单集上下文抽取） | ❌ 单集专用，不搬 |

# 字幕对轨判断（subtitle-align）

> **举证与实测数据**：`docs/工序-对稿-实证.md`——每条规矩为什么长这样、阈值从哪来、哪次踩了什么后果。**改规矩前先读它**；它是规矩的依据，不是规矩本身。

把对轨分诊表里的每一条判成「改」或「不改」，改的写成 findings，交回一份简报。

本 skill 只管**第三层工序**——拿官方英文逐条比。第一层查表归 `subtitle-clean`；逐句通读归审稿（那是另一道工序，可选），不归这道管。

## 被触发时先说一句

**凡按本 skill 干活，回复第一行必须写声明**——哪怕只是照派活单做事、没觉得自己在用一个 skill。派活单里出现本 skill 名字就等同于被触发。

- 走注册表正常加载：`已加载 skill：subtitle-align（注册表）`
- 只被 `@skill:` 附着、或人工读了本文件而没进注册表：`已按路径读取 SKILL.md：subtitle-align（未进注册表）`

派活单点名本 skill 就**先调 `Skill` 工具**，再谈读哪些文件。把「读到了判据文件」当成「走了 skill」，触发信号就丢了（2026-10-27 S08 教训）。

用户只是提到字幕、没要求判读，不要触发。

## 干什么

| | 路径 |
|---|---|
| 输入 ① | `02_工作区/align/<批次>/<季>_必看.tsv`（实质差异 + 错位，**必须逐条判**） |
| 输入 ② | `02_工作区/align/<批次>/<季>_我们缺.tsv`（官方有整句、我方没有，**逐条判**） |
| 输入 ③ | `02_工作区/align/<批次>/<季>_纯措辞.tsv`（**不逐条**，抽 20 条看有无系统性遗漏） |
| 输出 ① | `02_工作区/<季>/findings/<季号>x<集号>.json`（**只追加**） |
| 输出 ② | `02_工作区/交接/<任务名>对轨/判定_<季>.tsv`（逐条判定，**位置不能改**） |
| 简报 | `02_工作区/交接/<任务名>/` |

> 上面这些路径是第一个剧库的形态，**本库没有剧库目录**：实际路径一律按派活单，这张表给的是「谁放哪」的关系不是绝对路径。

> 输出 ② 的路径是硬要求，但**理由和手册原来写的不同**：老库的 `align_triage.py` 会自动扫 `交接/*对轨/判定_*.tsv` 把判过的行归「已判过」，**本库 `triage_diff.py` 没有这个功能**——位置写对也不认，重跑照样整批重新列进必看。位置仍要守，是因为统筹方要按位置找判定表、算「还剩多少」；**差集在本库只能人工算**。

## 先确认这批的边界

开工前核三件事，**数字不符先停下报统筹方，别自己开始判**：

1. 哪一季（或哪部剧）、哪几集
2. 必看多少行、我们缺多少行 —— 与 tsv 实际行数核对
3. 本批特有禁区

分诊表是脚本按当前工具版本生成的，派活单是人提前写的。**工具改过之后派活单常常过期**（2026-10-30 修配对逻辑，八季必看从 470 掉到 136）。以现场 tsv 为准。

## 分诊表长什么样，注意三处坑

**本库的列不是老库那 8 列**（`集 时间 档位 行号 我们的英文 官方英文 触发原因 簇` 本库没有，别照着找）。`tools/triage_diff.py` 实际输出 10 列：

`中文条号 中文开始 中文文本 参照文本 建议代号 规则 理由 证据 需人判 stage`

配对表（`align_bilingual.py` 的产物）是另一张 10 列：`中文条号 中文开始 中文结束 中文文本 英文条号 英文开始 英文结束 英文文本 置信度 标记`。两张表都以**中文条号**为键，没有「集」列——单集一跑，集号来自派活单。

1. **表里有中文文本，但仍然要回源字幕核。** 写 findings 的 `cn` 必须与源字幕**逐字一致**（含空格与全角标点），配对表里的中文是搬运来的，被清洗过就悄悄变了；**取行号、取英文以源字幕为准**（正传 `<源字幕目录>/定稿基线/`，两剧各自 `原始/`），换一份行号就对不上。
   - **判「这条到底缺不缺」→ 以成品为准**（`03_成品/`）。成品才是观众看的，而且补行只落在成品、不回写源字幕，两者会差几行。按源字幕行号看不到中文时，**必须再去成品核这一时刻屏幕上到底有没有中文**——2026-10-30 就因为这个，把 50 条成品里明明有字幕的判成了「缺」，用户逐条听片才发现。
2. **集号格式不同。** 表里没有集号，`findings` 的 `episode` 必须是 `"01x02"` 这种字符串，**不是数字**。转换写错会被静默丢弃。
3. **一对多要合起来看。** 本库是「中文当骨架、英文挂 0/1 条」：一行一条中文，**不存在老库那种 `21|23|24` 合写行号**。反过来，多条中文对同一句英文时，配对表会出现多行、英文列内容重复——要合起来判断中文有没有覆盖官方那句，别当成「重复条目」删掉。

## 判读顺序（钉死，不能颠倒）

**第一步：只看我们自己，不打开官方。**
我们这行的英文有没有截断、拼写错、语法不成立？中文和英文是不是一个意思？

有 → 按**最小改正**修，与官方这一行写什么无关。

**第二步：再比官方差异。**
两边都通顺、中文跟我们的英文自洽，只是说法不同 → **判不改**，记「听写分歧」进判定表，**不进 findings**。

★ 官方在这一行听错了，**不构成「我们没问题」的理由**，两件事独立。别让官方的错替我们免罪。这条纪律的完整版与反例在 `docs/判断纪律.md` 第 5 条第 9 款。

## 硬约束

- **行号一律锚源字幕**，不锚成品。成品有补行会偏移，patch 的四重定位也只认源字幕。
- findings **只往数组里追加**。不改已有条目、不删、不重建文件。
- 每条 `cn` 必须与源字幕**逐字一致**（含全角标点与空格）。抄错会被 apply 的四重定位拒掉。
- `evidence` 必填，只写能当场复算的：官方 SRT 原文片段、术语表 canon 值、全季出现次数。
- 判「不改」的也要留记录，别只交「改」的。
- **不跑 `merge` / `apply` / `verify`**（本库对应 `python tools/land_verify.py apply` / `verify`；并表本库没有工具，靠统筹方人工）。那是统筹方的活。
- **不改别人的库（`日常杂活` / `是大臣系列`）里的文档，尤其台账。** 有发现写简报「顺带发现」一节。
- 判据有问题写简报，**别自己放宽**（判据只能由不干活的人定）。

## 三条最容易判错的地方

1. **整集时间轴偏移不是内容问题。** 看到「整集几百条错位」，先看偏移表划了没有；没划的时候那些错位全是假的，一条真错都没有。**本库没有整集偏移自动估算**（`srt_compare.py` 那件不在本库），偏移表靠人划三列（起条号 / 止条号 / 理由）喂给 `triage_diff.py --offset`，参数见本文「本手册用到的脚本 vs 本库」一节。
2. **错位档不许整档跳过。** 旧口径「整档判不改、每集抽 5 行」已废弃，会把行内硬伤漏掉，现在一律按簇抽查。**「簇」怎么划、每簇抽几条，本库没写**（原判据摘要被裁时漏登，属已知缺口，只剩结论在 `docs/工序-对稿-反例与黑名单.md` 第 27 条）——别自己另编一套，拿不准就整档逐条读。
3. **背景歌词、SDH 音效、片头落款都不是漏译。** 净化没做好时它们会整批落进「我们缺」，见 `docs/工序-对稿.md` 第 4 节「不算 T1 的」。

## 三条规则边界的查法（2026-11-08 加）

边界本身写在 `docs/工序-对稿.md` 第 4 节（`DR0` / `DR1` / `DR5` 各带一句「不判什么」）。这里只写**怎么当场把界划出来**，三件都不用新工具：

1. **先看分布，再逐条判**（`DR5`）。候选表一出来先数 `rule` 列，别从第一行读起：
   ```bash
   python -c "import csv,collections,sys;c=collections.Counter(r['rule'] for r in csv.DictReader(open(sys.argv[1],encoding='utf-8'),delimiter='\t'));print(c.most_common())" X.triage.tsv
   ```
   某一条占九成 → 先怀疑匹配键（普通名词进了词表 / 拿错剧的表），别用人判硬扛。剧库 110 条候选里 105 条是 `DR5`，判了两天、只采纳 8 条。
2. **`DR0` 侧空先数、不先判**：按条号上溯，找最近一条英文非空的，看它英文里有没有 `\N`。**多行占比 ≥95% → 这批是断行结构，整类不判**；<80% 才逐条看。本库没有现成工具，20 行脚本或先数 200 条估比例都行——**估比判便宜一个量级**。
3. **量级错靠第二份译本，不靠机器也不靠推**：`DR1` 不查量级，另拿一份独立中译做「我中 vs 他中」逐条比，不一致再回看「我英 + 他英」。**参照是证据不是判决**——它自己也错（剧库 `YPM_S02E01#29` 参照与英文轨都写 30 万，中文写 3 万）。英文 `?` 缺位时**禁止按首位补 1**，一律查参照，参照也没有才落 `T?`。

## 撞到现象先搜经验卡

改了没生效 ／ 替换没匹配上 ／ 数字离谱 ／ 脚本报红 → 先 `grep` 判定记录与对稿实证，别从零试错。踩了新坑当场往 `台账` 记一行。

## 交回什么

格式与「三件缺一不算交回」的规矩见 `docs/判断纪律.md` 第 4 节。
**findings 的字段格式（`layer` / `type` / `severity` / `tc` / `en_after`、补行走 `inserts`）按 `docs/findings写法.md` 写**——本 skill 只判该不该改，不定义文件结构；写错会被 merge 静默丢弃。

对轨这条工序额外的两件事：

- **判定表要能反查**：每行写清 集／行号／档位／结论（改/不改/疑问）／一句话理由。统筹方要拿它算「还剩多少没判」。
- **原有列必须原样抄，不许重编号**（2026-10-31 L3 实测）：最稳的做法是把输入表**原样复制**成判定表，只追加「结论」「理由」两列，不重排、不改原有列。实测踩过——执行方把 38 行编成「集 1–38」，而续一只有 10 集，归位后老库的 `align_triage.py`（**本库没有这个自动归并**）会把判过的行认到错的集，**反而制造假信号**（比不判更糟）。本库虽然没有自动归并，规矩照旧：重编号会让下一个看表的人对不上原表。
- **简报第一节必须是大白话**：这批改了几条、哪几条拿不准、用户要不要亲自看。判了几条、采纳几条、跑了什么自检放在后面。

## 完成标志

`必看.tsv` 和 `我们缺.tsv` 里**每一行都有人判过**，包括判「不改」的。纯措辞抽看 20 条，看有没有成片漏译或成片错译。

某集实质差异判完只采纳 0–1 条 → 这集已经做透，不用再加大投入。
