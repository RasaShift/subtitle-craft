# 字幕判断 · 公共总则（只此一份，各 skill 引用不复制）

> **举证与实测数据**：**本文各条自带**——集号、事故经过、后果都写在条目里（如 #80 那批 6 条红线、续一 E01 那 17 行歌词），没有单独的实证文件。
> **改规矩前先读这些标记**；它们是规矩的依据，不是规矩本身。含真实集号，只留本地。

> 读者：执行判断类工序的 AI　｜　性质：「怎么判断/怎么交回」的通用纪律
> 本批流程细节见当批派活单；脚本怎么跑见本库 `tools/` 下各脚本的 `--help`。

## 1. 触发声明（按 skill 干活时回复第一行）

- 走注册表正常加载：`已加载 skill：<名字>（注册表）`
- 只被 `@skill:` 附着或人工读了 SKILL.md：`已按路径读取 SKILL.md：<名字>（未进注册表）`
- 派活单点名 skill 就**先调 `Skill` 工具**，再谈读哪些文件（2026-10-27 S08 教训：把「读到判据文件」当成「走了 skill」，触发信号丢了）。

## 2. 冲突优先级（2026-10-27 定）

```
当批派活单  >  对应 SKILL.md  >  该工序的判据来源
```

第三项写该工序的判据来源：清稿 / 查表 → `docs/工序-清稿-规则清单.md`；对稿 → `docs/工序-对稿.md`；审稿 → `docs/工序-审稿-判据.md`（编号真身是同目录的 `工序-审稿-判据表.tsv`）。

派活单是本批的即时指令，写它的人知道这一批要什么；技能是通用模板，不知道批次细节。
冲突按派活单办，**必须在简报里写一行「与 SKILL.md 第 X 条冲突，我按派活单处理」**——默默按一条执行不算处理完（2026-10-27 S08 就漏了这行上报，所以它是硬要求，不是提醒）。
分清**读和改**：「不许改某目录」≠「不许读」；派活单说「只读下面路径」才是禁止读，两种措辞别混。

## 3. 证据纪律（evidence）

1. **必填，不许空**。`accept.py` 第 6 项查空值。
2. **只写能当场复算的东西**——官方 SRT 原文片段、术语表 canon 值、全季出现次数。这三样拿源字幕就能验。
3. **不要引用「另一条已改过的 findings」当依据**（2026-10-26 S04 教训：示例引用了还没落地的改动，写出拿源文验不出的依据）。
4. 引用的英文片段会被 `accept.py` 第 7 项拿去官方 SRT 里比对——**找不到的片段疑似编造依据，会报红**。引号包住、长度 ≥ 8 的英文原文才参与比对。
5. **引英文前先确认它来自哪条轨**。ASS 里内嵌的英文是**我们转写/合并的轨**，与 `01_源字幕/官方英文SRT/` 是两份东西，写法常有出入（`Ramos` vs `Vamos`、`wre` vs `we're`、`sever` vs `severe`）。#80 那批 6 条红线里 5 条 evidence 明写「官方 SRT 证实拼写错误」，实际引的是我们自己的英文轨，官方恰恰是标准写法。要引英文轨就写明「英文轨作…」，要引官方就照官方原文抄。
6. **判「要不要改」前先过两问**（2026-11-03 立，来自 #116 判错）：① 会不会挤占别人的位置？② **观众会不会认错这是什么？** 第二条更容易漏、也更致命。反例：续一 E01 那 17 行歌词，只判了「无对白穿插、不挤占」就收工，实际是 Default 样式（48 号大白字贴底）、和角色念白同一个长相，观众看到第 43 分钟只会以为「主角在说话」——用户看实片说「看着非常怪」，翻案重做。**样式类、定位类改动必须过第二问。**

## 4. 交回三件（缺一件不算交回）

1. **数据**：写进既定文件（findings 只追加、判定表按路径），不新建目录结构
2. **简报**：存 `02_工作区/交接/<任务名>/`，**第一节必须是大白话**：
   - 这批干了什么（日常话，不许出现字段名和行号）
   - 有没有拿不准、需要人拍板的（几条、分别是什么事）
   - 用户要不要亲自看（不看就写"不用看"）
   - 后面才是给统筹方的数表（处理条数/改/不改/新增/补行）、疑问表、格式问题
3. **自检结果**：跑了哪些自检命令、过没过

## 5. 禁区（执行方通用）

1. 不跑 `merge` / `apply` / `verify`——落地由统筹方验收后做。
2. 不改已有 findings，只许追加。
3. 不改判据。判据有问题写进简报，别自己放宽（**判据只能由不干活的人定**）。
4. 不碰其他季/其他剧的文件。
5. 不新建统计工具；缺工具在简报里说要什么。
6. 不改别人的库（`日常杂活` / `是大臣系列`）里的文档（尤其台账）。发现写简报「顺带发现」节，由统筹方决定记不记。
7. **改的人不验，验的人不改**：写 findings 的不做最终验收，验收的不写 findings。
8. **证据源只有三样，音频是例外通道**（#85 → #88）：默认只用「官方 SRT + 术语表 canon + 源字幕中文」。
   **默认不抽音频、不跑 ASR、不转写**。只有遇到**两难**——两边都通顺、没有仲裁者、且判错代价高——才允许抽，
   且**每批 ≤3 条**，并且：①先报统筹方同意，别自己开；②evidence 里写明「音频：<听清的原文>」，
   不许伪装成官方 SRT 有这句；③简报里单独列这几条。用户 2026-10-27 明确给了这个口子（原话：只允许在两难时听）。
9. **官方 SRT 不是权威**（2026-10-27 #87，用户听片实证）：官方 SRT 只是**另一份听写稿**，和我们一样会错。
   已实测四类错：漏句（01x01 L539）、截断（L714 `Are you...`）、简化（L761 只到 `See you.`）、
   **听错**（实测：把 `Not tonight` 听成 `Nine tonight`，见台账 #87）。
   **以上英文引例全部是脱敏时换上去的自造句，不是剧目原文**——原句已在 2026-11-07 脱敏时替换。
   所以对轨层（`layer: align`）只认两类**可内部判定**的错：
   - **技术性缺陷**：句子截断、拼写错、语法不成立、明显串行 → 按**最小改正**修，不凭语境补内容；
   - **内部矛盾**：我们英文与中文说法不一致、或与术语表 canon 冲突 → 取与上下文通顺的一方。

   **判定顺序钉死（2026-10-28 立；回归基线实测漏改）——两步，不能颠倒：**

   1. **先只看我们自己的中英，不打开官方**：有没有截断、拼写错、语法不成立、中英互相矛盾？
      有 → 按最小改正修，**与官方这一行写什么无关**。
   2. **再比官方差异**：两边都通顺的**内容分歧**（中文跟我们的英文自洽）→ **判不改**，
      记「听写分歧」进判定表，**不进 findings**。

   ★ **官方在这一行听错了，不构成「我们这行没问题」的理由**——两件事互相独立。
   实测反例（2026-10-28）：有一行官方确实听错，判读方据此整行判「不改」，连带放过了
   我们自己英文里的语法错（少一个冠词）。正确做法是先走第一步自查：我们自己有错就改，
   与官方听没听错无关。**先自查，再比对，别让官方的错替我们免罪。**

   > **写反例的铁律（2026-10-28 踩过两次）**：本文件里的例子**不许点名回归集里的具体行
   > （集号+行号），也不许写出该行的结论**。首基线就栽在这上面——反例点了某一行的号并写了
   > 「正确结论是……」，而那行正是当轮考题，判读方照抄即对，那次成绩整批作废重考。
   > 更荒唐的是修这个漏洞时，那条「铁律」自己又点了号，于是又泄一次。
   > **例子只讲情形，不讲哪一行、不讲该怎么判。写完自己按这两条自查一遍。**

   改成官方版等于赌官方对；真需要定音就走第 8 条的音频例外通道，别猜。
10. **改已有文件必须保持它原本的换行符**（2026-10-27 S01E02 实测）：往 CRLF 的 findings JSON 追加一条，
   整文件被写成 LF → `git diff` 从 4 行涨到 72 行，真实改动被淹，事后审不出改了什么。
   写之前先读 bytes 数 `\r\n`，写完按原样落盘；新文件不带此约束。

## 6. 撞现象先搜经验卡

改了没反应 / 替换没匹配上 / 数字离谱 / 报错看不懂 → 先 `grep` 判定记录与对应实证，别从零试错。踩了新坑当场往 `台账` 记一行。

## 7. 停下报统筹的三种情况

1. 数量对不上（派活单写 N 行、实际 M 行）——以现场数据为准，但先停下报数再动手
2. 同一处有两种读法都成立——进简报疑问表，别自选
3. 发现判据本身有问题——写简报，不改判据
