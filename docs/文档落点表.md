# 文档落点表

> **写任何文档之前先查这张表**，别现场判断「差不多放这儿」。
> **进本库只有三种**：别人照着做需要的（判据 / 命令 / 模板）、别人想改这套方法需要的（实证回答「为什么定这条」）、决策记录。**检验法一句话：换个人、换部剧，这条还成立吗？** 一次性的实验数据、具体集的表现、私人工作习惯、半成品一律不进——脏活放剧库 `03_工作区`，那边才是试验田，本库只收提炼后的结论。
> 上限怎么定见下面「上限怎么定」一节——**先判它是哪种文档，再决定满了怎么办**，别一律拆。

## 上限怎么定（2026-11-06）

上限不是「别太长」，是「**长到这儿说明出问题了**」。但「出什么问题」三类文档不一样，混着用只会一律拆——而现在拆得太多，正是这么来的：

| 生长方式 | 怎么认 | 满了怎么办 |
|---|---|---|
| **稳定型** | 讲「现在是什么状态」，不随工作量增长：流程总图、命名准则、落点表、接棒必读、做法 | **删或搬，不许拆**——变长就是塞了不该塞的 |
| **只增型** | 随工作线性增长、长的是必要信息：规则清单、判据、判定记录 | 不设总量，设单卷阈值（判定记录已用：满 150 行开新卷） |
| **收敛型** | 有出清机制、自己会缩：台账（做完删行 → archive） | 简表宽上限（60）；**超了往详情搬，不是删条目** |

判法一句话：**先问「它只增不减吗」**——是，就是账本，别套页数、只控单卷；不是，再看它有没有出清机制。

**台账是「一份功能、两份文件」**（2026-11-07 立）：简表管「现在干什么」，收敛型、有上限；详情管「为什么、怎么干」，随条目数长、不设限。**哪一份长错了，是东西放错了份，不是文档太长**——简表超 60 往详情搬，别删条目；做完一条两边同时删，别再往简表里堆历史。

还有一条：**上限数字必须有出处**。写个数不写理由，等于给下一棒埋一个「不知道为什么但必须遵守」的约束，而这种约束最后一定被绕过或被用来凑字数。

**`examples/新剧接入.md` 2026-11-07 从 150 改到 210，理由**：它是 12 步全流程（0 盘家底 / 1 建目录 / 2 造底本 / 3 体检 / 4 对齐 / 5 攒词表 / 6 清稿文件层 / 7 清稿文本层 / 8 对稿 / 9 定档 / 10 审稿 / 11 验收），每步要带命令、判据指针、常见坑，实测 **209 行**。原 150 是拍的、没写出处；压回 150 只能靠删命令或删判据指针，那是拿可用性换行数。拆成两份也不行——「从零到能判」是连续的一条线，断成两截就要多跳一次文件。**210 = 实测 209 + 1 行余量。2026-11-08 提到 220**：补了「落地」一段——对着 `docs/流程总图.md` 第 8 步核的时候发现**本文件里根本没有这一步**（审稿产出清单、验收直接拿成品验，中间没人把清单写回文件），那是漏写不是新增，正落在它自己说的「加了新步骤就重估」那条上。现在 219 行。**2026-11-09 提到 240**：加 `05_参考资料` 一行后实测 240；**它本来就 239 行、早过了 220 没人报**——该文件不在 `doc_lint` 范围（它只查 `docs/` 和根 README），和 `#46` 是同一类盲区。240 就是实测数，不留余量，下次超了按同一规矩重估。

## 四条硬规矩

1. **一份内容只有一个真身**，别处只留指针（例：上游那两份决策文档只在 README 里指路径，不复制）。
2. **超上限先拆**，不靠「这次特殊」。拆出去的部分进 `docs/` 同级或各剧库工作区。
   **但账本不按这条办**（2026-11-06）：只增不减的账本（判定记录）满了不拆内容，开新卷——拆内容等于砍记忆。判法一句话：**它是「讲现在是什么状态」还是「记发生过什么」**，前者设总量上限，后者只控单卷长度。
3. **不写「作者」**，写 `最近修改：<日期>（改了什么）`。名字是会漂的，日期和原因不会。
4. **HTML 只是呈现层，不是真身**（2026-11-06 立）：要出就由对应的 Markdown 重新生成单页，改内容先改源件。**本库不设 HTML 存放目录**（2026-11-09 删掉 `docs/展示/`：一份单页要跟着源件同步，长期只会变成第二份过期的真身）。**出不出由赵哥点头，不自己主动做**——他觉得某个形态好看，不等于他愿意每次都付这份成本。
