00一句话

一份字幕从进来到能交，走十步：三步备料、清稿两道、对稿一道、定档一道、审稿一道（可选）、落地写回、验收收口。
审稿做不做、读多深，由委托人定——这是全流程唯一一个岔路口，也是唯一可以整道跳过的工序。

0体检 1对齐 2攒词表 3清稿·文件层 4清稿·文本层 5对稿 6定档 7审稿 8落地 9验收

验收是第四道工序，有自己的一条命令（tools/accept.py）和判据文档，不是落地的附注。

02四条硬顺序，各有各的理由

左边是理由，右边是违反了会怎样。四条都不是习惯，是实测出来的。

1文件层 → 文本层

文件层重写整行但不动文本，跑完文本锚点仍有效。

违反了

反过来做，样式器还得把文本原样保住再对一遍账。

2清稿 → 对稿

脏输入（粘连、贴字）会让对稿假红成倍。

违反了

假信号淹掉真问题，人力全耗在噪声上。

3对稿 → 定档 → 审稿

定档要读干净文本（清稿后）、要一个全量负证据（对稿候选数）；审稿要跳过「中英对照本身错位」的那几行，还要先按词表把术语定稿。

违反了

清稿前抽样，会把「译名不统一」误读成「翻译差」，白读一批；读错位的行必然误判。

4清稿先落 → 其余并成一张再落

对稿要吃干净输入，所以清稿必须单独先落盘；但落盘之后不能再回头改清稿。

违反了

后一行静默覆盖前一行，复算仍全绿（已实测，land_verify 现在直接拒，退出码 2）。

「清稿一次、其余一次」是硬要求，不是习惯。清稿单独落盘后，对稿定案的改动与审稿清单必须并成一张、落一次——落两次之间没有复算，错了看不出来；同一条在清单里只许出现一行。

还有一条会悄悄过期：对稿只读配对表、不读字幕。清稿改过中文后，表里那列就是旧值，所以清稿落地后必须重建一次配对表再跑对稿。

03现在断在哪、哪里会悄悄过期

两处。前一条靠流程硬约束，后一条是工具缺口。（错位区间与 stage 已在 11-06 补上）

配对表会过期，没人会收到提醒静默

对稿只读配对表、不读字幕（脚本只认「中文条号 / 中文文本 / 英文文本」三列）。清稿改过中文后，表里那列就是旧值，对稿照着旧文本出候选 → 落地锚点失配。

做法：清稿落地后重建一次配对表再跑对稿。不做的话验收会以「跳过非 0」暴露，但那已经是白跑一轮。

triage_diff.py:59

关键点核没有预筛工具工具缺

否定词、数字、人名这三类机器挑得出来，现在得人自己翻——「关键点核」这一档的省时优势因此打了折。

台账第 12 条

前两条要改对稿文档，但它现在是 130 / 130 行顶格——加字段之前得先拆，不能硬塞。

04谁触发、谁定案

统筹方

决定这一步跑不跑、什么时候跑。清稿、对稿、定档、审稿都由它触发。

机器

只挑候选、只算数值、只做替换。一句判断都不下——审稿那道机判项为 0。

人

定案。对稿的 T?、定档的档位、审稿的全部条目、词表的译法，都得人过。
