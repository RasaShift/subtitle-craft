# 判定记录（通用库）

> **只写「定了什么 / 为什么 / 什么条件重开」，一条一段话。** 过程在 `.workbuddy/memory/`，待办在 `docs/待办台账.md`，内容放哪查 `docs/文档落点表.md`。
> **格式照 `ADR-FORMAT.md`**（`skills/domain-modeling/`）：一段话讲清背景、决定了什么、为什么，**重开条件写在段末**。不拆「结论 / 理由」两条线——那是把一段话拆成三行，读的人还得拼回去。
> **这份是账本，不是文档**：只增不减。当前卷满 150 行，整卷搬进 `docs/archive/判定记录_YYYYMM.md`，头部留一行指针；**主文件只压一个卷**。不设总量上限——套文档的页数上限只会在某天逼人硬砍记忆。

## 2026-11-09

### 外部技能只装原版，术语表只收出过事的词

全局装 `writing-for-agents` + `diagnosing-bugs`，取上游原版，只改 `description` 指向本库路径，正文一字不动；中译版不装——它 47 处核心术语留英文（`pointer` 18 / `branch` 11 / `leading word` 8），半中半英不比纯英文省力。术语表同理，只收**已被误用或跨库会看错**的词：收一个没出过事的词，就是把它变成必须记住的生词（11-07 自造「薄壳」被当场问过一次，八份技能抬头全改回人话）。**重开**：上游出现用得上的新技能，或某个词被两个库理解成两个意思。

### 术语表只写词义，不抄会过期的状态

词条区不许出现状态词（`下一批`/`目前`/`现在`/`当前`/`还剩`/`暂时`/`最近`），`doc_lint` 的 `check_glossary_state` 查；号段、进度一律指向真身，不写当前值。起因是建表当天从协议抄了一句「下一批从 `#12` 起」，抄的时候对、抄完立刻过期（台账已排到 `#41`）——**术语表里给一条错的规则比不给更糟**，人是来查词义的，不会核号段。同源于「转述丢条件」：副本不知道原件已经变了。**重开**：某个词的定义必须带时间限定（如「旧编号」这种相对说法）时，写清参照点，仍不写绝对号段。

### 跨库编号按来源分家，一个问题只用一个号

`GQ-n` 专给「剧库报本库的问题」，从 `GQ-19` 起；**同一个问题两边沿用同一个号**——剧库报的记 `GQ-n`，本库台账里记它也用 `GQ-n`，不另起号。裸 `#n` 只给本库自己发现的待办，不跨库；`#1`~`#12` 封存不改。起因是裸 `#n` 三套并存且互撞：剧库 `06_治理/待办台账.md:31` 的 `#10` 是「38 集一致性比对」、同目录 `待报通用库.md` 的 `#10` 是「DR 规则」、本库台账 `#12` 是「关键点核预筛」、剧库报来的 `#12` 是「让人看的文档没形态」——**同一符号指四件事**。改旧号不行：剧库有 47 处裸 `#n` 引用，改了全断。「两边各起一个」是随后长出来的同一个病：骨架形态那条一度挂三个号（剧库 `#12`、本库 `#42`、该用的 `GQ-19`），搜哪个都不全。**重开**：出现必须合并两套编号的硬需求（如跨库总索引）时另立映射表，仍不改编号本身。

### 台账按「卡在谁身上」分节

分节只用一个维度——等我动手 / 等协作方 / 等外部 / 等你拍板；一条同时等两样的，归到**先动的那一方**；「现在手上」这类摘要不占节，压成顶部一句。这套搬到任何库都成立。起因是当天先按内容切过四节（本库要改的 / 等真实数据验的 / 等外部条件的 / 等场景触发的），**四节混了四个维度**（谁动手 / 到哪一步 / 阻塞原因 / 触发方式），跟 11-08 废掉「三档」是同一个病——三把尺子。按内容分还有第二个毛病：换库就失效，剧库没有「本库要改的」这种类。**重开**：阻塞方超过四方（如引入第三方验收）时加第五方，仍不改维度。

### 扫除三项不做

① **不装 20KB 提交钩子**——9 个存量文件超标（判定记录归档 124KB、`selftest.py` 81KB、审稿手册 50KB、`doc_lint.py` 37KB），全是该大的账本和工具本体，本库按文件类型管行数（`LIMITS`），统一字节阈值不适用。② **不合并「30 件 / 25 件」三处写死**——`check_counts` 已拿三处跟 `tools/*.py` 实际数对，写错报 ERROR；收成一处反而让对外文档没具体数。③ **不压 README、不补 AGENTS.md**——README 109 行是对外说明，agent 入口是接棒必读（60 行纯目录），职责已覆盖。三条共同点：拿代码项目的通用做法套文档库，而本库大的是账本、入口也已有更严的形式。**重开**：本库开始产出真代码（不只是单文件脚本）时，第①条重判。

### 三条建议只收一条半：拒「靠人一眼看见」

外部建议吸收三条，只收「结构上犯不了」和「拿真错撞」，**拒「让人一眼看见」那档**——它跟 `docs/做法.md` 三级阶梯表里 ✗ 行（「要靠人读才算生效的东西，等于没有」）直接冲突。三条里一条已被 `做法.md:33` 的判据覆盖（规则配拦截），一条与本库既有判断打架，只有「结构上犯不了」是真缺：本库最强只到「钩子拦截」，那是犯了再拦，没有「根本写不出来」。**重开**：出现「结构上做不到、自动检查也做不到、但人一眼能看出来」的场景。

### 拿真错撞：正例必须来自真错

`agent-craft` 第 6 步在「验双向」后面补一句——该命中的那一半，**正例必须是历史上真犯过的错，不许自己编**；把真错原样放回去，检查不红就说明这条检查是摆设。原文只防**误伤**（造反例看会不会乱报），缺的是**空转**（检查写了、看着全绿，其实从没真跑过）。自己编的正例和检查逻辑同源，自己验自己必然过。落地第一分钟就撞出活标本：`doc_lint` 的件数核对不认接棒必读的表格写法，改错退出码仍为 0。**边界**：`agent-craft` 是全局软链，改一次四个库同时生效，属跨库改动，要单独拍板。**重开**：出现「正例没法从历史里取」的判据（全新领域、无真错可放）时，放宽成「用最接近的真实失败」。

### 骨架目录定两段

顶层目录分两段——`NN_中文名` 给人翻（`01_源字幕` / `05_参考资料`），`docs / tools / skills / examples` 给命令敲（英文、不编号）。判法一句话：**这名字会不会出现在命令行里**。落实为 `doc_lint.check_top_dirs`（WARN 级，不查编号连续性）。根子不是语言，是**编号跨两段连续数**：`01/02/03` 是中文数据层，`tools/` 占着第 4 格却不编号，于是下一个数据目录只能叫 05——定成两段后，跳号有了出处。全英文被否：要把流程总图、两份手册、新剧接入里 124 处 `02_工作区` 一起改，否则新库第一天就带死链；全中文被否：4 份技能正文 28 处 `docs/` 是全局软链。编号用 05 不用 04，因为判词与协议都写 05，为整齐改号要付一次跨库通知。**重开**：出现第三种合法顶层目录（既不是数据也不是工具）。

### 起点素材能找样本，不能验通用

《嗜血法医》是本库判据的起点，拿它**找样本**可以，拿它**验「规则通不通用」不算数**——只能证明「不砸起点」，因为判据都是从这部剧的经验里长出来的，等于自己验自己。已有实证：法医源库整库 UTF-16、本库 UTF-8，「第一部剧不可能撞到这个」，盲区是结构性的不是运气。通用件维持「大臣先、法医后验」的顺序；**找样本与验通用是两条线**，找样本用哪部都行（起点剧里若有，反说明上次扫描口径不全）。**重开**：出现第三部剧时重估；或某条判据明确只服务单一剧。

### 判据要事前可判

规则清单 MF8 的第二条原写「同刻有署名行被删」，并注「旧库 49 条 100% 满足该交集」。实测只有 **41/49（83.7%）**，容差放到 2 秒也不变——因为那是**事后**视角：人删署名行时顺手把底纹条一起删了，工具运行时看不到「将被删」。改成「同一起始时间还有别的非空 Dialogue 行」后 49/49 成立、0 条孤单。判据多半从人工校对报告里提炼，而报告写的是「人当时怎么做的」，含未来信息；工具只看当前文件状态。**凡从报告搬一条判据，先问：这条只依赖当前文件吗？** **重开**：出现必须看上下文才能判的规则（如靠前后条判断的折行）——那时改的是工具接口，不是把判据缩水成能算的样子。

### 改动只认触发点、不认引用面

改了 A 处，B/C/D 还说着旧话——这类问题不靠记性防，靠提交前 `grep` 四类：① 旧计数（工具数 / 行数）② 刚废掉的规矩原话（如「两套并存」）③ 让你改的那句原文（确认它还在）④ `VERSION`。剧库一天内报了四处同形：协议 §5 与 §6.1 定了相反的编号规矩、§6.7 指挥它改一句早就改完的话、§8 预告扫一个它没有的目录、`doc_lint` 加 35 行而三个版本 `VERSION` 同号。**与「跨文件副本漂移」不合并**：那条判法是副本只留一份，这条是同一文件内部加代码元数据，判法是扫引用面。第 4 类单列，因为版本号不在文档里，一忘就得让下游把 30 个工具全 `md5` 一遍。**重开**：出现第五种关联面——既不是文本、也不在 git 里（环境变量、外部系统状态）。

### 检查器的「一致」必须双向

两边各有状态的检查器，必须同时报 `A − B` 和 `B − A`。只查一个方向还输出「全部一致」的，比没有检查器更危险——实测剧库那版 `recon.py` 报「全部一致，不用读协议」，而当时两条新条目正挂在待报、协议 §5 里根本没有：它只做了「§5 的号待报里有没有交代」，新报的一律看不见。这与「检查说通过、实际没查」同病，只是长在检查器自己身上。**附带一条归属**：两边都要跑的检查器，会写文件的拷副本、只读的直调原件，真身放 `tools/`——只读件拷副本除了制造版本漂移没有好处。**重开**：改成双向后仍漏（如正文提到的编号被当成条目），说明问题在编号的存放位置。

### 技能不触发：规矩在记忆里也不够

技能能不能被拉起，只看 `description` 与首句的匹配。记忆里那句「开工先加载」是背景偏好，读到了不等于会执行——2026-11-09 实测：用户记忆每轮无条件注入，15:05 接棒那轮照样一次没读 `SKILL.md`。**记忆能被读到，但不会被当成「现在去执行」**；`description` 直接参与技能匹配，是唯一自动生效的入口。这解释了为什么过去几个月「写了规矩还是不生效」：一直在补文案，没补入口。同一天两轮对照：补了触发词之后，新会话只说「接棒」就按 `agent-craft` → 当时还存在的 `buddy-workflow`（同日已删，理由见 `docs/讨论-文档内耗_20261109.md`）拉起来了。**连带修**：「技能不触发也没误事」只对 4 份字幕技能成立（它们只是索引页，判据正文在 `docs/工序-*.md`），被扩成「所有技能」就成了免罪符，已在接棒必读收窄。**重开**：出现「`description` 已含场景词、仍不触发」的实例——那问题在注册 / 发现机制，不在文案。

### 子 Agent 只收「结论 + 出处」

派子 Agent 解决的是**主上下文容量**，不是事实可信度，也不是省积分（它读的原文照样计费，还多一层总结开销）。三条同时成立才派：要读的比要交的多一个数量级 / 结果能独立验证 / 结论不直接进判据；回来**必抽查一条指针**，对不上整份不采信。只返回结论等于把证据和推理路径一起丢掉——主方没法复查，于是不再复查，结构上就是那个报「全部一致」的 `recon.py`。**只能落 0 级**：子 Agent 是运行时行为，仓库里任何检查都拦不住，做成流程或模板就落进「靠人读才算生效」那档 ✗。**重开**：出现「抽查指针也拦不住」的场景（如它伪造行号）——那时改成让它把原始输出落文件，主方直接读文件。

### 审稿降为可选工序

四道工序里清稿 / 对稿 / 验收必经，**审稿改为可选，默认不审**；要走就走关键点或全量，**档位由委托人定，本库不设触发条件、不设判定标准**——助手只摊开观察（来源、抽读结果、对稿候选数），不把「发现几条」换算成「你该走哪一档」。理由是它唯一不能机判、判完没人能复算，成本不可摊销（全量约 2.8 小时/集、关键点 20–40 分钟、不审 0）；而且委托人一开始就这么判断，中途被助手以「工序不能砍」掰到「砍档位」又掰回来——**「默认」这种东西必须写在库里，否则每次对话都会漂**。配套：`定档.md` 不审也要写（验收 `accept.py` 查痕迹），而它的落盘密度只标 ⚠ 不判 ✗，所以不审不会被判不过。**重开**：出现「按默认不审交付后，成品被指出明显理解错」的实例——重估时要连同「哪一档能接住这类错」一起判，不许直接恢复成全部全量。
