## 四、制度体系评估：骨架已完整，缺 4 块「元制度」

这个库的制度体系在**决策**（判定记录 ADR + 重开条件）、**执行**（工序判据 / 手册 / 流程总图）、**检查**（doc_lint / selftest / pre-commit + 三级阶梯）、**协作**（协议 + 编号制）、**状态**（台账 / MEMORY / 落点表）、**发布**（CHANGELOG / README）六个层面都有真身且互相咬合，比绝大多数仓库完整。真正缺的不是更多条文，是这四块：

1. **事件计量制度**：判定靠个案，验证靠统计，但没有「事件登记」的规定载体（撞墙、假闸、失联都散在日志里）。补法：定一个登记格式 + 月度盘点动作。
2. **周期复核制度**：重开条件是被动触发的，没人主动扫「哪些 ADR 的前提已失效 / 重开条件已满足」。本库已装了全局 `retro` 技能却没定触发时机。补法：先手工跑一次「扫判定记录全部重开条件与前提」，验过值再决定要不要立成制度（避免空转）。
3. **快照回流闸**：讨论快照 → 制度真身 / 台账，目前靠自觉，这次就漏了两条。补法：在落点表「讨论快照」行加一句「快照里操作性结论须收工前落真身并立台账条目」。
4. **对外反馈制度**：库已公开（MIT、发 Release），但外部使用者没有报问题的入口——GQ 机制只覆盖剧库。要么 README 加一节「报问题走哪里」，要么立一条 ADR 明确判「不设」并写重开条件。二选一，别悬着。

另有一个**缓办项**（不要现在立）：工序文档的准入 / 退役判据，等 `#51` 盘完 14 份再定，现在立就是为没发生的事写规则——这符合库里「等活来了再立」的既有判断。
