### 病根 C：口径改了一半，另一半还是硬编码（`#1` / `#9`）

**共同形状**：参数或常量改了一处，别处仍在用旧值，输出照样本绿，**检查执行了 0 次也不报**。
**共同判法**：凡有「可切换的根」这类参数，改完必须全文件 `grep` 同一个常量名（不是看函数入口改没改）；凡带计数的检查，`查 0 个` 一律非零退出（已有）；凡分发出去的副本，必须能分辨**同一天内的不同版本**。

- **`#1` `doc_lint` 的 `VERSION` 只到天**｜成立（`doc_lint.py:36` 确为 `'2026-11-08'`，同日改过三次）。**采纳「带时分」**，不打文件 hash——hash 人眼比不出来，时分足够，且改一行。改完输出形如 `〔doc_lint v2026-11-08T2140〕`。**关闭条件**：同一天两个版本跑出来的字符串不同。**重开**：出现「机器要对副本新旧做判断」的场景（那时才需要 hash）。
- **`#9` `--docs` 只改了 `DOCS`，三处硬编码没动**｜成立，已逐行核：`:293` `FOLLOWERS`、`:309` 报错文案、`:333` `git_last_commit('docs/接棒必读.md')`，因 `:276` 是 `cwd=ROOT` + 相对路径，老库永远返回 `None`，走到 `:334` 整段返回。这是**静默失效**，不是误报。**采纳三行改法**（全换成 `f'{DOCS.name}/…'`）。**另两处一并改**：`:384` 归档豁免只认 `archive` → 扩成 `archive` / `_存档` / `归档` 任一；`LIMITS` 里本库不存在的文档，`--docs` 生效时不报「找不到」。**关闭条件**：任一文档目录不叫 `docs` 的库跑 `--docs`，三项检查真执行（能报出「落后」与「未提交」）；归档死链零误报。

### 病根 E：缺一层「跨集怎么排」（`#4`）

**形状**：一集内的十步画得很细，**多集怎么排全库没有一处写**。接手方默认「继续做下一集」，每一步看起来都在正常干活，方向是错的。剧库连续三次汇报都念「下一步 E02」，三次被当场纠正。
**为什么严重**：缺文档能发现，**缺一层调度会让人按错的方式干下去**，而且不报错。

**判法：采纳剧库的四段排法**（这是实证过的，不是设计出来的），写进 `docs/流程总图.md` 新一节「跨集怎么排」：

| 段 | 干什么 | 粒度 |
|---|---|---|
| 0 预扫 | 机改类工具全库跑一遍，**只出清单、不落盘** | 全剧一次 |
| 1 落盘 | 清稿落盘 → 重建配对表 → 对稿候选 → 人定案 | **按季一批** |
| 2 单集 | 定档 → 审稿 → 落地 → 验收 | 一集一闭环 |
| 3 收尾 | 全剧一致性比对 | 全剧一次 |

**三条必须一并写，否则照抄会踩**：① **段 1 与段 2 串行，不交错**——上游（词表、规则）要到最后一集才收敛，剧库两起实测（人名前缀叠字、剧情错叫）都波及已交付的集；② **段 0 只扫不落盘**，38 集一起落盘会把回滚粒度从 7–8 集放大到 38 集；③ **抽样只报警不放行**，0 硬伤只许写「未发现硬伤」。
**另两处**：`examples/新剧接入.md:208`「再挑第二集跑，两集规则都成立，才谈整季」加限定「**本条只用于新库准入，一次性，不是长期节奏**」；`docs/做法.md` 加一条常驻原则（赵哥原话）：**能提前做的、能按季推进的，一律先做完；审稿这类不可重跑、占人力大头的，单独按单集放最后。**
**关闭条件**：流程总图有这一节且含三条注意；新剧接入那句带「一次性」限定。**重开**：出现「段 1 必须与段 2 交错」的实证（交错的省时必须压过回修成本）。

### 病根 F：机器规则只写查什么，不写不查什么（`#6` / `#7` / `#10` / `#11`）

**共同形状**：判据写了「怎么查」，没写「哪些不归我管」。于是机器在一条规则上**过宽**（假红九成）、在另一条上**过窄**（9 处量级错一条没报），人开始不信候选表。
