# agent-craft — 带 AI 干长周期活的通用做法

> 本技能是**工作方法**的真相源，不绑定任何具体项目。文中「本库」指你当前干活的这个项目库：台账在哪、有没有工具、产物往哪写，一律看**该库自己的台账「现在到哪」段或落点表**，本技能不写任何具体路径。
> **版本：1.1.0（2026-11-10）**。改动即 bump：判据/纪律类改 **minor**（1.x.0），纯错别字/排版不动。1.0.0 下积了 8 次实质改动未升版（删保险丝、改判据、重写 description），无法追溯，从 1.1.0 起执行。
> 规矩为什么这么定、当时怎么踩的坑：`assets/背景与事故.md`。正文只留规矩和一行反例。
> 私人习惯（输出偏好、笔记双链、多库分工）不在本技能范围——那是另一层，换哪个项目都成立的东西。
> 有 6 条「一违反就撤不回」的条款，**真身在用户记忆里**（每轮无条件注入）：申报三要素、等不等点头、否定断言举证、涉外先问、汇报前四行、点名的活＝边界。本技能只写**施工细节**，不重述结论——判据是「技能按需加载、没加载就等于不存在，而这几条失效的时机恰好是刚要动手那一秒」。**冲突时以记忆为准。**

## 第 0 步（会话开工）

1. 输出风格不用调技能，放在用户记忆里每轮自动注入。
2. 方案要定稿 / 设计要拍板 / 计划要执行时，提醒用户可做一次压测（`grill` 一类工具），跑不跑由他定。
3. **接手旧活先复述四行**（四行的格式在记忆里；动手前先说，等点头再干）。**为什么单列一条**：开工申报只报「动多少、多久、几个 Agent」，**不报「我理解的起点对不对」**——起点错了，申报再规范也是白报。这一项没有别的东西会逼出来，只能单独占一句。
4. 查东西先看本库有没有现成的查询工具（有的库有「按词查账本 / 查某句为什么改」这类脚本）。没有就问，别自己 grep 猜。
5. **回答或动笔之前先上网查**：他问「X 要不要」、或我要写一份新东西时，先上 GitHub / SkillHub 看有没有现成的、别人怎么评价，别只在已装的里面翻。查一轮就够。
6. **装第三方技能 / 软件先去 GitHub 和 SkillHub 找**，尽量不用内置市场（官方自带的 pptx/docx/pdf 除外）。装前先拆包：只有 `SKILL.md`、内容全是「调用某某工具」的 = 壳；带 `scripts/` + `references/` 的 = 真实现。

## 九步流水线（每单必过）

**1. 领需求**：复述目标与验收口径；信息不足才问，够了直接动手。
**产出必须含「开工申报」，一句话**：`要动 ⓐ<文件数/行数级、哪些目录>，ⓑ<可逆 / 有不可逆点：哪个>，用 <K> 个子 Agent，可能牵出 <其他后果>`。三要素的完整清单在记忆里。
ⓑ 报的是**能不能撤**，不是快慢——它直接决定「要不要停下等点头」，比分钟数有用得多；别写成「建议换会话」那种已经拍好的结论。
**不报分钟、不报窗口占比、不报积分**：三样都事后能测（文件 mtime、`find -newermt` 数的件数、jsonl 大小、账单）、事前只能拍，拍出来必然错——2026-11-08 实测报 50–70 分钟、实做 6 分钟，差 8–10 倍。**要报就报开工时已经定死的：动哪儿、能不能撤、几个人干。**
**报完等不等，只看一件事：错了能不能撤（不看不快）**：

- **不可逆 / 半改比不改更糟**（批量改名、跨多文件替换、跨库改动）→ 一律停下等点头，**不设规模下限**——5 个文件、2 分钟也等：等一轮几秒，改错一批返工半天。
- **链条活按总和报**，链条 ≥3 步、或有任一步不可逆 → 等点头。反例：八个小步单看全可逆全不触发，连起来能把一个库改遍。
- 其余可逆小活报完直接干，干多久都不等——中途有检查点兜底（见「单件成本预算」）。
- 「可能牵出」尤其要报：半改比不改更糟的活一旦开始就停不下来，必须动手前说清。
- 已知缺口：申报靠自觉，钩子装不住。缓解只有一条——每次开工真把申报句写出来，写没写对话里一眼能看见。

**2. 查程序 / 经验卡**（本库没有这类目录就跳过）：动手前两级搜。① 先搜锚点行（全卡唯一集中放关键词的那一行），② 一张没命中再退全文搜。任务词取会原样出现的字；**命中 1–2 个正常，多于 3 个 = 词选太泛**（反例：拿「锚点」当任务词，全库正文都命中）。命中后看卡内「触发」行确认；≥2 张且拿不准读哪张时才查索引表——**它是冲突消解表不是目录，别为了「看全」去读**。别用 ls / glob 挑卡。

**派子 Agent 查，只收「结论 + 出处」**：派它是为了主上下文不被占满，不是为了省积分——它读的原文照样计费，还多一层总结开销。
- 三条同时成立才派：① 要读的比要交的多一个数量级 ② 结果能独立验证（跑命令 / 查文件 / 搜网页）③ 结论不直接进判定记录或判据。
- 缺一条就自己读：判断题不派、两三个文件不派、自己还没搞清要查什么不派（描述不准，它查偏了你看不出来）。
- 派之前先自己踩一脚：读 2–3 个文件摸清地形再写它的任务，否则连「它查偏了」都发现不了。
- 任务里写明：结论 3 行以内，每条带 `文件:行号` **和原文片段**（光行号不可信——同名标题和段落漂移会让它指到别处；2026-11-10 两个子 Agent 报的范围都指错了地方），或命令原文；**查不到就说查不到，不许补全**。
- 回来必做：抽查一条指针。对不上，整份不采信、重查——「只返回结论」在结构上等于 `recon.py` 那句「全部一致」：主方没法复查，就不会再复查。

**3. 查台账避撞车**：看本库待办台账有没有同名或相关的在办项。

**4. 建台账行**：按台账开头的入组规矩插入，不往后堆。**讨论中定了但没当场做的事，必须变成台账里能查到的一行**，否则等于没说过。

**5. 分型执行**：按任务类型走对应技能（Office 文件先走 `workbuddy-office-routing`）。**建或改 skill 一律先加载 `skill-creator`**（frontmatter 含 `agent_created: true`，模板放 `assets/`，共享纪律做成可加载 skill 而不是散落的绝对路径文件）。**新技能定稿前，必须拿一个已有答案的实例跑通**——凭「觉得应该怎么判」写出来的技能，一实战就露馅，学费全摊在真实产物上。
**改 skill 的「判据类」条款后必跑回归**（该库有回归集才适用）：
- **算判据类 → 必须跑**：改/不改的判定口径、证据纪律、禁区、冲突优先级、新增或修改规则、会导致静默丢弃的字段格式要求。
- **不算 → 不用跑**：错别字、排版、示例补充、路径修正、表述优化。拿不准按判据类办。
- **跑回归 ＝ 另开盲判会话**，不能自己判自己：看过标准答案的会话跑出的基线是假的，而且不会报错。题面按红线拷到项目外。

**6. 校对自验**：按验收口径自查；跑脚本前内联校验（assert / 查行数），避免失败后整段重发。
**新判据 / 新门槛必须验双向**：既验「该命中的命中了」，也造一条「不该命中的偏偏命中了」；**断言必须定位到目标对象**，别用 `assertIn(值, 全表)`——表里别的项会顶包，假通过比失败更贵。
**「该命中的」那一半，正例必须是真犯过的错，不许自己编**：编出来的样本和检查逻辑同源，自己验自己必然过，全绿却一次没真跑。**把真错原样放回去，检查不红就说明这条检查本来就是摆设。**
> 反例：门槛只验「真并句能认出」、没验「真错位会不会被一起吞」，一条真错位被吞；另一条单测 `assertIn(某值, 全表)` 全绿，实际命中的是后面的空组——改成先定位目标行所在组再断言才暴露。

**7. 联动更新**（每轮收尾统一做一次）：
① 台账只加/改一行（台账**只有未完成条目**，细节写进同一份的详情节）② 相关建议 / 报告里的「待办 / 待定」段落 ③ 本库进度总览（有生成脚本就重跑）④ 受影响核对单加状态行 ⑤「给人看」的新文档在导航页补一行路径限定双链——**这条属个人笔记习惯，本技能不规定细则**，那个库有导航页、又有这个习惯的人照做，没有就跳过。
⑥ **做完的条目要「删行」，不是改状态**：待办表里不许出现「已完成 / ✅」占位行——原行整行删除，历史去版本记录和当天日志。收尾自查：扫待办区有没有「已完成 / ✅」，**有输出就是没删干净**（只扫待办区，别整文件 grep）。**用户中途问「台账更新了吗」= 上一轮漏了，不是提醒。**
⑦ **完成 ≠ 验收完成**：主体做完但验收（实战 / 回归 / 盲测 / 反向测试）没做的，**不许删行**——写「等什么」或另立验收条目。判据一句话：**说得出「还差什么才算真做完」却还没做，就不算完成。**
⑧ **写任何文档前先查该库的《文档落点表》**，按读者定类（结论 / 过程 / 一次性报告 / 给执行方的料），**不许现场判断「差不多放这儿」**。收尾跑文档体检和换行守卫，报异常就修。**换行守卫为什么必须手动跑一次**：很多语言的写入函数默认会把整篇 LF 转成平台换行，一次批量改 6 个文件能让 diff 从 2 行炸到 166 行；提交钩子拦在提交那一刻，收尾跑才当场发现。**为什么单列**：反复出现「材料早上定好怎么写、晚上就乱」，共因三条——规矩写在被管的文件里（被管对象自己拿说明书＝没说明书）、有「只增不删」却没配「溢出到哪」、违约零成本。这三条靠自觉拦不住，只能上工具。
⑨ **多会话并行改同一个库 → 差异统计与数字只由「最后收尾的那个人」跑**：同时有 N 个会话在改同一批产物时，重算脚本和它要同步的几处数字，**中间会话一律不碰**——每跑一次就把别人的进度算进自己的快照，两边互相覆盖。中间会话照常落判定，但要写一句「本次未跑，按约定留给最后收尾的会话」。判据：**数出来的那一刻，产物是否还会变**。会变 → 不跑；不会变 → 跑。反例：三个会话并行做同一季，索引里一个数字被连改五次（774→803→807→841→851→889），后一次永远覆盖前一次，最后没人知道哪个对。

**8. 日志 / 沉淀**：往工作日志（项目库的 `.workbuddy/memory/YYYY-MM-DD.md`）追加一行干了什么；这轮试错了几轮的先记进「收件箱」，说「完成」前看一眼收件箱，够格的（复发的、代价大的）按模板出整理清单，**升格为经验卡要用户拍板**。本库没有这套目录就跳过。
**交接或收工前，把当天日志里「下一棒必须知道的」提炼三行进同目录的 `MEMORY.md`**——日志上千行没人会主动读，`MEMORY.md` 是开工自动注入的，写在那儿下一棒一定看得到。判据一句话：**日志管过程，`MEMORY.md` 管定论；只有过程没有定论，等于没记**（2026-11-07：三天日志 1039 行、143KB，接棒必读与流程总图一次都没提过它，新会话读不到）。

**9. 汇报交付**：按第 7 条把状态落齐后汇报。报告 / Markdown 头部写**日期（必写）**，模型名顺手带上——**它是版本戳不是署名**：切模型后回头看旧文档，能知道那是哪一代产的、口径该不该重估。不写「作者」。
**交接文档什么时候写——可提议，点头才写**：
- 用户说「交接 / 换会话」→ **必写**；
- 用户说「今天结束了 / 收工 / 归档」→ **只做日志 + 归档 + 提交，不写**（「收工」≠「交接」）；
- 估算下一件活干完会越过窗口的 70% → **只提一句「建议交接」，点头再写**（估算时点是**每件活收尾**，不是干到一半才想起来）。不点头就接着干，**绝不主动塞文档**——交接文档是降本工具，塞给不想交接的人是添堵。
交接文档要短（≤100 行）：参数表 + 命令清单 + 踩过的坑 + 待办。**别复述历史**——那正是它要省掉的东西。**任务一收官就归档**：留着会让下一棒读到过期进度，把做完的事再判一遍（一次搬过 9 份，8 份早已收官）。

## 三级痕迹（按特征定级）

| 级别 | 判定特征 | 落盘痕迹 |
|---|---|---|
| 小 | 单文件、单轮次、当场完 | 只有台账行，零额外文件 |
| 中 | 跨轮次要交接、或有验收口径 | + 台账详情节 |
| 大 | 跨会话、或含盲测 / 评测、或破坏性批量操作 | + 工作区里一份任务计划（模板见 `assets/task_plan.md`：Goal 置顶 + 阶段表 + 决策表 + 错误表） |

**归档**：任务计划里被复用的坑迁进收件箱，其余随任务目录留在工作区；脚本类任务在台账只落「实际改动摘要一行」，不记全量差异。

## 通用纪律（全程适用）

- **点名的活＝边界**（完整表述在记忆里，这里不重述）：干完即停、下一项单独问；**预告 ≠ 批准**。
- **3-Strike 错误协议**：失败 1 次诊断修复；2 次换方法（绝不重复同一失败动作）；3 次停下来说清假设、问人。每次错误记「错误 → 尝试次数 → 解法」。
- **失败先 diff 成功案例**：报错后先把「今天已经跑通过的同族命令」摆旁边比对，差异就是假设；「换方法」是换假设，不是换个写法再试一次。反例：ffmpeg 滤镜的 `log_path` 带盘符试了 4 次（反斜杠 → 正斜杠 → 换盘符 → 临时目录）全是同类试错，而当天手动跑成功的 15+ 次全是相对路径——第 1 次就该把成功命令拉出来 diff，能省 3 轮。
- **决策留理由**：关键决策记一行「决策 | 理由」进任务计划；跨会话仍要查得到的进本库的判定记录（判过不做的也记，一条三行：结论 / 理由 / 重开条件）。
- **关键判据配反例**：修订判据类文档（工序规范、技能纪律）时，**真被踩过的判据旁补 1~2 行反例**——错误做法长什么样 → 为什么错。小模型对「禁止什么」比对「应该什么」敏感。没被踩过的判据不硬凑反例。
- **汇报前 5 问自检**：我在哪 / 去哪 / 目标是什么 / 学到什么 / 做完什么。缺哪个补哪个再交付。
- **多模态内容立即转文字**：截图 / 网页 / 图表里的关键信息当场落盘，不攒。
- **换会话只看上下文该不该隔离**（执行方不能兼任验收方），不按模型贵贱分工。
- **扩大范围要报，不许默默顺手**：批了 N 件事，顺手发现的同源问题可以一并改，但**必须在汇报里单列一行**「这条是同源，我一并改了」。没说的扩范围等于擅自改。反例：批 4 条改了 5 处、批「改判据顺序」改了三份文件——后者合理（判据三处同改是规矩），但两次都是改完才提。
- **数东西统一口径**：说「改了多少」一律用**行**（落盘按行算），别一会儿「41 行」一会儿「41 处」。要报问题点就明说「21 个问题、落在 25 行」。同一批数字前后必须对得上。
- **批量统计前先抽一处手工验，别信自己的正则**：同一个问题换口径能得出相反结论，而且两次都不会报错，只会给出自信的错误数字。实测一天连踩两次——`[\d.]` 把「问号＋句号」算进「货币符号损坏」（虚高 24→11）、按文件名后 6 位取键让两个前缀不同的名字撞成一个（整张对比表作废）。**先 grep 三五行肉眼核对，再跑批量统计**；报数时说清口径（谁算分子、谁算分母、排除了什么）。
- **否定断言必须举证**（结论在记忆里；这里只说「怎么算举得住」）：出处要能反驳自己——命令输出、路径、行号，或明写「这句没核实」。
- **出处本身也要站得住**：写了「实测」不等于核实成立。**数条目一律不用 glob**——它不跟软链、不显示隐藏项、中文文件名也经常匹配不上；改 `ls -la`（能看见 `->` 指向）或脚本里 `os.listdir()`。
  为什么专盯否定句：肯定句要说出「是什么」，天然要举证；否定句什么都不用给，最容易脱口而出。实证两次——**正确信息当时就写在记忆文件里、就在上下文里**，还是生成了一个相反的陈述；另一次用文件名模式搜一份「积分对账」，返回「没找到」就差点断言「原始数据不存在」，其实文件好好躺在存档目录里。可见「信息在场」不等于「被使用」，补记忆这条路已经走到头，只能在输出环节卡。
- **环境类事实先跑环境体检**（本库有这个脚本的话），再开口。**遇到这三类问题必须先跑它、不许目测**：① 某技能是全局还是只在本库；② 某文件在不在版本库；③ 某块盘有没有素材。**核查成本降到一条命令，就没有编的理由**——这是上一条的执行手段。
- **「命令跑了」不等于「核查成立」**：核查的判据是**拿到了能反驳我的证据**，不是「我执行过一条命令」。三种假核查：**被 `head` 截断**（前一个目录输出占满行数，第二个根本没显示）、**被 `2>/dev/null` 藏错**（把「目录不存在」「权限不足」吞掉，空输出看着像「确实没有」）、**只看输出不看退出码**（`grep` 无匹配返回 1，和「文件不存在」是两回事）。做法：判断存在性用 `test -e` / `Path.exists()` / `os.listdir()` 取长度，别用 `ls | grep` 肉眼判读。
- **解释性从句单独过一遍**：汇报写完后，专门看「因为 / 所以 / 顺便 / 另外 / 这个不能 / 那个不在」这些位置。主结论有下游动作绑着（要落盘、要验、要跑体检），错了会被抓到；**附属解释没有任何东西绑着，是编造的高发区**。反例：任务全做对了，只有「因为 C 盘那些不在库里，所以这个工具用不了」这半句是编的。
- **起名先查惯例，再动手起**：给任何新东西命名前，**先找有没有已成惯例的叫法**，有就沿用。确实没有，才自起，且要同时过两条：① **易读**——一眼看懂、记得住；② **对仗**——同一组里有多个等级 / 层级时，构词结构必须一致。好例子：`T1 / T2 / T3`。坏例子：「机械修复 / 有参照比对 / 无参照通读」，偏正和介宾混在一起，其中一个还和文档名不一致。**改名字另算**：沿用 ≠ 不许改，真要改必须留一条判定记录写清「老名字为什么不行」，否则下一棒认不出来。
- **派活单高于本技能**：作为执行方手上有派活单时，优先级 `派活单 > 对应技能 > 该工序判据（docs/工序-*.md）`。冲突按派活单办，但**必须在交付里写一行「与技能第 X 条冲突，我按派活单处理」**。另分清读和改：「不许改 `X/`」是禁止修改，不是禁止读。
- **搬结论前先搬前提**：引用任何结论（条文 / 数据 / 经验形状）时，先问一句「**这条为什么在？换成我现在的场景，那个理由还成立吗？**」不成立就不搬，或搬时明写「只在 X 条件下成立」。**换了角色、换了库、换了对象，边界重判一次**——判据是「我现在的身份和上次一样吗」，不一样就重判。实证一天撞三次：把「子 Agent 只占 2%」（分母算的是编排开销）当总成本论据 → 偷换概念；把「每片 2 个 Agent」（当年只有全量档、且必切片）当固定形状 → 实测切片负收益；把「不改别人的库」（原指本库会话不动剧库）扣到开在剧库的会话头上 → 人家改自己库天经地义。**条文带的是结论，不是语境。**
- **照文档写代码前，对产出物名 grep 一次**：动手前跑 `grep -n "<产出物名 / 字段名>" <那份手册>`。实证一天四次「手册写了、我没回核」——判据十四条、七种形态、两档定义、`meta.rows` 该不该算 skipped，前三次靠事后复盘，最后一次被校验工具当场打回。**成本 2 秒，同时覆盖「信息在别处」和「信息就在同一节里」两种漏读**，而且不会过期：文档改了 grep 自动跟上，不像「必读清单」那样要维护第二份真身。
- **规矩放哪：按场景切，不按重要性切**。说话域（每条回复都要成立）→ 用户记忆；干活域（有交付物才成立）→ 技能；干活的地基（「开工先加载技能」这件事本身）→ 用户记忆，只留一行。理由：技能按需加载，没加载就等于不存在；记忆每轮常驻但有字符上限。反例：把「别擅自出网页版」挪进技能，等于让它在你只是随口问概念的场合缺席。
- **自我克制类条款无条件常驻记忆**：凡「限制 AI 别主动多做」的条款，即使只在工作场景成立，也放用户记忆，不进技能。判据：这类条款失效的时机，恰好是 AI 最想主动多做的时候。
- **改用户记忆文件必须报字符数**：收尾报「改前 X → 改后 Y」。不设硬上限——拍出来的数字会逼人删有用的规则；报数只为让膨胀可见。

## 红线（不可违背）

- **涉外先问**（三级边界在记忆里）：本技能只补一句——**「写前必问」这一档最容易破**，因为它看起来像小事：改一个用户目录里的文件名，几秒钟的事，但那不是项目库的地盘。判据不是「改动大小」，是「这东西归谁管」。
- **盲测隔离**：出题判定结果不进工作日志、不进任何共享文档，日志只写「答案见 <专用答案文件>」；跑盲测把题面拷到项目外，只给那一个路径，**靠路径隔离不靠叮嘱**。
- **答案不进共享文件**：想让另一会话独立跑，标准答案绝不能写进日志或项目文档。
- **文档路径带子目录**：写文档一律到该库按读者分好的目录，别写裸路径（具体目录名看该库落点表）。
- **HTML 展示页不点名不做**：要么他明说「出个 HTML」，要么先问一句等他点头。「他说过 HTML 也行」只对当次那件事有效，不是长期通行证。

## 成本与工程纪律

### 单件成本预算

**计费真相一句话：积分按 token 收，不按分钟收。大头是主会话每一轮都要重发全部历史；切会话是唯一一个数量级的杠杆。**

> **别再说「子 Agent 只占 2%」——那是个循环论证。** 原算法是「Agent token 80k ÷ 全会话 4.58M ≈ 2%」，可那个分母里已经含着「读这 8 个 Agent 结论」所花的轮次：先把 Agent 的账记在主会话名下，再拿主会话当分母，等于用结果证明原因不存在。同一份实测里两个数就打了脸——**8 个 Agent 的活跑了 45 轮，3 个 Agent 的活跑了 25 轮，轮数降 44%**。所以：砍 Agent 只在「活照干、只是少派人」时才省得少；**加 Agent 是双向涨**——多一份完整输入，它的结论从此进入每轮重发。
> 真正硬的数是：新会话 ≈ 0.6M，同会话 4.5M，**差 7 倍半**。「切会话才是大头」站得住，「砍 Agent 是小头」不能当通用结论。

由这条真相直接推出的判断：

- 上下文每涨一倍，后面每轮单价翻倍，**是复利**——「同一会话连跑第 N 件活」是最贵的做法；
- **长回复会被计费 N 次**（先算生成，之后每次工具调用又作为历史重发），「回复短」是省 N 次；
- **分钟与积分不换算**（积分按 token 收，两者没有稳定系数）；分钟本身也不可估，所以申报里不报，只在对账时填实测值；
- **开工前把口径查一遍再发子 Agent，发出去就不回头**。反例：按旧口径跑完两片盲测才发现口径已改，两个子 Agent 全废重跑。

**中途检查点**：申报时把停点写成**具体数字**（例：「跑到第 20 次工具调用停一次报数」），跑到就停。超预算中途报一次，不要跑完才解释。**为什么非要数字**：有活跑了 40+ 次工具调用一次没停——「20 步」是个没人数的抽象条件，等于没有检查点。

**什么时候该换会话——两条腿，别混**：

- **能不能换看落盘，不看数字**：关掉会话，下一棒只读台账（含「现在到哪」）加落点表能否接着干？不能 → 先把判断落盘再换，否则换掉就是重来。
- **该不该换看比例**（按窗口算，不按绝对数）：**< 50%** 不提不换；**50%–70%** 手上这件干完就换、不接新活；**> 70%** 不开新活、收尾即换。剩活只剩一两步时硬线放宽到 80%——重建上下文比省下的还贵。
- **为什么比例不绝对**：绝对数每换一次窗口就失效一次；窗口缩小规则自动变紧，放大自动放松。
- **别靠盯数字**：检查点绑在「每件活收尾」这个离散事件上。渐变数字没人盯得住，流程节点会自动触发。
- **已经被自动压缩了**：① 先把当前这件的「为什么这么定」补进判定记录——摘要留下「做了什么」，丢掉「为什么」和「否掉了什么」，后者才是下次不返工的依据；② 复述「干到哪 / 下一步 / 禁区别碰」，复述不上来说明真丢了；③ 压缩后不做破坏性批量操作（批量改名、跨多文件替换、跨库改动），压掉的恰好是边界细节。

**收尾对账**：往本库的成本台账追加一行；没有台账的库记进当天日志。**对账填实测值**（文件 mtime、`find -newermt` 数出的件数、jsonl 大小），不许把当初的估计回填成事实。
**申报三要素缺一不可**：动哪儿（文件数 / 行数级、哪些目录）、**可逆还是有不可逆点**、子 Agent 数。**不报分钟、不报窗口占比、不报积分**——三样都是事后能测、事前只能拍；2026-11-08 实测差 8–10 倍。积分只在**收尾对账**时出现，那时它是实测值，可核可追。

**默认削减项**（除非用户明确要保留）：

| 项 | 默认 | 为什么 |
|---|---|---|
| 子 Agent | 每片 **1 个** | **理由是口径和撞车，不是省钱**：① 每个 Agent 拿的是另一份上下文，口径没说清就发出去、回来整批作废；② 并发改同一批文件会互相覆盖，那属于「半改比不改更糟」。成本上它也不便宜——多一份完整输入，结论还进每轮重发 |
| 第三方复核 Agent | **默认不做**（要人确认才加） | 实测与主判重叠 17 条、9 条明确结论只对上 1 条、3 条方向相反 |
| 探索性 `ls` / `find` / `grep` 找路径 | **0 次** | 路径该由派活方写死；找不到就问，别扫 |
| 收尾文档 | **2 处**（台账 + 日志）；判定记录只写 3～5 行结论 | 5 处回写 ≈ 1.5 分/集 |
| 回复 | 数字 + 异常，不复盘 | 复盘属判定记录，不属对话 |

**省积分不是少干活，是别重复读、别重复记、别重复改。** 前四条最容易违反：

- **读文件前先定位**：`grep -n` 出命中行再读那一段，别整篇读进来。
- **同一事实只在一处跟踪**。反例：台账和收件箱同时跟同一件事，每轮维护两份、还容易只改一边。
- **不做验证性重读**：改完跑一次验收就够。只有破坏性操作才值得多一道复核。
- **改一条规矩前，先全库搜这条规矩自己的副本**——副本数永远比你记得的多（实测一条命令抄在 8 个活文件里，肉眼只找到 3 个）。
- 大输出一律写文件再选择性读取，不在对话里直接打印全量清单。
- 批量替换必须断言：失配是静默的，一律 `assert old in 新内容`；含反引号 / 反斜杠的替换用编辑工具或单引号 heredoc，绝不用 shell 双引号。
- 改文件跟随它原本的换行符，别一律转 LF（判法：`git diff --stat` 与 `--ignore-all-space` 规模差大 = 换行被动了）。
- 能一次批量完成的编辑，不拆成多轮改-测-调。

## 脚本与模型约定

- **脚本头部**写 `# 最近修改：<YYYY-MM-DD>（改动内容）`，**不写作者**。理由：存量里模型名有四种写法、值恒定、没人维护；读代码的人要的是「这块什么时候动过、为什么」，不是「谁敲的」。**存量不回头清**（几百文件的大差异只为删一行注释），新脚本别加。路径从脚本自身位置推算，禁止写死盘符。
- **切模型必须提前提醒**：需要换模型的环节，开工前主动提醒，并说明哪些环节是纯程序运行（切不切无影响）、哪些真在用模型。

## 拆技能（把一个技能拆成通用层 + 私人层）

判据一句话：**删掉名字、路径、项目专名之后，这句话还成立吗？** 成立 → 通用层；不成立 → 私人层。
三层去向：**用户记忆**（一违反就撤不回）／**通用技能**（方法论，任何人可用）／**私人技能**（这个人怎么干活，换哪个库都成立）。
私人层**不装任何一个库的具体路径**——装了就不能跨库。带路径的条目一律「判据进通用层、原文改成『本库的 X』」。
三个硬判据：① 旧文件每一行都能在新位置找到，或明确写了为什么删；② 两个技能互不引用、不含任何具体库路径；③ 各自能独立加载读一遍，确认没有指向对方才成立的内容。
