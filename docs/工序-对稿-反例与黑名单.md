# 对轨反例与黑名单

> **性质**：摘要。统筹手册第 4 节是黑名单的原始出处（详版），内容冲突时**以本文件与手册共同修订为准**——两边都要改，别只改一边。
> **用法**：开工前扫一遍。这里每一条都有人真踩过，照着做会白干半天。
> **铁律**（2026-10-28 踩过两次）：写反例**不许点名具体行 + 写出该行结论**——那正是当轮考题时，判读方照抄即对，成绩整批作废。本文件只讲情形，不讲哪一行、不讲该怎么判。

## 一、被否决过的说法（谁说都别再让它复活）

| 说法 | 为什么不成立 |
|---|---|
| 「官方条目特别密，所以错位多」 | 实测 12 集官方间隙中位数**全是 0.13s**，没有哪集特别。看着错位多的真实原因另有，查清之前不要编 |
| 「用『我们英文对应官方哪一条』判错位」 | 算出 93 条"异常"，抽查时差最大的 14 条，**全是分段合并或短句乱配**，无一是真错行。判错位只能看行内中英对不对得上 |
| 「补行会毁掉通读的行号主键」 | 不成立。三层坐标全锚源字幕，apply 有插入感知补偿。真正的问题是**判断依据失真**（中英错开一行时逐句判不可信），不是主键坏了 |
| 「只有补行需要先行处理」 | 不准确。错位不产生 inserts，但同样污染逐句判断 |
| 「英文轨与官方不一致就以官方为准」 | 已推翻。官方只是**另一份听写稿**，实测会漏句、截断、简化、听错。两边都通顺的内容分歧没有仲裁者，改成官方版等于赌官方对 |
| 「分诊能砍 60–70% 工作量」 | 只对「实质差异」这一档成立（纯措辞占 63–81%）；算上错位后整体降幅约 45% |
| 「执行方交回的数字可以直接信」 | 真伪会混在同一份简报里。实测一份简报里三组数：两组真、一组把 88 处正确译法说成 95 处该改——照做会把对的改成错的。**只能逐条复算**，尤其"建议改标准答案"这类结论，必须先在成品里数一遍 |
| 「副会话不会越界改共享文档」 | 它真改过台账。内容都对，但这是两方争一支笔。**默认它会越界，写死禁令才管用** |
| 「机械段改的都是对的，verify 过了就没问题」 | 出过事故：7 处把正确句子改坏（补语被吃掉、助词被换成另一个字），全部落地成品。**verify 只查「声明的改动有没有落地」，不查「改得对不对」** |

## 二、判读时走过的弯路

| 弯路 | 为什么不通 |
|---|---|
| 逐条判「我们多 / 我们缺」 | 多数是一句话拆成两条，真错极少；判几百条换不来几条改动 |
| 继续深挖 SDH / 轻微差异 | 用三个专门脚本精细对照一整集，72 处里只采纳 1 条，收益接近零 |
| 错位档整档跳过、每集抽 5 行兜底 | 已废弃。错位档里藏得住行内硬伤，整档跳过必然漏。现在按簇抽查 |
| 拿字数变化反推改动类型 | 语义类型和字数之间**没有对应关系**：换译名编辑距离接近 100%、补译让中文变长 2 倍、改两三个字就超阈值。这条路整体不成立 |
| 看到「整集几百条错位」就当内容问题逐条判 | 先看偏移表。整集偏移没校正时，几百条错位里一条真错都没有 |

## 三、句群：不许单行硬改

症状：一句话被拆成两行，中文和英文错开一行落位。

| 弯路 | 为什么不通 |
|---|---|
| 用单行替换硬改其中一行 | 必然读不通——另一行的中文还停在原来的位置 |
| 只改中文、不动英文 | 组内要一起改，`verify` 的 V21 要求「组内全改或全不改」 |
| 当成「两条独立的错」分别判 | 这是**一处结构问题**。分开判会各改一半，越改越乱 |

**正确做法**：在 `02_工作区/<季>/groups/<集>.json` 里声明这一组（哪几行、各改成什么）。目录不存在就新建——这个目录是按需生的，不是每个季都有。`merge` 读它、与单行改动冲突时以句群为准；`apply` 整组一起校验，任何一行对不上就整组不动。

**怎么认出是句群**：看是不是**整段错开**，不是看单行读不通。单行读不通多半只是翻译问题。

**找不到哪几行算一组时**：把中英逐行并排打印，找「中文第 k 行说的其实是英文第 k+1 行」的位置——错开处一眼就能看出来。

**组里有一行 `cn_before` 对不上**：整组都会被拒。回去核源字幕原文，含空格与全角标点，逐字对齐。

## 四、工具会给出假信号的三种情况

1. **数字离谱**（几百上千条）→ 先查工具，别急着判。八季必看从 470 掉到 136 全是工具修正换来的。
2. **「我们缺」虚高** → 官方一句常等于我们两行，单行比对必然低相似度，会凭空造缺。已改成时间 ±8 秒内搜 + 字符级包含。
3. **判过的不改行会回潮** → 不写判定表，下次重跑又翻进必看。判定表路径是硬要求（见 `docs/工序-对稿.md` 第 6 节「输出」）。
