# buddy-workflow — 私人干活习惯（跨所有工作库）

> 本技能只装**这个人**的习惯，不装工作方法，也不装任何一个库的路径与工序——那些在各库自己的接棒必读里。
> 判据：**删掉某一个库，剩下的还成立吗？** 成立才留在这儿。所以这里一条具体路径都没有。
> 版本 2.0.0：从「日常通用工作流程」收窄成「私人习惯」，方法论部分已独立出去。翻旧版本的人看到的应当是「同一个技能收窄了职责」，不是「一个技能消失、另一个凭空出现」。

## 适配范围

所有工作库通用。开工时先看该库的接棒必读拿路径和工序，本技能只补它没写的私人习惯。

## 输出

- 风格规矩在用户记忆里、每轮自动注入，**不用调技能**。`i-have-adhd` 是手动工具，用户喊才用。
- 「说人话」对交付文档同样成立，不只聊天：少术语、句子短、结论在前。
- 他关注积分消耗，具体策略在工作方法那一层，本技能不重复。

## 笔记导航双链（Obsidian）

- 当轮新落盘的**「给人看」**文档，在导航页（MOC）对应分组补一行**路径限定双链**：`[[库/路径/文件名|显示名]]`。限定路径是为了防同名撞车。
- **不挂**：给 AI 看的、存档目录、脚本自动生成的文件（通常标了「勿手改」）、管线机器产物。
- 库没有 MOC 就跳过，**不代建**——有没有属于那个库自己的决定。

## 多库分工

- **电脑本身**（装软件 / PATH / C 盘 / 环境踩坑 / 盘符容量）→ 电脑管家那个库。
- **各项目业务** → 各自的项目库，互不越界。
- **环境类的事不进项目库**：项目库只放这个项目的料。
- 判据一句话：**这件事换个项目还成立吗？** 成立 → 管家库；只对某个项目成立 → 那个项目库。

## 和旧版的关系（给下一棒看）

旧版 159 行的 `buddy-workflow` 是「一套东西全装」：方法论 + 私人习惯 + 具体库路径。现在方法论独立成通用技能，库的路径交回各库的接棒必读，本技能只留跨库成立的那部分。
**旧真身目录已停用，仅作历史存档，别再在那边改规矩**——它的位置记在通用库的判定记录里，不写在这儿（本技能不留路径）。
