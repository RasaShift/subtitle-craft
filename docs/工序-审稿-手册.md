## 一、回顾段（前情提要）怎么处理

**查表**：`02_工作区/recap_boundary.json`，按 `ep` 找本集：

```json
{"ep": "S02E01", "start_line": 23, "end_line": 135, "rows": 113, "source": "mark"}
```

`start_line` 为 `null` 表示本集无回顾段（如 S01E01）。全库 96 集里 95 集有，合计 3929 行。

- **正传**：`mk_worksheet.py` 的起止行**必须绕开** `[start_line, end_line]`，回顾段一行都不进分片。
- **续一 / 续二**：`slice_nb_r.py` 不做这个剔除，`片1.tsv` 头两行就是「前情提要 / Previously on…」。现行口径是**照判**，别自行删行，但开工时要说一句「本片含回顾段 N 行，按现行口径照判」。
- 派活单说回顾段要单独处理（另立专线）时，从派活单。

> **为什么必须机械剔除**：S02E01 首版落盘 24 行里混进 14 行回顾段，全部回滚。当时 handoff 明写「前情提要不在本次范围」，**靠文档警告没拦住**。

## 二、切两片

**片数固定 2。** 旧口径一集 5 片（每片 190 行）已作废——成本实测 1 片 100%、2 片 125%、3 片 151%、5 片 201%。

**正传**：

1. 取正片段（回顾段之后的全部对白）时长，目标切点落在 **1/2 处**
2. 在目标位置 **±3 分钟**内找**时间空档最大**的那一处作切点
3. 窗口内最大空档 <2s（对话极密）→ 该集不切，或改在整集范围找合理空档
4. 切点必须落在两个 Dialogue 之间，**不许切断同一说话人的连续句**
5. 切完按行号各跑一次：

```bash
# 在本库根目录跑（不是 cd 到某个「工具目录」）
python tools/mk_worksheet.py "<源ass>" <起行> <止行> "<输出目录>/worksheet_01.tsv"
python tools/mk_worksheet.py "<源ass>" <切点+1> <止行> "<输出目录>/worksheet_02.tsv"
```

`mk_worksheet.py` 解析复用 `ass_rows.iter_rows`（**不是老库的 `dialogue_proof.iter_rows`**，本库没有那个模块），输出 UTF-8 BOM + CRLF，四列 `行号 / 时间码 / 中文 / 英文`，中文为空会报「中文为空 N 条」。**行号是 ASS 的物理行号**，与 `recap_boundary.json` / findings 同源。

**续一 / 续二**（⚠️ **下面这个 `slice_nb_r.py` 本库没有**，照抄会报「找不到文件」；续一 / 续二切片在本库只能手工，或者从剧库那边连工具一起带过来）：

```bash
cd <工具目录>          # 本库没有这个「工具目录」，这段只在剧库里成立
python slice_nb_r.py --show <剧型代号> --ep 05 --out "../../02_工作区/通读/<剧型代号>_E05"
python slice_nb_r.py --show <剧型代号> --ep 05 --dry-run        # 只看统计不写文件
python slice_nb_r.py --show <剧型代号> --ep 05 --chunks 3       # 临时改片数，默认 2
```

只取 `Default`（对白）与 `注释`（歌词）两种样式；`English` / `Mark` 不进审稿范围。切点取全片最大时间空档、位置靠近中点。产物：`片1.tsv` / `片2.tsv` / `meta.json`。

**切完跑自检，不过先停下报，别开判**：

```bash
# 本库有 check_slices.py，别再去找 .workbuddy/skills/... 那个旧路径
python tools/check_slices.py "<通读集目录>"
# 正传分片带行号，要连回顾段一起核：
python tools/check_slices.py "<pilot 集目录>" --recap "<recap_boundary.json>" --ep S02E02
```

脚本核四件，退出码 0 才算过：

1. 每个分片去表头后的数据行数 = `meta.json` 的 `slices[].rows`
2. 各片行数相加 = `meta.json` 的 `rows`（**实测口径：`skipped` 不计入 `rows`**，续一 E01–E05 五集都对得上）。`meta.json` 里的 `skipped` **必须是对象**（如 `{}` 或 `{"片1": 2}`），写成数字 `0` 会直接 `AttributeError: 'int' object has no attribute 'values'`——2026-11-07 手造测试数据时踩的
3. 相邻两片时间不重叠、顺序递增
4. 给了 `--recap` 且分片有「行号」列时：任一行号落进回顾段区间就报错

本库有 `tools/check_slices.py`，直接跑；真跑不动时才手工核这四件——**别跳过**，S02E01 就是没机械拦边界，24 行落盘混进 14 行回顾段。

## 派活：两遍分开，别让一个 Agent 一口气做完

判读有两个动作，实测**塞进同一个 Agent 的同一次扫读里会互相挤**（2026-11-02 E07 回归，数据见本节末）。派活按两遍分：

| 遍 | 只看什么 | 提示词要点 |
|---|---|---|
| **第一遍 · 句法遍** | 中文自身：念不通、塌句、指代悬空、问句成陈述、断行错位 | **不许拿英文比对措辞**，合上英文把中文念一遍 |
| **第二遍 · 逐词遍** | 英文形态：时态语气、关键名词、限定词范围 | **只看这三样**，不看中文顺不顺 |

两种派法，按预算选：

- **推荐**：每片 2 个 Agent（一个句法遍、一个逐词遍），每集 4 个。子 Agent 只占 token 的 2%，换来省掉盲测与复扫——那两样各要 1–2 个 Agent，还都要统筹方重读、核原文、合并。
- **省着用**：一个 Agent 做两轮，但提示词里必须**明确隔开**：「第一轮到此结束。现在进入第二轮，忘掉第一轮的全部结论，只查这三样。」

### 为什么不能塞成一步（实测数据）

2026-11-02 拿 续一 E07（真值 37 条）做回归：把「逐词核三样」加成判读顺序里的第 1 步之后，一个 Agent 报了 18 条——**总数和首轮 17 条几乎一样**。拆开看：

| | 三类（时态／名词／限定词） | 其它类（句法／指代／方向） |
|---|---|---|
| 首轮（只有句法遍） | 4–5 条 | 12–13 条 |
| 加了逐词步之后 | 9 条 | 6 条 |

**加了一步等于换了一批，不是多抓了一批。** 判读注意力是零和的，所以必须分两遍、分开派。

## 判断路径

**四步，全在 `docs/工序-审稿.md` 第 5、7 节，这里不重复**：整句回读 → 念中文 → 逐词核三样 → 十四项打勾 → 定档。

本技能只补一件文档没写的：**这四步怎么分给两遍做**——整句回读和十四项打勾归句法遍，逐词核三样归逐词遍。塞进同一个 Agent 会互相挤（数据见上一节）。

> 顺序反了会漏整句：只过十四项、不做整句回读的那一版，实测召回 48%。

举例一律用虚构句（**别抄真实集的原文**——真实例句写进判据，那一集就不能再当回归集了，2026-11-02 踩过）：`almost ready → 已经准备好`、`what you are → 你做过的事`、`good news` 里的 good 不见了。

## 明确不报

一句话：**看不懂 → 报；看得懂但觉得能译得更好 → 不报。**

十二类不报的完整清单在 `docs/工序-审稿-判据.md` 第二节（N01–N12），动手前扫一遍。最容易误报的是措辞、翻译腔、语域、脏话净化这四类。

## 形态清单（派活时必须带上）

七种形态在 `docs/工序-审稿-判据.md` 第三节（F1–F7）。**派活时原样带上**——不带这七类，出条数差一个数量级（某片 325 行出 6 条 vs 另一片 545 行出 15 条）。复扫时同样要带全，别因为「上一轮带过」就省。

## 密度：已作废（2026-11-02）

**密度不再作为门槛、不再用于判断「这一片判够了没」**，只作为过程记录写进判定文档。实测两集：密度 6.20 那集（判了四轮）还查出 4 条漏的；密度 4.42 那集（一轮判完）盲测真漏 0。**密度最高的漏得更多——它衡量「报了多少」，不衡量「该报的报到了没」。**

唯一的门槛是盲测真漏数（在 `subtitle-read` 第 2 步）。报 30 条别以为判够了，报 10 条也别以为漏了，等盲测跑完再说。

## 输出两种形态

**正传**：每片一份严格 JSON（`semantic_chunkN.json`），结构照 `p4_semantic.md` 的「输出 JSON」一节抄，字段一个不许少：

```json
{"episode":"S02E02","chunk":1,"vo_ranges":[[22,41]],"issues":[
  {"ln":309,"dimension":"L0","problem_type":"C1.2 主客颠倒","severity":"major",
   "confidence":0.9,"evidence":"…","suggest":"…"}]}
```

- `problem_type` 必须带 C 编号（`C1.1`–`C3.3` 共 14 个），不在这 14 个里的一律不报
- `dimension` 只做标注，取值 `L0`–`L5`，不许自造
- `vo_ranges` 必须是成段区间，`[23,23]` 这种单点等于没做

**续一 / 续二**：每片一份精简清单（TSV 或 md 表），四列：`时间码 / 一句话理由 / 建议改法 / 严重度`。
只给这三样，**不写长篇证据**——证据留到落盘后只对采纳条目补。单次输出约 3800 token；全量详细版 17000 token，后段必然草率。

**但「建议改法」必须是能整行替换的完整中文段**，不是只修坏掉的那半句。这两件事别混：证据可以省，改法不能残。

> 反例（2026-11-02 续一 E07 实测，37 条里 12 条踩）：原行是「石板把她压住了 但是」，建议改法只写成「石板把她压在那儿」——后半句「但是」没了。意思是「只改这一句」，但落盘是按整行串替换的，照抄就把句子改断。落盘方逐条拼回整行，多花 12 分钟。
> 另一类同源错误：「- 医生 结果怎么样 -还行」只给「那就好」，丢了前半段对话。
> **写法：把整行中文原封不动抄下来，只动要动的地方。**

## 硬约束

- **只报不改**：除建议改法外不输出完整译文，不重排、不合并行、不动任何文件。
- **行号与原文照抄输入**：正传抄分片的「行号」列，不许自己推算；续一 / 续二 用时间码定位，别从成品里去数行号。
- **置信度只用于排序，不作丢弃门槛**：低于 0.6 也报，`confidence` 如实填。唯一例外是整片几乎无可报之处却已报 20 条以上（判断失控），才用 0.5 兜底。
- **同一处不重复报。**
- **回顾段**：正传回顾段已在分片阶段剔除；续一 / 续二 的 `slice_nb_r.py` **不剔除**（`片1.tsv` 头两行就是「前情提要 / Previously on…」），现行口径是照判，别自行删行，但要报一句。
- **不写 findings、不跑 merge/apply/verify**：那归 `subtitle-read` 和统筹方。
- **不改别人的库（`日常杂活` / `是大臣系列`）里的文档**，尤其台账。有发现写简报「顺带发现」。
- **判据有问题写简报，别自己放宽**（判据只能由不干活的人定）。

## 两条最容易判错的地方

1. **拿「读得通」当免罪理由。** 「读得通」只证明 C2.1 没命中，不证明 C2.5 没命中。
2. **把段首截断当漏译。** 抽样给的是连续片段，段首那行的前半句常在段外上一行。凡「缺主语／缺前半句／否定反了」的指控，先回看上一行。

## 交回什么

三件（格式见 `docs/判断纪律.md` 第 4 节）：候选数据 + 简报 + 自检结果。

简报第一节必须是大白话：这集报了几条、哪几条拿不准、用户要不要亲自看。后面才是按 C 编号的分类统计与密度。

两条本工序特有的：

- **报数要给条数**：两片分别报，别合成一个数。密度可以附上作参考，但不作任何判定（见「密度已作废」一节）。
- **说清盲测真漏数与处置**：每片真漏几条、走了定向扫还是全片复扫、补了几条。

## 完成标志

见 `docs/工序-审稿.md` 第 10 节。本工序特有一条：**密度和条数都不是完成条件**，只有盲测真漏数算——处置规则在 `subtitle-read` 的真漏处置表。

## 正传七步

### 1 格式校验

```bash
# 在本库根目录跑
python tools/validate_semantic.py <result.json> --season S0x --ep NN --sheet <本片.tsv>
```

五项闸：行号在题面内 / 字段齐 / `vo_ranges` 成段（含单点凑数告警）/ 密度（条每百行）/ 结构合规。**不合规先退回去重出，别在脏数据上往下走。**

### 2 预筛（必跑，顺序在打包之前）

```bash
python tools/prefilter_semantic.py --ep-tag S02E01 --chunks "<候选 glob>" --dry-run   # 先看数
python tools/prefilter_semantic.py --ep-tag S02E01 --force-new 205,121               # 人工捞回
```

剔掉成品已改好的行（旧 finding 覆盖 / 只改英文轨的机械 pass），只留真新增。

- **「跳过 N 条」不是结论**。必须人工扫一遍跳过明细（`<key>_已改过.tsv`）：同一行两处问题时，旧 finding 只覆盖一处、整行被跳过，第二处会**静默消失**。
  实测 S02E01 第一版剔 8 条，其中 **5 条是真问题**（同行两问题 2 条 + `en_typo` 型旧 finding 根本没碰中文 3 条）。
- 自动判「同行两问题」**不采用**——按改动区段判会把措辞变体也算成两处，误报比抓到的真问题多。用 `--force-new` 手动捞。
- 判「成品改好没有」读 `03_成品/`，不是 `定稿基线/`（后者是审稿输入，内容不同）。

### 3 抽 5 条判误报

人工抽看。这一步没有机检，必做。

### 4 第三方复核（默认不做）

只在用户明确说「要复核」时做：`isolate_review.py` → 子 Agent → `check_review.py`（exit 1 = 打回）。**本库有 `isolate_review.py`，没有 `check_review.py`**——打回与否本库靠人看复核结论。

```bash
python tools/isolate_review.py --ep-tag S02E02 --result <result.json> --sheet <片.tsv> \
  --only <预筛新增表> --prefiltered --base "<项目外的隔离根>"
```

- 隔离目录**必须在项目外**，只放 `p4_rubric.md`、`terminology.json`、`character_tone.json`、样本表、交接卡片。**绝不放候选清单**，放了就锚定，测试作废。
- 复核结论**只作参考列，不做出发点**：实测与用户定档重叠 17 条、明确结论 9 条里只对上 1 条、3 条方向相反。
- 别手工造「过滤后的 result.json」——中间产物不留档、不可复现。

### 5 分档

```bash
python tools/split_by_tier.py --review <隔离目录>/review.tsv --candidates <隔离目录>/candidates.tsv \
  --ep-tag S0xEyy --judged <上一次 judged.tsv>
```

产三件：`auto_apply.tsv`（应改，直接落盘）、`manual.tsv`（人工判）、`summary.md`（条数 + 抽样明细）。

- 人工**只判 `manual.tsv`**。「不改（抽检）」留空 = 按 AI 判定不落盘；「应改」行缺建议改法或属句群成员，要人给一手。
- **`--judged` 是防「判宽」的监视闸**：不改档漏报率 >30% 判本片复核失效。闸只管判宽，召回靠盲测兜，两个数都要看。
- **抽检人判「要改」时看理由落在哪**：落在 C1/C2/C3 才算 AI 漏判；只说「读着别扭」不算。一批里 C1/C2/C3 类漏判 ≥2 条才回去调提示词。

### 6 落盘

- **待议 = 停手**：待议条目一律跳过并报「待议 N 条未落，等确认」，答了再单独落一批。
- **越界硬校验**：findings 行号落进 `recap_boundary.json` 的回顾区间 → 中止。
- **撞旧条就地改**：目标行已有旧 finding 的，补 `cn_new` 并改 `type`，不新开条。
- 写法（字段、补行、句群）归 `docs/findings写法.md`，本步只调用它。

```bash
# 本库没有 merge（并表靠人工），也没有 --season / --ep 这种全季开关——一集一跑
python tools/land_verify.py apply <本集字幕> <改动.tsv> [-o <输出>] [--inserts <补行.tsv>]
python tools/land_verify.py verify <改前> <改后> <改动.tsv> [--inserts <补行.tsv>]
```

**`verify` 绿 ≠ 改动到位**：它只校验改动表内的条目，被并表丢掉的条目它不知道存在。三个数字一起看：findings 条数 → 并表保留数（**本库靠人工数**）→ apply 应用数。
**merge 丢弃数必须逐条看原因**，丢弃表基本等于执行方的抄写错误清单，同时就是打回证据。

### 7 盲测（每集必做，验召回不验精确）

常规复核只判「报的对不对」，验不出「报少了」。

```bash
python tools/blind_sample.py --worksheet <片.tsv> --ep-tag S0xEyy --tag 01 --segs 5 --len 10 \
    --base "<项目外的隔离根>"
```

（`--base` 必填，不给直接报错——隔离产物不许落进项目里。落在项目内也会被脚本拦下。）

两片合计 100 行、**一个 Agent 跑完**。隔离目录**绝不放候选清单**。卡片写明「这是查漏测试、重点是找全不是挑准、符合判据就报（含低置信）」。

回收后**逐条核原文，不许直接采信**，分四类记账：与我重叠 / 段首段尾截断假阳性 / 读得通但不如原文 / 真漏。

**判定走下面的「真漏处置表」，别在这一步自己拍。** 「无明显缺口」不等于零漏——E03 片 1 盲测 0 漏，整片复扫又补出 7 条，所以 0 漏只是「没找到证据」，不是「已证明干净」。

## 续一 / 续二 六步

> **本节整段只在剧库成立。** 用到的 `slice_nb_r.py` / `apply_nb_r.py` / `verify_nb_r.py` **本库一件都没有**（名字带剧型、单集，属红线里「剧专用不搬」）。本库做续一 / 续二没有工具链：要么纯手工，要么从剧库连工具一起带。下面的命令保留是为了让人知道原流程长什么样，**不是让本库照跑**。

### 1 候选门槛：只看盲测真漏数（2026-11-02 改，密度指标作废）

~~片级密度 < 2.0 就复扫~~ —— **密度这个门槛作废，不再用它判任何事。**

作废理由（实测，别再用别的话绕回来）：密度衡量的是「报了多少」，不衡量「该报的报到了没」，两个数之间没有因果关系。

| 集 | 密度 | 实际漏没漏 |
|---|---|---|
| E07 | 6.20（判了四轮之后） | 判据回归时还查出 4 条漏的 |
| E08 | 4.42（一轮判完） | 盲测 100 行真漏 0 |

**密度最高的那集漏得更多。** 因为它是四轮叠加的产物，不是判得准的证据。

**唯一门槛是第 2 步的盲测真漏数。** 先把它是什么说清，免得又走密度那条老路：

> **它是成本开关，不是质量认证。** 100 行抽到 1 条，按比例外推全片还有 5–6 条；可真实漏率 1%／百行时，抽 100 行有 37% 的概率一条都抽不到。**0 和 1 的差别常常落在抽样噪声里。**
> 拿它决定「要不要再花一次钱」可以；拿它证明「这集干净」不行。密度当年就是被当成质量证明才出的事。

处置见第 2 步之后的**真漏处置表**。

### 2 盲测

两片合计抽 100 行（片 1 按行数比例多抽），派 **1 个** Agent 独立跑，**不给候选**。四类记账与判定见下。

**抽样的底本必须是「改后」的**（2026-11-04 续二 E01 踩）。首轮判完先 apply，再重跑一次切片到本集 `复扫底本/`：

```bash
# ⚠️ slice_nb_r.py 本库没有，这行只在剧库成立；本库重切续一/续二只能手工
cd <工具目录>
python slice_nb_r.py --show <剧型代号> --ep 01 --out "../../02_工作区/通读/<剧型代号>_E01/复扫底本"
```

然后从 `复扫底本/片X.tsv` 抽。拿首轮分片直接抽会照到已经改好的行——被测方「报出」它们，白算重叠，还稀释真漏判断。续二 E01 第一次抽的 L264–L273 段正好压住已改的 0:15:04.82，整批重抽。

**抽样命令（续一 / 续二 加 `--with-rowno`，2026-11-02 起不用手搓副本）**

`blind_sample.py` 默认取首列当行号，而 续一 / 续二 分片首列是时间码。**现在加 `--with-rowno`
就行**：它会在内存里给分片插一列序号，源文件不动，`sample.tsv` 会带上这一列方便回写。
（11-02 之前的老办法是手工生成一份 `_rowno.tsv` 副本，已作废，别再手搓。）

```bash
# 正传分片（首列本来就是行号，只加 --base，不给 --with-rowno）
python tools/blind_sample.py --worksheet <片.tsv> --ep-tag S0xEyy --tag 01 --segs 5 --len 10 \
    --base "<项目外的隔离根>"

# 续一 / 续二 分片（首列是时间码）
python tools/blind_sample.py --worksheet <片.tsv> --ep-tag <剧型代号>_S0xEyy --tag 01 \
    --segs 6 --len 10 --with-rowno --base "<项目外的隔离根>/_tmp"
# 行号在中间某列时用 --ln-col N（1 起）；都不给且首列非数字时，脚本会自己找并提示
```

两片各跑一次，再把两份 `sample.tsv` 合并成一份题面（列＝片号/时间码/中文/英文）。

产物落到 `<项目外的隔离根>\<日期>_<剧>_E<集>\`，卡片写「查漏不挑准」。跑完把题面和结果**复制回** `02_工作区/通读/<剧>_E<集>/` 归档。

**组装题面前必须查污染（每集都做）**

题面目录里**每一个文件**都 grep 一遍当集的特征串——人名、专有名词、当集独有的长句、以及当集已落盘的改前／改后文本。命中任何一条，说明这份材料里藏着答案，题面作废、重做。

```bash
# 拿当集已落盘的声明里的改前串去反查题面目录
cut -f7 "02_工作区/诊断/<剧型代号>_通读E0X_<日期>.tsv" | while read -r s; do
  [ -n "$s" ] && grep -rlF "$s" "<项目外的隔离根>/<日期>_<剧>_E<集>/" && echo "↑ 污染：$s"
done
```

> 2026-11-02 踩过：把某集的三条真实答案写进判据当例子，又把判据发给被测方，被测方当场指出「泄漏的不算盲判召回」，那次回归只算半次。**判据文件是双用途的——既是执行标准也是教材，教材举例就会漏答案。** 所以判据里的例子一律用虚构句（已写进 `subtitle-read`），题面这边也要自查一遍。

**四类记账**：与我重叠 / 段首段尾截断假阳性 / 读得通但不如原文 / 真漏。

**重判 ≠ 复扫，别选错**

| 动作 | 是什么 | 什么时候用 |
|---|---|---|
| **重判** | 不给原候选，整片从头判一遍 | 判读**方向性错误**（整片只做了通顺度、根本没核英文形态）。代价最高，会把已经判对的部分一起推翻 |
| **复扫** | 带着原候选，只找没被覆盖的 | **有漏但方向没错**。默认走这条 |

判定口径（2026-11-02 二改：**按漏的量分档处置**，不再一律全片复扫）：

| 真漏数 | 处置 | 成本 |
|---|---|---|
| **首轮密度 < 1.5（判崩）** | **直接全片复扫，不看盲测结果** | 1 个 Agent |
| **0** | 收工 | — |
| **1** | **同类定向扫**：把漏的那一条的错因形态（时体／名词／限定词／句法塌陷）写成清单，交给 1 个 Agent 扫该片全文找同类。**不带原候选、不做全片逐词核** | 约全片复扫的 1/3 |
| **≥2** | **带候选全片复扫** | 1 个 Agent |
| 漏得分散、彼此矛盾、明显整片没按判据过 | **重判**，不补扫 | 最高 |

**为什么密度 <1.5 要越过盲测直接复扫**：E03 首轮密度 0.94（明显没在判），盲测抽 100 行**真漏 0**，整片复扫却补出 7 条。首轮判崩时，抽样里本来就没东西可漏，盲测的 0 是假象。
密度在这里只干**证伪**——报得极少说明没逐句看，不能说干净；报得多也不证明干净（这是它作废的理由）。两条判据分工：密度管「有没有判」，盲测管「判够了没」。

**为什么 1 条也动，但不全片复扫**：1 条真漏按比例外推是全片还藏 5–6 条，装看不见不行；但拿一次全片复扫去抓 5 条不成比例。漏通常成簇——E07 的 20 条里 14 条同属三类，只要告诉 Agent「只找这一类」，命中率比再扫一遍全片高。

**补扫之后不再抽样复验。** 这一步 2026-11-02 砍掉：补扫本身就是把全片过了一遍，再抽 40 行是重复劳动，还会把最坏情况从 4 个 Agent 拖到 5 个。扫完直接并进候选。

> 实录（E07）：片1 真漏 4 → 全片复扫补 15 条、零重复；片2 真漏 1 → 按新规走定向扫就够（当时全片复扫，多花了一半）。

口径附注（写给以后想调松门槛的人）：8 集实测真漏 **0/0/0/2/4/2/5/0**，5 次触发补扫、占 62%。**这个比例反映的是首轮判得不够全，不是门槛定高了。** 想降它得提高首轮覆盖（两遍分开派就是为这个），调松门槛只会把漏留在成品里。

### 3 收候选：合并去重（必做，别省）

一集通常出三份候选：首轮 `候选_片1/片2.tsv`、盲测补的、复扫补的。**落盘前必须并成一份**，否则同一行会被改两次，或两处改法互相打架。

- 按**时间码**去重——续一 / 续二 没有稳定行号，别拿行号做键。
- 同一时间码出现两次 → 保留首轮那条，把新增的理由并进「一句话理由」栏，**不新增行**。
- 合并后加一列 `来源`（首轮／盲测／复扫），落盘后能一眼看出判读质量。
- 密度可以顺手记一笔作参考，**但它不参与任何判定**（2026-11-02 作废，见第 1 步）。
- **判读方给的建议改法大多是半句**（E07 37 条里 12 条），合并时要把每条补成能整行替换的完整中文段。

> E07 实录：17（首轮）+ 5（盲测）+ 15（复扫）= 37 条，零重复；合并后片1 6.07、片2 4.82、整集 5.60。

### 4 预演改动

```bash
cd <工具目录>
python apply_nb_r.py --show <剧型代号> --tag "通读E0X" --rules "旧→新,旧2→新2"        # 不带 --apply 只预览
```

- 改前串不能与另一条规则的改后串首尾相接，否则撞残留断言、**整批不写盘**。两行对调时把改后串写成互不为对方改前串的措辞。
- **改后串不能是改前串的超集**（如 `他还没回来 → 他还没回来呢`），会撞 `assert old not in zh2`，整批不写盘。换措辞：`他压根还没回来`。
- **`--allow-empty-new` 管的是「改后串为空」，不是「改前串为空」**（2026-11-02 修正，旧版这句写反了）：
  - 改**前**串为空（中文段整段是空的单语行）→ `apply_nb_r.py` 直接 `sys.exit('改前串不能为空')`，**这个参数救不了，只能手改**。手改后声明里「改后中文」要写成含样式标签的整串（如 `撑着\N{\fs26…} Braced`），`verify_nb_r` 的 V2 才过。全库 NB+R 20 集这种行只有 2 处：E05 `0:15:50.78` 已手改补好；E06 `0:01:10.09` 是歌名 `"Bright Harbor" by Nora Vale`，本来就不该有中文，不动。
  - 改**后**串为空（要把中文整段删掉）→ 必须加 `--allow-empty-new`，否则脚本拒执行。
- **规则写盘前先自检**：一条规则只能有一个 `→`、改后串不含改前串、不含 ASCII 逗号（会把 `--rules` 切碎）。现成写法见 `02_工作区/诊断/apply_e07.py` 顶部的三个 `assert`。

### 5 落盘 + 对账

```bash
python apply_nb_r.py --show <剧型代号> --tag "通读E0X" --rules "旧→新" --apply
python verify_nb_r.py --tsv "../../02_工作区/诊断/<剧型代号>_通读E0X_<系统日期>.tsv"
python verify_nb_r.py --fitness
```

- 声明文件名带**系统日期**，不是开工日期。
- **分批 apply 时，多批声明要合并成一份、用第一批的基线统一验一次**。各批单独验会互相报 V6「声明外被改」，属正常现象不是错。

## 硬约束

- **改的人不验，验的人不改**：写候选的不做最终验收，验收的不写候选。
- **本 skill 不改判定档位**。档位不对退回去让对方重判，别自己改档落盘。
- **不动其他集、其他剧的文件**。
- **不改别人的库（`日常杂活` / `是大臣系列`）里的文档**，尤其台账。发现写简报「顺带发现」。
- **不新建统计工具**；缺工具写简报说要什么。
- **会报错的检查才值得信**：新增或改动任何检查后，先故意造一个错看它认不认。
