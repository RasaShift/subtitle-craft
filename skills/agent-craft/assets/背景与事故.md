# 背景与事故——各条规矩的来历

> 本文件只收**叙事与溯源**（规矩为什么这么定、当时怎么踩的坑），不收规矩原文——规矩以技能正文为准，改规矩不用动这里。
> 已做脱敏：项目名换代号（甲剧 / 乙剧）、库名换角色（环境库 / 项目库）、日期与数字保留原值。**数字不脱敏是有意的**——「某项目有过这问题」说服不了人，「八步各 2 分钟连跑 40 分钟」能。

## 开工申报规则的演变（2026-10-27 → 11-02）

- **2026-10-27**：立「预计超 10 分钟或跨台账项，开工前报耗时等指令」，写在通用纪律里。
- **当天即违反**：批了两项小活却连跑 40 分钟无中途汇报。
- **2026-10-31**：同款错误再犯两次（各跑 40 分钟）。诊断：规矩位置太泛（放在通用纪律），而判断发生在「这一单要不要动手」那一刻，没有固定触发点、也没有任何检查会发现违规 → 挪进流水线第 1 步「领需求」变成产出物。同日尝试装工具钩子做外层强制，实测自建插件钩子不被加载（平台只信官方来源），放弃。
- **2026-11-02 审计**：发现「规模三问」与「本单预算」是两张重叠报表；且「报完等不等」新老版本打架。用户用四道情境题拍板：等不等只看**可逆性**，不看快慢——不可逆一律等（不设规模下限）、链条总和超 15 分钟等、可逆小活直接干；「超 10 分钟报备」退役，15 分钟只用于链条总和。详见 `回归_开工申报.md`。

## 交接文档规矩的演变（2026-10-30 → 11-02）

- **2026-10-30**：当天违反一次——把「收工」当成要交接，写了交接文档。立规矩：「收工」≠「交接」。
- **2026-11-01**：补反向——该交接时不交也是错：交接文档是唯一能把上下文重置成本压下来的降本手段，估算下一件活超 ~50k 就该写该切。
- **2026-11-02 审计**：两条方向相反、且「50k 该写」与「自己判断不算」直接矛盾 → 收敛成「可提议、点头才写」：提议权在模型、决定权在用户。

## 积分认知的两次修正（2026-11-01 / 11-07）

**第一次（11-01）**：先按「积分 ≈ 0.5～0.8 × 分钟」建了账（三集对照表），当天就被推翻：砍子 Agent 8→3、工时 17→15 分，积分只降 12%。真相是计费按 token，主会话每轮重发全部历史是大头，切会话是唯一的数量级杠杆。教训：**短活的换算系数外推到长会话必然失真，别拿分钟假装算积分。**

**第二次（11-07）**：由上一条推出的「子 Agent 只占 2%」又被推翻，而且是同一个人的同一份数据。那个算法是「Agent token 80k ÷ 全会话 4.58M ≈ 2%」——可**分母里已经含着「读这 8 个 Agent 结论」所花的轮次**，等于先把 Agent 的账记在主会话名下，再拿主会话当分母，用结果证明原因不存在。同一份实测里两个数当场打脸：8 个 Agent 的活跑了 45 轮，3 个 Agent 的活跑了 25 轮，**轮数降 44%**，两者是同向变化的；再加 Agent 时是双向涨——多一份完整输入，结论还进每轮重发。

教训两层：① 说某个成分「只占 N%」时，先问**分母里有没有它自己引发的开销**；② **积分是结果不是计划**——事前估出来的那个数字没有可核来源，报它只是制造「算过了」的错觉。所以申报四要素的第三项换成了「上下文会不会过 50k」，积分挪到收尾对账，那时它是实测值。

## 校对自验反例的出处（2026-10-28）

当晚两次实证：① 并句门槛只验正向，一条真错位被吞；② 单测 `assertIn('分段不同', 全表)` 全绿，实际命中的是空组，目标行压根没判对。由此立「验双向 + 断言定位到目标对象」。

## 交付物呈现规矩的由来（2026-11-04）

- **现象**：一天干完一整单（20+ 次写文件、跨 4 个文件、新建一整套目录），收尾只写了文字清单，从头到尾没把文件递出来。用户反馈「想找生成了啥，还得自己翻」。
- **诊断：不是忘，是没规矩。** 当天反查全部 9 个技能和参考资料目录，「呈现」这个动作一次都没出现过——所以每个新会话都没有依据，只能靠临场想起，必然时灵时不灵。
- **为什么不上工具**：钩子路线 2026-10-31 已实测不可用。这条只能落在规矩上，但选了**违约看得见**的形态：卡片在不在，双方一眼能判，不像抽象条款要等下次翻目录才暴露。
- **收窄的经过**：用户明确「不是所有动过的都要呈现，重要的、值得我看的、需要我看的才呈现」。判据按五类收（要拍板 / 要验收 / 要反复查 / 结论会被引用 / 他要跑的工具），反列五类不呈，并加「上限 5 个」——防止从「不递」反弹成「全递」，噪声卡片和没卡片一样费时间。
- **覆盖面更正**：原判「技能只在本项目生效」是错的。实况是软件级技能目录下有一条软链指向项目库里的真身，所以各库都能加载。错因：用 glob 数技能目录，**符号链接目录不被跟随**，只数到真实目录就下了否定结论，而正确信息当时就写在记忆文件里。教训：**判断「某技能是否全局」必须 `ls -la` 看链接，glob 数不出来。**
