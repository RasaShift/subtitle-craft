# 清稿 · 规则清单

> **最后更新：2026-11-08** · 主文档 `docs/工序-清稿.md` 定「什么算机械」；这里逐条列「有哪些规则、改法唯一不唯一、谁来落」。
> 规则会一直加，所以从主文档拆出来独立成表。**加一条规则就在这里加一行。**
> 示例一律自造，不出现剧名。

## 一、先分两层，别混着说

| 层 | 改什么 | 粒度 | 谁落 |
|---|---|---|---|
| **文本层** | 每条字幕的中文字符串 | 一条 | `tools/land_verify.py`（条号 + 旧文本双锚点，只换中文段） |
| **文件层** | 整份文件的结构与样式：编码、画布坐标、样式表、字体字号、描边底纹、样式引用 | 一份 | `tools/style_normalize.py`（v1：头部 / 样式表 / 坐标与字号换算 / 引用断言 / `MF6`；`MF8` 只报不改） |

文件层为什么不塞进 `land_verify`：它的锚点是「条号 + 旧文本」，样式改动没有条号；它解析的是 Dialogue 那一行的文本字段，`[V4+ Styles]` 和文件头根本不在它的视野里。两件事用一件工具做，迟早互相绑死。（补行 2026-11-06 已能落，但那是**照声明插一整条 Dialogue**，不是「让文本工具顺手改样式」——两回事。）

## 二、文本层规则

| # | 规则 | 机器能做什么 | 改法唯一？ | 落 |
|---|---|---|---|---|
| MT1 | 译名错写（词表里已登记的错写法） | 三列词表精确替换，最长匹配优先 | 唯一（单字错写只报不改；同键冲突拒绝加载） | 能落 |
| MT2 | 内联标签残留 `<font>` / `<i>` / `<b>` | 数得出、删得掉，正文不动 | 唯一（删标签） | 能落 |
| MT3 | 半角标点贴中文、中英之间缺空格 | 换全角 + 补一个半角空格 | 唯一（基准见下） | 能落 |
| MT4 | 花括号残留 `{...}` | 空花括号删；带参数的报出来 | **分两种**：空标签可删；带参数的要先看是不是样式引用 | 能落一半（只落「删空」） |
| MT5 | 单词粘连（超 16 字符） | 只报数 | **不唯一**（两个人拆得不一样）→ 退回审稿 | —— |
| MT6 | 金额符号被吃（`?\d`） | 只报数 | **不唯一**（`?8` 是 £ 还是 $ 要看片源）→ 退回对稿 / 审稿 | —— |

前三行的落地工具是 `tools/text_scan.py`：命中即出清单，清单直接喂 `land_verify apply`。
**它只认 ASS**（文本层排在文件层之后，那时输入已经是 ASS），SRT 直接拒。

**MT3 的基准**（2026-11-07 定，此前只写「有基准间距」，等于没写）：

| 情形 | 怎么改 | 为什么 |
|---|---|---|
| 半角 `, . ; : ? !` 前后都是中文（或后面是行尾 / 空格） | 换全角 | 中文句子用半角问号，观众看到的是排版错误 |
| 标点任一侧是数字 | 不动 | 千分位 `21,793`、小数点、时间码都长这样，换了就是一串新错 |
| 中文 ↔ **拉丁字母** 相邻 | 中间补一个半角空格 | `我用BBC的东西` → `我用 BBC 的东西` |
| 中文 ↔ **数字** 相邻 | 不动 | `2万1千793票`、`第487卷` 是中文常规写法，补空格反而错 |
| 已经有空格 | 不重复补 | 一对相邻字符里前一个是空格时不触发 |

**扫描器不碰的三种条**（进「需人判」表，一个字都不动）：中文里有 `\N` 折行（整条替换会压成一行）、
中文里有带参数的花括号（`{\c&Hd19640&}` 这类，删了颜色会静默变默认）、中文里有不认识的尖括号。


**MT1 的三条纪律**：① 按最长匹配，两字以下的错写法只报不改（短词当子串会误伤别的词）；② 同一段文本被长短两个错写法同时命中时取长的（`奥德曼` 优先于 `奥德`），短的自动让位；③ 表里同一个错写法登记两次，工具应拒绝加载，不许挑一个。

**候选怎么来**：`tools/term_candidates.py` 出底稿（只挑候选、不给译法），人定译；流程见 `examples/新剧接入.md` 第 5 节（攒词表），格式照 `examples/词表样例.tsv`。

## 三、文件层规则（判据从旧库实例提炼，本库有 `style_normalize.py` 可执行）

**前提**：文件层的「统一成什么」不是天生唯一解，必须先有一份**样式基准**——一个模板文件或一张参数表。没有基准，两个人对「字号多大」会给出两个答案，那就不是清稿。

**现状**：`tools/style_normalize.py`（v1）做 MF1–MF6 与 MF7 断言；**`MF8` 只报不改**。MF6 要显式加 `--f6`，不给开关就一个标签都不动。它有两个显式开关，都是「不许工具自己猜」的位置：`--from-res`（原文件 PlayRes 是 0×0 时声明它原本的坐标系）、`--style-map`（旧样式名对不上基准时给出对应关系，否则整片静默回落 Default）。

| # | 规则 | 要检查什么 | 改法唯一？ |
|---|---|---|---|
| MF1 | 编码 / BOM / 换行符 | 全库一致。旧库成品统一 UTF-8 BOM + CRLF；本库自己的文档是 LF——**基准要显式写下来**，别跟着手边文件走 | 唯一（有基准） |
| MF2 | 画布坐标 PlayRes | **宽高比 = 视频显示宽高比，纵向 = 交付高度 1080**：16:9 写 1920×1080，4:3 写 1440×1080，2.35:1 写 2538×1080；必须非 0。**别按片源像素分辨率写**——PAL 720×576 照抄工具不拒：它按 1.25（实际 DAR 1.333）算横向，纵向又把字号描边缩到一半（实测 79→42、描边 2→1），**两处都错且无声**；补成 768×576 只是比例对了，纵向照样缩一半。片源低于 1080 就 upscale 交付。这条同时防 4:3 片源被写成 16:9 而横向拉伸。旧库成品是 384×288（4:3）配 1080p 宽屏，属历史遗留，不是范本。**这条的管辖范围不只清稿**——任何「造画布」或「改画布」的工具都受它约束（`build_base --video`、`style_normalize --base`），写那类工具前必须先读这一行 | 唯一（按显示宽高比 + 交付高度） |
| MF3 | 样式表的条数 / 顺序 / 命名 | 正式样式固定几条、顺序固定。旧库把八季四套面孔（S01–S03/S05–S07 一种、S04 一种、S08 一种）收成 3 条 | 唯一（有预设） |
| MF4 | 字体族 / 字号 / 字重 | 中英字号比。旧库：中文 21 加粗、英文 14 常规，1.5 : 1，英文不抢中文 | 唯一（有预设） |
| MF5 | 描边 / 阴影 / 底纹 / 模糊 | 字色、描边、阴影、字号、边距**按选定方案整套来**（`examples/样式预设/` 三套：A 现代 · B 经典 · C 老电视），不再写死「边 2 影 1」。`\blur` 过大会把描边糊成灰晕（旧库实测 0.5 可用，5 以上过强） | 有预设，**选哪档人定** |
| MF6 | 内联标签 → 样式引用 | 把每条里成串的字体/字号/颜色标签换成单个 `{\rEnglish}`（旧库 8.3 万处） | 能落（`--f6`；必须有样式基准，见下节） |
| MF7 | 正文引用的样式必须已声明 | 样式一改名，正文里所有 `{\rX}` 会**静默回落 Default**，不报错 | 这是断言，不是改动 |
| MF8 | 底纹条 / 水印块残留 | 「可见字符只剩方块字符」**且**「同刻还有别的非空 Dialogue 行」才删（旧库 49 条；`--f8`，默认关） | 条件唯一，但要两条同时成立 |

### MF6 具体怎么换（内联标签 → 样式引用）

**先定一句**：MF6 只在**有样式基准**时动文件；没有基准就只出清单、一个字节不改。禁区 1 管的就是这条——别把「没定就按原来的来」理解成「跑一遍但保留参数」，那是白跑一趟还动了文件。

**什么算「英文段起点」**（三条同时成立才算）：

| 条件 | 判据 | 为什么这样定 |
|---|---|---|
| 位置 | 在 `\N` 之后 | 同一行里中文在前、英文在后，是本库与外部素材的共同写法 |
| 形态 | 紧跟一个或多个 `{...}` 块，块内只有样式类参数（`\fn` `\fs` `\b` `\i` `\c` `\1c` `\3c` `\4c` `\bord` `\shad`） | 这一串本质是「给英文配的一套内联样式」，正是要被样式引用替掉的东西 |
| 内容 | 块序列之后，「中文」与「拉丁字母」谁先出现——先出现字母才算；中间允许夹 `- ` 这类符号 | 后接中文的是**中文折行**，不是英文段；而英文常以 `- ` 开头（`- What do you want?`），只认「紧跟字母」会漏掉一整类（实测 43 条） |

三条不全 → 不算，MF6 不碰。典型反例：`-你想要什么 - What do you want?` 英文没有标签、直接空格接在后面，那是结构问题不是标签问题，归审稿。

**换的时候参数怎么处理**（三层，2026-11-07 定）：

| 情形 | 怎么办 |
|---|---|
| **有基准**（该剧已选定 A/B/C 预设或自有基准） | 整串换成 `{\rEnglish}`，原参数**全部丢弃**，字号 / 字体 / 颜色一律由基准的 `English` 样式接住。不挑着留——「英文比中文小一号」这类比例基准里已经配好，自己再留一份就成了两套数打架 |
| **没基准** | **不改文件**，只输出「这条可以统一成 `{\rEnglish}`」的清单，等人定基准 |
| **原样本身有问题** | 报出来让人议，**不许换**。见下 |

「原样有问题」是两类，都不许换：

1. **块里有定位 / 动画参数**（`\pos` `\move` `\org` `\clip` `\an` `\fad` `\blur` `\fscx` `\fscy`）。这些基准不覆盖，换成 `{\rEnglish}` 等于把它们抹掉，画面会挪位或少了淡入。特效条（`Mark` 样式）基本都落这一类。
2. **基准里没有 `English` 这条样式**。换了之后 `{\rEnglish}` 会静默回落 Default，正是 MF7 要断言的那件事。这种情况直接拒绝并说明，不许挑 Default 顶上。

**前置断言**：MF6 跑在 MF3（样式表换基准）之后，届时 `English` 必须已在样式表里声明。不满足就停，理由同 MF7。

**量**（《嗜血法医》某一集，`--f6` 已落地）：749 条对白里 **746 条换成 `{\rEnglish}`**，剩 3 条落「需人判」——2 条开场声明带 `\move`，1 条纯中文声明含折行。同一集再跑文本层，「需人判」从 **749 条降到 3 条**、可机改 1 条（`然后?` → `然后？`）。
本库自己的写法（`\N{\rEnglish}`）跑一遍是 0 处可换：合规的直接跳过，不产生噪声。

**落地口径**：`style_normalize.py apply ... --f6`，默认关。复算也要带 `--f6`，否则会按「标签数 1→0」逐条报红（一条一个假红）。

### MF8 具体怎么删（底纹条）

**它是什么**：一个 `■` 字符，配 `\alpha&H9F&`（半透明）+ `\c&H000000&`（黑）+ `\fscx600`（横向拉伸）+ `\an2`（底部居中）——署名文字背后的黑底。**只删文字不删它，画面上留一个悬浮黑块**。旧库 49 条全是这个形态。

**两条同时成立才删**：

| 条件 | 判据 | 为什么这样定 |
|---|---|---|
| 形态 | 去掉 `{...}` 后可见字符非空、且**只由方块字符组成** | 底纹条只有一个字符，`\fscx600` 把它拉成一条。**别加长度阈值**——11-08 那次写「长度 ≥6」，49 条一条没扫到，不是剧里没有 |
| 上下文 | **同一起始时间还有别的 Dialogue 行，且那行可见字符非空** | 防「正文里孤立的方块行」被误删：没别的行陪着的时候删了就是凭空少一句 |

**为什么不是「同刻有署名行被删」**：那是**事后**视角——删署名行时顺手把底纹条删了。工具运行时看不到「将被删」，只能看当前文件。实测旧库 49 条里这一条只有 **41 条（83.7%）**成立，容差放到 2 秒也不变；换成「同刻有别的非空行」后 **49/49 全成立、0 条孤单**（2026-11-09，法医 S01–S08 原稿 96 份 + 定稿基线 96 份对扫）。

**验过什么**：原稿命中 **49 条**（S06 32 / S07 5 / S08 12），与旧库报告一字不差；定稿基线 **0 条**残留；《是大臣》38 份参照 **0 条**（不误改）。端到端跑 S06E01：删 4 条、875 → 871 条、复算带 `--f8` 通过；不带就报「条数变了」，说明折算是必要的、不是把检查弄松了。

**落地口径**：`style_normalize.py apply ... --f8`，默认关。复算同样要带 `--f8`，否则会按「条数变了」报红。

**不在范围内**：片头 `\p1` 矢量绘制的台标（法医 S07E08–E12 有 20 条，定稿里保留着）——那是图形不是底纹条，删了会少一个图标。

## 四、文件层三条防呆（必须内置进工具，不写成提醒）
1. **PlayRes 的硬约束是比例，不是那个数字。** 0×0 必须补；宽高比必须等于视频（1080p 就是 16:9）。改画布等于改坐标系，坐标、字号、边距、描边都要同步按轴缩放，漏一样就整片错位。**造画布的工具同样受这条约束**——`build_base` 第一版把「源 PlayRes 是 0」按规范补成 384×288，等于原样保留 4:3，配 16:9 片源就是拉伸 33%，正是这条要防的。
2. **样式名一改，全部 `{\rX}` 静默回落 Default。** 改完必须断言「正文引用的每个 Style 都在样式表里声明过」。
3. **换字体后字宽会变**，`\pos` 定点的画面文字可能偏移。旧库按「字数 × 字号」估算了最宽的几条，**没做画面截图**——这条至今是已知不足，不是已验证。

### MF2 具体怎么改（改画布 = 改坐标系）

| 对象 | 怎么变 |
|---|---|
| `\pos` `\move` `\org` `\clip` 的坐标 | x 乘 W'/W，y 乘 H'/H |
| 样式里的字号、内联 `\fs` | 乘 H'/H（保持视觉高度） |
| `MarginL` / `MarginR` / `MarginV` | 由左到右按 x / x / y 各自缩放 |
| `\bord` `\shad` `\blur` | 乘 H'/H |
| `\an` `\fscx` `\fscy` | 不动（锚点与百分比语义不变） |

两种情形必须分开，别混成一条：

- **等比换画布**（384×288 → 768×576，比例不变）：纯机械，渲染结果完全等价，能写成断言。
- **改比例**（4:3 → 16:9，把错的改对）：改法唯一，但**结果会变**——原来被横向拉宽的字会恢复正常宽度，必须截一帧让人看一眼，不能只跑数字。

**基准按片源的显示宽高比落一次，纵向固定 1080**：预设母版写 1080p（数值总得有个地方写），每部剧开工时用 `base --video <按 DAR 算出的分辨率>` 换一份本项目专用的——16:9 写 1920×1080、4:3 写 1440×1080、2.35:1 写 2538×1080。纵向跟母版同高，文件里写 72、画面里就是 72（交付 1080 时渲染 1:1），调样式不用自己乘一次、量截图也对得上号。**别按片源的像素分辨率落**：PAL 720×576 写成 `720x576`，工具不拒——横向按 1.25（实际 DAR 1.333）算错，纵向再把字号描边缩到一半（实测 79→42、描边 2→1），两处都错且无声；补成 `768x576` 只是横向对了，纵向照样缩一半。剧库两起换算事故就是这么来的。

## 五、文件层先于文本层

```
文件层（结构 / 样式）→ 文本层（逐条字符）→ 对稿 → 审稿
```

理由：文件层会重写整行（引用、标签），但**不动文本内容**，所以它跑完，文本层的锚点（条号 + 旧文本）依然有效；反过来先改文本，样式器仍要保留文本并重新对一遍账，纯属多一道。

## 六、禁区

1. **没有样式基准就不许动文件层**。那不是统一，是把四种面孔变成第五种。
2. **不许用「全库替换」改样式名**：样式名是引用键，改它必须同时改所有 `{\rX}`。
3. **文件层的改动也要出清单**（哪一项、旧值、新值），不许跑完就完了——不然下次没人说得清这一版样式是谁定的。
