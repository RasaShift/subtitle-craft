# 新剧怎么接进来

> 拿一部没碰过的剧，从零到能判，走 12 步（第 0 步盘家底、第 1 步建目录，之后十步按流程跑）。每步都有验收口径，不过就别往下走。
> 这里不放任何真实台词或成品——示例一律用自造句子。

## 0. 先看手上有什么、要什么

| 手上的东西 | 走哪条 |
|---|---|
| **一份**中英双语文件（.ass / .srt 都行） | 跳过第 2、4 步；配对表到第 8 步一起出——第 6 步的 `--f6` 才拆得开它 |
| 中文一份 + 英文一份（两个文件） | 十二步全跑 |
| 只有中文 | 跳过第 4 步；对稿只判得了 T2 的一半和 T3，判不了「漏译」，审稿判不了「译法对不对」 |
| 再加一份第三方参照 | 对稿能交叉验「漏译」，但**本库没有专用工具**，靠人比 |

**别急着凑齐**。少一份就少判一档，工具会明说判不了什么，不会假装判过了。**双语 SRT 也能进，但第 6 步起只认 ASS**——先用外部工具转成 ASS（本库没有这个转换器，`build_base` 要的是两份单语 SRT），不然文件层进不去。**文件只是这一半**：动手前还得问清「你要什么」——八问见 `docs/接活单.md`，不问就定档，等于替用户猜档位。

## 1. 准备目录

**先认清两个根**：工具在一个库，数据在另一个库。下文所有命令都在**工具库根**执行；`01_源字幕` / `02_工作区` / `03_成品` 是**简写**，实际敲的时候换成你剧库的完整路径（照下一段那条例子），**不换就会指到工具库自己的目录**。

```
字幕精校通用库\       ← 命令都在这儿执行（tools\ 是 22 件工具真身，只此一份）
<你的剧库>\           ← 数据在这儿，不用往里放 tools\
├── 01_源字幕\        原始字幕（只读，别在这上面改）
├── 02_工作区\        工具跑出来的表，可删可重跑
└── 03_成品\          改好的字幕，这一份才交出去
```

完整一条：`cd E:\Workedbuddy\字幕精校通用库` 之后跑 `python tools/subtitle_probe.py ..\我的新剧\01_源字幕 --tsv ..\我的新剧\02_工作区\体检.tsv`。

源字幕是回退基准、工作区是一次性产物、成品是交付物，混在一起迟早分不清底本。**编号与 `docs/工序-*-手册.md` 一致**，对不上就是路径写错了。

## 2. 造底本（手上只有两份 SRT 才需要）

还没有 ASS 成品、只有简 / 英两份 SRT 时，先合出一份双语 ASS；已有成品的剧跳过这节。

```bash
python tools/build_base.py 01_源字幕/X.简.srt 01_源字幕/X.英.srt -o 02_工作区/X.base.ass \
    --style-from <参照样式.ass> --video 1920x1080
```

· **`--style-from` 抄谁**：用 `examples/样式预设/` 那三套（`A_现代` / `B_经典` / `C_老电视`，第 6 步也是它们），拿不准选 `B_经典`。**手上没有现成成品也能跑**——把 `--style-from` 和 `--video` 两个参数一起删掉就用占位样式（1920×1080 / 微软雅黑），那只能当草稿。
· **`--video` 怎么定**：先问片源。`片源.mkv` 放哪都行，这步只读分辨率、不写文件。**手上只有字幕、没有片源就不给这个参数**——画布沿用源、不换算，到第 6 步统一处理。

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,display_aspect_ratio \
  -of default=noprint_wrappers=1 片源.mkv
```

看 `display_aspect_ratio`：16:9（1.78）写 `--video 1920x1080`，4:3（1.33，1980s 剧常见）写 `--video 1440x1080`。**别照着参照字幕的 PlayRes 抄**——老库那批 384×288 配 16:9 片源，字是横向拉长的。

**没装 ffprobe 也不卡**：播放器打开看一眼画面，宽屏就是 16:9、接近正方形就是 4:3，判的是同一件事，比查参数还快。本库工具是纯标准库，ffprobe 只在这一次取参数时顺手用一下，不是依赖。
· **画布不跟着抄**。给了 `--video` 就按轴换（字号 / 描边 / 纵边距走 y，横边距走 x）；不给就沿用源画布并在报告里说「可能拉伸」。4:3 的样式配 16:9 片源，字会被横向拉长——老库就是这么错的，别照抄。缺 `English` 样式的从 `Default` 复制一条、字号缩到 75%。抄来的样式先看一眼再当成品。
· **时间跟中文轨，不自动延长**。英文比中文长半秒以上的会列出来——延长会压到下一条，要不要改是人看了再定。

## 3. 体检

```bash
python tools/subtitle_probe.py 01_源字幕 --tsv 02_工作区/体检.tsv
```

看四个数：条数、坏块、坏时长、重叠。**坏块和坏时长为 0 就能往下走**；工具还会另判「不合格」，那来自短条（`<0.8s`）、超长条、font 残留这类——记一笔不必当场修，font 残留就是内联标签，第 6 步的文件层会换掉。

## 4. 对齐（只有中文、或手上一份双语文件的，跳过）

```bash
python tools/align_bilingual.py 01_源字幕/X.简.srt 01_源字幕/X.英.srt --tsv 02_工作区/X.align.tsv
```

**这一步只干一件事：确认两份文件是同一集、配套。** 手上一份双语文件时没有「两份」可配，跳过——配对表到第 8 步一起出。

看报告末尾三行（**配错集不报错，只会安静给出一张看着正常的表，所以必须读**）：

- `配对率` 低于 95% → 两份不是同一集，或时间轴整体偏移（先校偏移，别急着判）
- `真漏 N 条` 必须为 0。不为 0 就是真缺对白，不是标题卡
- `文本长度相关 r` 低于 0.35 → 两份文件疑似不配套

## 5. 攒词表（放在清稿之前——它靠词表才跑得动译名）

```bash
python tools/term_candidates.py 01_源字幕 --min 2 --tsv 02_工作区/词表候选.tsv
```

底稿是 **7 列**（候选 / 次数 / 首现 / 型 + 三列留空），**不是词表**。手工做成 **4 列**：`原文 / 规定译法 / 已见错写法 / 备注`（照 `examples/词表样例.tsv`），落 `02_工作区/词表.tsv`，不进本库不进 git。**译法从中文实文里查**，别照英文字面编。

**只留会反复出现的专名**（`--min 2` 已在挡），再合并同一个人的不同写法：昵称与全名是两条（`Max` / `Maxwell`），三词以上的长词则在底稿里只剩碎片（中间那个词它认不出）。一个概念只填一个规定译法；成品里写成两种的，把错的那个填进「已见错写法」，两种都合法的写进「备注」别硬压——压平的后果是每次都报假红。

**原文有值、规定译法空着，`--term` 会整批报错**，所以宁可填错也别留空。

## 6. 清稿·文件层（先跑这一层：它重写整行但不动文本，文本锚点还有效；反过来先改文本，就得再对一遍账）

编码、画布、样式表、字体字号、描边，统一到一份**基准**。判据在 `docs/工序-清稿-规则清单.md` 第一节。

**先选一套样式、再按片源分辨率落基准**：`examples/样式预设/` 有 A 现代 / B 经典 / C 老电视三套（含字号、颜色、描边、边距，带 `样张.png`），拿不准选 B。**基准只是起点，不是标准答案**——同一季内一致即可。

```bash
# 4:3 的剧（1980s 老剧）：从库里的 16:9 样例换算出 4:3 的基准
python tools/style_normalize.py base examples/样式预设/B_经典.ass --video 1440x1080 -o 02_工作区/基准.ass
# 16:9 的剧把 --video 换成 1920x1080；没片源也写 1920x1080（用母版、不换算），别猜 4:3
# <字幕.ass> = 第 2 步造的 X.base.ass；手上一份双语文件的，直接写原 ASS
python tools/style_normalize.py check <字幕.ass> --video 1440x1080 --base 02_工作区/基准.ass
# --f6 是 MF6：把对白行里的 {\fn黑体} 换成 {\rEnglish} 样式引用
python tools/style_normalize.py apply <字幕.ass> --base 02_工作区/基准.ass --f6 -o 02_工作区/X.styled.ass
```

**基准的画布要等于片源的实际分辨率**（720p 就 1280×720，1080p 就 1920×1080，4K 就 3840×2160），比例还得等于显示宽高比，否则字会被拉宽。`base` 子命令干的就是这件事：改 PlayRes，字号与纵边距按 y 缩、横边距按 x 缩，其余照抄。别手写脚本改——`build_base` 第一版就是这么错的。原文件 PlayRes 是 `0×0` 就用 `--from-res` 声明；样式名和基准对不上就用 `--style-map 旧名=新名`，**带星号的 `*Default` 也算对不上**（基准里叫 `Default`）——不给工具直接拒，并把对不上的样式名和条数列出来，猜错了没人看得出来。

**画布比例一变，字形宽度就跟着变**——`apply` 会 WARN 提醒「必须截一帧人看」，但**本库没有截帧工具**，用播放器打开成品对着片源看一眼就行。（没有片源时这条只能跳过，记一笔「画布未经片源核对」。）

## 7. 清稿·文本层

规则能说清「改成什么」的错，命中即改，不逐条判。判据在 `docs/工序-清稿.md`，每条规则的改法基准在 `docs/工序-清稿-规则清单.md` 第二节。

**先扫，命中的出清单**：

```bash
python tools/text_scan.py 02_工作区/X.styled.ass --term 02_工作区/词表.tsv \
    --tsv 02_工作区/X.mech.tsv --report 02_工作区/X.需人判.tsv
```

它做四件事：词表错写法替换、删 HTML 标签、半角标点换全角 + 中英之间补空格、删空花括号。
**说不清的它一律不动**，只列进 `X.需人判.tsv`——中文有 `\N` 折行、带参数的花括号（`{\c&H..&}` 这类）、不认识的尖括号。
那张表是**四列 `no / rule / 说明 / 当前文本`**，要人看过：确认该改的，按 `no / 旧文本 / 新文本` 三列加进 `X.mech.tsv`（它共五列，后两列 `rule` / `note` 可空）。
**只认 ASS**：文本层排在文件层之后，那时输入已经是 ASS，给 SRT 会直接拒。

**再落地**：

```bash
python tools/land_verify.py apply  <字幕> 02_工作区/X.mech.tsv -o 02_工作区/X.mech.ass
python tools/land_verify.py verify <字幕> 02_工作区/X.mech.ass 02_工作区/X.mech.tsv
```

两个数必须对上：**实改数 = 声明数**、**跳过 0**。跳过不为 0 就是锚点没对上，别当成「大部分改成了」。
**一条字幕只许在清单里出现一行**——两行改同一条会互相覆盖。**2026-11 起工具直接拒（退出码 2）**，不会再出现「覆盖了、复算还全绿」那种静默通过；但别拿它当兜底，同一条只写一行是你自己的责任。

**整句漏译要补一行，另给一张补行表**（六列 `start / end / cn / en / after_no / style`）：

```bash
python tools/land_verify.py apply <字幕> 02_工作区/X.all.tsv --inserts 02_工作区/X.ins.tsv -o 03_成品/X.ass
```

插在哪**由 `start` 在时间轴上算**，`after_no` 填了就核对（对不上直接退出码 2）——别拿 after_no 当位置用，老库就是在这上面出过「19:31 后面跟着 19:06」的跳行。新行样式照抄相邻那条，歌词补行在 `style` 里点名。只支持 ASS。

## 8. 对稿

```bash
# 清稿改过中文了，配对表必须先重建（对稿只读表、不读字幕）——不管哪种素材，都在这儿出
python tools/bilingual_pairs.py 02_工作区/X.mech.ass --tsv 02_工作区/X.align2.tsv
python tools/triage_diff.py 02_工作区/X.align2.tsv --tsv 02_工作区/X.triage.tsv
```

出的是**候选**，不是结论。**只有中文的素材英文列是空的，这时只判得了 T2 的一半和 T3，T1 判不了——那个 0 不是「一条没漏」。** 判据在 `docs/工序-对稿.md`：

- `T1 漏译` → 补一行
- `T2 误译` → 改这一行
- `T3 表述差异` → 不动，登记
- `T? 无法判定` → 交人

**工具挑的只是嫌疑**，语义要人定。有词表就加 `--term 词表.tsv`，能多查一条术语——但 DR5 只认单词不认短语边界（`Prime Minister` 会被当成 `Minister` 报假红），这类先排除再定案。

**T1 要补的行回第 7 步**（补行表 `X.ins.tsv` 的用法在那里），补完重跑第 7 步落地、再重建配对表看一遍。DR5 抓到真术语不符也一样——**回第 5 步把错写法补进词表再重跑**。词表不是一次填完的，就是这么一轮轮补起来的。

## 9. 定档（决定这一集读多深）

判据在 `docs/工序-审稿.md` 第 3 节。三条信号按序用：

1. **来源**：机翻 / 没人校对过 → 直接全量，别抽样，也别指望它好；
2. **抽 40 条**（片头到片尾等距切三段，前 14 / 中 13 / 后 13 凑满 40，段内随机起点取连续条）：**出现 1 条硬伤就转全量**；抽到 0 条只能记「未发现硬伤」，不许记「质量好」；
3. **对稿候选数**：多 → 全量；少 **不作证据**（对稿只有几条粗规则，候选少不等于翻译好）。

两档：**全量**（逐条读，约 2.8 小时一集）／**关键点**（只核否定、数字金额年代、既成事实、人物关系，约 20–40 分钟）。

结论写剧库工作区的 `定档.md` 三行：来源 / 抽样结果 / 档位（演练期落演练目录，别硬找 `02_`）。**不写这三行，后面没法声明「这集读完了」。**

## 10. 审稿（按档执行，这一步没有工具）

前两步都建在「有一份能比的文本」上。这一道读的是中文自己：**字都对、话也通、意思偏了半格**。判据在 `docs/工序-审稿.md`（条目在 `-判据.md`），机判项为零，全靠人／模型读。

**按上一步定的档执行**：全量档一集切两片，照必查顺序走（否定词 → 时体 → 主客 → 数字／年代／金额 → 专名与术语 → 「既成事实」→ 整句完整性 → 中文通不通 → 话轮标记）；关键点档只核那四条，**并要在清单里写明是哪一档**。

产出前三列固定（`no` / `old` / `new`），后附 `rule`（`C1.4` 这类编号）/ `evidence` / `source` / `stage=read`。**说不出依据编号的，就是没判据**，别写进清单。

只做前两步会漏掉什么：老库有实例——S03 只做了清稿和对稿，63 处改动全是译名和拼写，**一条错译都没查出来**。

## 11. 验收（这几条不过，别往下一步铺量）

**先跑机器能判的那一半**：

```bash
python tools/accept.py <改前.ass> <改后.ass> [--changes 02_工作区/X.all.tsv] [--inserts 02_工作区/X.ins.tsv] [--stage 02_工作区/定档.md]
```

一条命令报出条数 / 对白行 / BOM / 改动数 / 补行位置 / 落盘密度 / 定档痕迹；**有 ✗ 就退出码 1**，非 0 即不过。下面五条是机器判不了、必须人看的部分：

1. 单集跑通，该出的表都出来了（体检 / 配对 / 词表 / 对稿候选 / 清稿清单 / 审稿清单）
2. **落地复算两个数对上**：实改 = 声明、多改 0、跳过 0。跳过不为 0 就是锚点在漂
3. 抽 20 条候选人工复核，**假红率 = 判为误报的条数 ÷ 这 20 条**（不是 ÷ 工具命中数，两种算法结论可能相反）；超过一半说明规则不适合这部剧
4. 拿同一集重跑一遍，结果完全一样（工具得是可复现的）
5. 再挑第二集跑，两集规则都成立，才谈整季

## 常见坑

| 现象 | 多半是 |
|---|---|
| 一堆「未配对:标识」 | 正常——标题卡、组标、注释本来就没对白 |
| 对稿一条都没挑出来 | 要么译文很干净，要么规则太严；先加 `--term` 再抽 20 条看 |
