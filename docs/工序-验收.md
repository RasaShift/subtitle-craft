# 工序 · 验收

> **这是哪一步**：第 9 步，管「执行方交回的东西到底能不能落」。
> **管什么**：跑复算、逐条判红、给放行或打回结论，并说清是谁的错。
> **不绑什么**：不出现剧名、季号、集号规则。换一批 findings，判法不变。

## 1. 这道工序解决什么

验收专治「执行方说改完了」和「真的改对了」之间的落差。

**它是正式一步，不是落地的尾巴**：有自己的判据、自己的结论、自己的退出码。落地跑完顺手看一眼，等于没验——被 merge 丢掉的条目压根没进 patch，落地器无从拒绝，永远显示 0 被拒。

**不做会怎样**：错改和漏改混进成品，而且复算全绿看不出问题。旧库记过一次：被 merge 静默丢弃的整批 findings，`apply` 报「0 被拒」、`verify` 报绿，成品里一条都没进去。

## 2. 输入

| 输入 | 必需 | 干什么 |
|---|---|---|
| 成品字幕 | 是 | 验的对象 |
| 改动清单 / findings | 是 | 声明的改动，逐条跟成品对 |
| 定档（`定档.md`） | 是 | 判「这批该有多少条」合不合理；没定档就没有期望值 |
| 机械段清单 | 条件 | 有自动改动时必须逐条人读，不能只看数 |

**没定档就没期望值**，验收会退化成「跑一下看红不红」——那不叫验收。

## 3. 判断路径：红了先分四类，别急着判谁的责任

对上任何红项，按顺序排除：

```
红了
  ├─ ① 时序？      还没落地就跑了验收（补行没进成品）→ 等落地再验
  ├─ ② 期望过期？  拿旧批次的条数验新批次 → 核对期望参数
  ├─ ③ 阈值/口径？ 用默认阈值跑出「全绿」，但项目红线更严 → 显式给项目红线
  ├─ ④ 脚本自己错？季节前缀取错、路径拼错 → 冤枉了执行方，先修脚本
  └─ 四类都排除 → 这才是真错，这时候才追责任
```

**前四类排除之前，不许打回给执行方。** 打回一个冤枉的单，执行方会去改本来没错的地方——这是把好改坏的最快路径。

## 4. 报红四分：结论里必须写归属

| 类 | 谁的问题 | 怎么修 |
|---|---|---|
| **成品错** | 执行方改错/漏改 | 打回该条，给行号与原因 |
| **清单错** | 执行方抄错条号、文本、时间码 | 打回，要求回源文逐字核对 |
| **工具错** | 我们的复算脚本或阈值 | 修工具，不打回 |
| **底线错** | evidence 编造、跳过必须报的项 | 打回并要求重写 evidence |

**分不清归属就别放行。** 四类的修法完全不同，混在一起改必然改错地方。

## 5. 七项 + 机械段清单

七项验 findings 自洽与在成品里是否成立，机械段清单是自动改动的逐条人读。**逐项口径见 `docs/工序-验收-手册.md` 第「七项 + 一项怎么读」节**，这里不抄。

三条最容易判错的：

- **成品行数差 vs 补行数**：落地前必红，属时序，不是错。
- **时间轴倒序**：只报「成品比源新增的」；源自带的倒序不算错。
- **evidence 引文查无出处**：官方轨和源字幕英文**都**没有 → 疑似编造。但引我们自己的错文是**合法**证据（技术缺陷类改动只能这么写），只要在源字幕该集英文里找得到。

## 6. 放行标准（全满足才放行）

1. 七项全绿，或红项已用四分解释清楚且属时序 / 期望 / 阈值问题
2. 机械段清单逐条人读过
3. 复算通过
4. `merge` 丢弃条数为 0，或每条丢弃原因已查明
5. 交回三件齐全，疑问表里没有悬而未决的项

**任一条不满足就是打回**，不许「差不多放行」。

## 7. 打回怎么打

给执行方三样，缺一样他改不了：

1. 哪几项红
2. 每条的行号与原因
3. 重写要求（例：「这条 evidence 补出处」）

**不替执行方改。** 改的人不验、验的人不改——自己改了自己验，等于没验。

## 8. 三问与完成标志

| 三问 | 答案 |
|---|---|
| **触发条件** | 执行方交回 findings / 判定表之后。**统筹方负责触发** |
| **完成标志** | 七项全绿或红项全部归因、丢弃数核过、机械段逐条读过、结论写明每个数 |
| **不跑会怎样** | 错改漏改混进成品且复算显示全绿，问题要到观众那儿才发现 |

## 9. 与旧说法的映射（历史不丢）

| 旧说法 | 本库说法 |
|---|---|
| 「验收复算」整层，含七项与 `check_all` | 验收（2026-11-07 技能重做时独立成文档） |
| 「落地跑完顺手看一眼」 | 明确否定：验收是独立一步 |

## 10. 禁区

1. **不许跳过验收直接交付**，也不许用「复算绿」代替「逐条判红」。
2. **不替执行方改 findings**。
3. **前四类没排除就打回**，等于把自己的问题推给对方。
4. **会报错的检查才值得信**——改过或新增任何检查，先故意造一个错看它认不认。认不出的检查等于没有。
