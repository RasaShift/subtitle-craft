## 怎么用

```bash
# 每部剧按片源的显示宽高比落一份基准，纵向固定 1080（必做，不是可选）
python tools/style_normalize.py base examples/样式预设/B_经典.ass --video 1920x1080 -o 02_工作区/基准.ass
python tools/style_normalize.py apply <字幕.ass> --base 02_工作区/基准.ass -o 02_工作区/X.styled.ass
```

`--video` 的**宽高比**取片源的显示宽高比（`ffprobe` 的 `display_aspect_ratio`），**纵向取交付高度 1080**：
16:9 就 `1920x1080`，4:3 就 `1440x1080`，2.35:1 就 `2538x1080`；片源比 1080 低就 upscale 交付。

**别填片源的像素分辨率。** PAL 的 `720x576` 像素比是 1.25 而 DAR 是 1.333，填了工具不拒、只按 1.25 算横向；
纵向 576 再把三套预设的字号描边缩到一半（实测 79→42、描边 2→1）——两处都错，且不报错。

**这样「文件里写几、画面里就是几」照样成立**：交付 1080 时渲染 1:1，调样式不用自己乘一次、量截图对得上号。
只有确定按原分辨率交付（例如只出 720p）时纵向才取 720 并把预设按 0.667 缩——那时缩是对的，屏幕上的像素确实少了一半。

## 描边数值是怎么定的

表里的「描边 / 阴影」是**画布等于片源分辨率时**的像素数，2 就是渲染出来 2px。
之所以能这么直白，是因为每部剧都用 `base --video <片源分辨率>` 落了基准。

**只改这个数不一定管用**，得连头部那一行 `ScaledBorderAndShadow` 一起看：

| 设置 | 含义 | 例子 |
|---|---|---|
| `no` | Outline 就是渲染像素数，不随画布变 | 384×288 画布写 2 → 1080p 上还是 2px |
| `yes` | Outline 按画布比例放大（本库默认） | 1440×1080 画布写 4 → 1080p 上 4px |

所以别人给的字幕拿来对照，只比 Outline 数字会得出错误结论——《嗜血法医》成品写 2、本库写 4，
看着差一倍，其实两边都"对"，只是一个缩放一个不缩放。**要比就比渲染到画面上的实际像素。**

## 一季一套是正常的

同一部剧不同季换样式很常见——制作年代、发行平台、母带画质都变了。
**样式跟的是「交付单元」（一季、一个发行版本），不是剧名**，只要同一季内一致就行。

## 字体

三套都基于母版里的 `更纱黑体 SC`。换字体要先确认目标机器装了（ASS 不嵌字体），
否则整片静默回落成系统默认，字形和字宽全变；换完 `\pos` 定点的行要重新看位置。

## 关于 `examples/样式基准样例.ass`

那是三套方案的**派生来源**，现在没有任何脚本或文档引用它。留着是因为删文件要人点头；
**别拿它当基准用**——它的描边还是旧值 8/4，跟三套都对不上。要用就用 A/B/C。
