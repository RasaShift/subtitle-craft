## 怎么用

```bash
# 文档体检（提交时会自动跑一次）
python tools/doc_lint.py
# 文档超长，拆成两份
python tools/doc_split.py <文件> --dry-run
# 换行符守卫（整篇被换掉时报警，不报「文件内混用」）
python tools/eol_guard.py --check <文件或目录>
```

## 目录

**两段，判法一句话：这名字会不会出现在命令行里？** 会 → 不带编号、用英文（给命令敲）；不会 → 带编号、用中文（给人翻）。

| 路径 | 放什么 |
|---|---|
| `01_源字幕/` | 原始字幕。只读，别在这上面改 |
| `02_工作区/` | 工具跑出来的表。可删可重跑 |
| `03_成品/` | 改好的字幕。交出去的是这份 |
| `05_参考资料/` | 人写给人看的：台账、操作卡、术语口径。形态照委托人样本，见里面的 `1_给人看/README.md` |
| `docs/` | 结论与判据（给 AI 照着做）。先查 `docs/文档落点表.md` 定类再写 |
| `docs/archive/` | 过期但还要查的整卷 |
| `tools/` | 脚本。只用标准库，路径从 `__file__` 推算 |
| `.workbuddy/memory/` | 当天工作日志，追加不覆盖 |

`04` 是工具位：老库叫 `04_工具`，本骨架的工具目录叫 `tools/`，不编号但占的就是这一格——所以编号从 `03` 跳到 `05`，不是漏号。加新目录前先判它属于哪一段，别另起一套名字。

## 约定

- 文档写完跑一次 `python tools/doc_lint.py`，超上限就搬内容，不压字数。
- 改文件跟随它原本的换行符（`.gitattributes` 锁 LF）。
- 脚本头部写 `# 最近修改：<日期>（改了什么）`，不写作者。

## 换机器后要做一次

```bash
git config core.hooksPath .githooks
```

钩子是本机配置，不进版本库；不设这一条，提交前的两道守卫等于不存在。
