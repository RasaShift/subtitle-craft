# 片源与压缩

> 最近修改：2026-11-06（新建）
>
> 一句话：**先算要不要压，再决定压成什么样。多数情况下答案是「不压」。**

## 一、先判断：该不该压

三个条件，占一个才值得动手：

1. 硬盘真的没地方了（不是「想省一点」）
2. 要传网盘、或拷进手机平板
3. 要在不做去交错的播放器上看（网页、电视盒子、部分手机播放器）

三条都不占 → 原样存着。**留原件，什么时候想压都不晚；原件删了回不来。**

算账口径：40 集 720×576 的 SD 剧集约 39 GB，压到 CRF 20 约 17 GB，省 22 GB。折合硬盘两三块钱，不值几小时机时加一次不可逆重编码。

## 二、先判隔行，再选编码器

隔行与否决定后面所有参数，**别跳过这步**：

```bash
ffmpeg -ss 60 -t 240 -i in.mkv -vf idet -an -f null - 2>&1 | grep "Multi frame"
```

- `Progressive` 占多 → 逐行素材，随便压
- `TFF` / `BFF` 占多 → 真隔行，见下

| 编码器 | 压隔行 | 结论 |
|---|---|---|
| x264 | 能（MBAFF） | **选它** |
| x265 / HEVC | 标准里没有场编码工具 | 不行，毁场结构 |
| AV1 | 完全不支持 | 不行，必须先丢场信息 |
| h264_amf / nvenc | 不支持 | 不行，显卡加速在这里用不上 |

AV1 的坑有实例：Yes Minister 那个 DVDRemux 的发布者本人试过 AV1，结论是「省不了多少空间，画质反而明显变差」，最后放弃二次压制、原盘直接 remux。

## 三、两种情况，两套参数

**A · 存档：保隔行**（信息不丢，播放器自己处理去交错）

```bash
ffmpeg -i in.mkv -map 0 -map_chapters 0 \
  -c:v libx264 -crf 20 -preset slow \
  -flags +ildct+ilme -top 1 \
  -c:a copy -c:s copy out.mkv
```

**B · 跨设备：去交错**（任何播放器都正常，代价是场信息焊死）

```bash
ffmpeg -i in.mkv -vf "bwdif=mode=send_frame:parity=auto:deint=all" \
  -c:v libx264 -crf 18 -preset slow \
  -c:a aac -b:a 160k -movflags +faststart out.mp4
```

体积参考（720×576 隔行 SD，28 分钟一集，实测）：

| | 单集 | 说明 |
|---|---|---|
| 原片 | 970 MB | MPEG-2，基准 |
| A 保隔行 | 431 MB | 只比 B 多 19% |
| B 去交错 | 350 MB | — |

保隔行的代价没有想象中大——**去交错在静止区域是无损的**（两场内容一致，合起来一行不少），只有运动区域才真丢信息。SD 对话剧九成以上是静止或微动。

## 四、五个坑

1. **`-flags +ildct+ilme -top 1` 漏写** → x264 按逐行编，隔行结构被毁，事后肉眼看不出来，要重跑 idet 才发现。
2. **AC3 音轨在网页/网盘播放器不出声** → 跨设备版必须 `-c:a aac`。
3. **mp4 装不下 VobSub 位图字幕** → 存档只能 mkv。
4. **从压过的版本再压 = 二代损失** → 要新版本永远从原件压。
5. **看到横向条纹先换播放器** → PotPlayer 有、夸克没有，就是播放器不去交错，不是文件坏了。

## 五、不负责什么

- 画面修复、AI 超分：会生成原片没有的内容，存档不接受，判断画面细节时也不能拿它当依据
- 选哪一版片源、去哪下：那是接入新剧时的事，见 `examples/新剧接入.md`
