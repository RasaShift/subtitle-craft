## 不许碰的四条（只许四条，要加新的先删旧的）

1. **不改别人的库**：`日常杂活`、`是大臣系列` 里的文档一律不改，只往 `是大臣系列/02_工作区/` 写数据产物。
2. **真实台词、术语表、成品永不出门**；参数里不出现剧名、季号、集号规则；只用标准库。
3. **一件工具要在至少两部剧上跑过才算通用**。只在一部上跑通的叫「凑合那部剧」。
4. **机器只挑候选，人定案**。不许为了数字好看放宽规则——短台词真漏和栏目名卡在机器眼里一模一样。

这四条的结论、理由、重开条件全在 `docs/判定记录.md`；两处打架时**以判定记录为准**。

## 交接怎么做到「下一棒全知道」

**不靠 handoff 装知识，靠三处落盘**：决策进判定记录（结论 + 理由 + 重开条件）、进度进台账（做完删行）、判据进工序文档。
**接棒必读必须和台账 / 判定记录同一次提交**——`doc_lint` 按 commit 比，落后会报 WARN，提交时能看见。
**收工前把当天日志里下一棒必须知道的提炼三行进 `MEMORY.md`**：日志管过程，它管定论；只有过程没有定论，等于没记。
