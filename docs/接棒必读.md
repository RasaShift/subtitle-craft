## 一句话

把「一个人带 AI 干长周期精工活」的方法，做成别人能照做的**工具 + 规程 + 模板**。
**主用户是自己**（《嗜血法医》100+ 集的实际校对），推到 GitHub 给别人用是副产品——发布不构成做不做的理由，别为「对外好看」改内部设计。

## 角色分工（11-08 定）
**本库 = 维护方**（改工具/文档、判卡点，不下场干活）；**剧库 = 干活方**（照文档走、出成品、报卡点，**不许改本库**）。交接说明归剧库（在 `是大臣系列/06_治理/`），那边写错由那边报，本库不代改、不另存副本。**两库通消息只走 `docs/协作协议.md`**——维护方写、干活方读，变更广播和 GQ 答复表都在那儿，**剧库不存副本**。**剧库做到哪一步不抄在这儿**（抄了就 30 分钟过期，`GQ-17` 的活标本），去它治理目录（`06_治理`）里那份进度台账看。

## 不许碰的四条（只许四条，要加新的先删旧的）

1. **不改别人的库**——**指本库会话不动剧库**。`日常杂活`、`是大臣系列` 的文档不改，只往 `是大臣系列/03_工作区/` 写产物；**反过来，开在剧库的会话改自己库不算违规**（11-08 定，别照旧条文瞎禁）。
2. **真实台词、术语表、成品永不出门**；参数里不出现剧名、季号、集号规则；只用标准库。
3. **一件工具要在至少两部剧上跑过才算通用**。只在一部上跑通的叫「凑合那部剧」。
4. **机器只挑候选，人定案**。不许为了数字好看放宽规则——短台词真漏和栏目名卡在机器眼里一模一样。

这四条的结论、理由、重开条件全在 `docs/判定记录.md`；两处打架时**以判定记录为准**。

## 交接怎么做到「下一棒全知道」

**不靠 handoff 装知识，靠四处落盘**：决策进判定记录（结论 + 理由 + 重开条件）、进度进台账（做完删行）、判据进工序文档、**词义进 `docs/GLOSSARY.md`（只收被用错过的词，不写状态）**。
**接棒必读必须和台账 / 判定记录同一次提交**——`doc_lint` 按 commit 比，落后会报 WARN，提交时能看见。
**收工前把当天日志里下一棒必须知道的提炼三行进 `MEMORY.md`**：日志管过程，它管定论；只有过程没有定论，等于没记。
